## DLList

在第 2.2 节（即本书第 5 章）里，我们构建了 `SLList` 类，它比之前的裸递归 `IntList` 数据结构要好。在这一节里，我们会结束对链表的讨论，并开始学习一种基于数组的列表（我们称为 `AList`）所需要的数组基础知识。在这个过程中，我们还会揭开上一章为什么用 `SLList` 这个别扭名字的秘密。

### addLast

考虑上一章的 `addLast(int x)` 方法。

```java
public void addLast(int x) {
    size += 1;
    IntNode p = sentinel;
    while (p.next != null) {
        p = p.next;
    }

    p.next = new IntNode(x, null);
}
```

这个方法的问题是慢。对于长列表，`addLast` 方法要走遍整个列表，就像第 2.2 节里 `size` 方法那样。类似地，我们可以试着加一个 `last` 变量来加快代码，如下所示：

```java
public class SLList {
    private IntNode sentinel;
    private IntNode last;
    private int size;    

    public void addLast(int x) {
        last.next = new IntNode(x, null);
        last = last.next;
        size += 1;
    }
    ...
}
```

**练习 2.3.1**：考虑表示上面 `SLList` 实现（包含 last 指针）的盒子与指针图。假设我们想支持 `addLast`、`getLast` 和 `removeLast` 操作。图示的结构能让 `addLast`、`getLast` 和 `removeLast` 都很快吗？如果不能，哪些操作慢？

![sllist\_last\_pointer.png](https://joshhug.gitbooks.io/hug61b/content/chap2/fig23/sllist_last_pointer.png)

**答案 2.3.1**：`addLast` 和 `getLast` 会很快，但 `removeLast` 会很慢。这是因为删除最后一个节点之后，我们没有简单的办法找到倒数第二个节点，来更新 `last` 指针。

### 倒数第二个节点

练习 2.3.1 中那个结构的问题是，删除列表最后一项的方法天生就慢。这是因为我们要先找到倒数第二项，再把它的 next 指针设为 null。加一个 `secondToLast` 指针也没用，因为那样的话，为了保证删除最后一项后 `secondToLast` 和 `last` 满足相应的不变式，又得找到倒数第三项。

**练习 2.3.2**：试着设计一种方案，加快 `removeLast` 操作，让它不论列表多长都总是在常数时间内完成。不用真的写代码，那留给项目 1。只需要想出你会怎样修改列表的结构（即实例变量）。

我们会在改进七里描述解决办法。

### 改进七：向后看

处理这个问题最自然的办法，是给每个 `IntNode` 加一个指向前一个节点的指针，即

```java
public class IntNode {
    public IntNode prev;
    public int item;
    public IntNode next;
}
```

换句话说，我们的列表现在每个节点都有两个链接。这种列表的一个常用名称是「双向链表」（Doubly Linked List），我们简称为 `DLList`。这和第 2.2 节的单向链表，也就是 `SLList`，形成对比。

加上这些额外的指针会让代码更复杂。我们不在这里带你一步步实现，你会在项目 1 里自己构建一个双向链表。下面的盒子与指针图更准确地展示了大小为 0 和大小为 2 的双向链表分别是什么样子。

### 泛型 DLList

我们的 DLList 有一个很大的局限：它们只能存放整数值。例如，假设我们想创建一个字符串列表：

```java
DLList d2 = new DLList("hello");
d2.addLast("world");
```

上面的代码会出错，因为我们的 `DLList` 构造函数和 `addLast` 方法只接受整数参数。

幸运的是，2004 年，Java 的创造者们给语言加入了**泛型**（generics），它能让你做很多事情，其中包括创建能存放任何引用类型的数据结构。

这种语法一开始有点难以掌握。基本思想是：在类声明中紧跟着类名，用尖括号 `<>` 括起一个任意的占位符。然后在任何想使用这个任意类型的地方，都用这个占位符代替。

例如，我们之前的 `DLList` 声明是：

```java
public class DLList {
    private IntNode sentinel;
    private int size;

    public class IntNode {
        public IntNode prev;
        public int item;
        public IntNode next;
        ...
    }
    ...
}
```

一个能存放任何类型的泛型 `DLList` 是这样的：

```java
public class DLList<BleepBlorp> {
    private IntNode sentinel;
    private int size;

    public class IntNode {
        public IntNode prev;
        public BleepBlorp item;
        public IntNode next;
        ...
    }
    ...
}
```

这里的 `BleepBlorp` 只是我编的一个名字，你几乎可以换成任何你喜欢的名字，比如 `GloopGlop`、`Horse`、`TelbudorphMulticulus` 之类。

定义了泛型版本的 `DLList` 类之后，实例化这个类也要用一种特殊的语法。具体做法是：声明时把想要的类型放在尖括号里，实例化时用空的尖括号。例如：

```java
DLList<String> d2 = new DLList<>("hello");
d2.addLast("world");
```

因为泛型只能用于引用类型，不能把 `int` 或 `double` 这样的基本类型放进尖括号，例如写 `<int>`。而要用基本类型对应的引用版本，`int` 对应的是 `Integer`，例如：

```java
DLList<Integer> d1 = new DLList<>(5);
d1.insertFront(10);
```

使用泛型还有一些细微之处，不过我们留到本书后面的章节，等你有更多机会自己试验之后再讲。目前，按下面几条经验法则来：

* 在**实现**数据结构的 .java 文件里，只在文件最上方的类名后面写一次泛型类型名。
* 在使用你的数据结构的其他 .java 文件里，声明时指定想要的具体类型，实例化时用空的菱形运算符。
* 如果需要用基本类型实例化泛型，就用 `Integer`、`Double`、`Character`、`Boolean`、`Long`、`Short`、`Byte` 或 `Float`，而不用对应的基本类型。

小细节：实例化时也可以在尖括号里声明类型，不过只要在同一行里也声明了变量，这就不是必须的。换句话说，下面这行代码完全合法，尽管右边的 `Integer` 是多余的。

```java
DLList<Integer> d1 = new DLList<Integer>(5);
```

## 数组

到目前为止，我们已经看到怎样利用递归的类定义来创建可扩展的列表类，包括 `IntList`、`SLList` 和 `DLList`。在本书接下来的两节里，我们会讨论怎样用数组构建列表类。

本书这一节假设你已经用过数组，并不打算全面讲解数组的语法。

### 数组基础

要最终构建一个能存放信息的列表，我们需要某种获得内存盒子的方式。前面我们看到，可以通过声明变量和实例化类来获得内存盒子。例如：

* `int x;` 给我们一个存放 int 的 32 比特内存盒子。
* `Walrus w1;` 给我们一个存放 Walrus 引用的 64 比特内存盒子。
* `Walrus w2 = new Walrus(30, 5.6);` 一共给我们 3 个内存盒子。一个存放 Walrus 引用的 64 比特盒子，一个存放这只 Walrus 的 int 型 size 的 32 比特盒子，一个存放这只 Walrus 的 double 型 tuskSize 的 64 比特盒子。

数组是一种特殊的对象，由一串带编号的内存盒子组成。这和类的实例不同，类的实例的内存盒子是有名字的。要取数组的第 i 项，就用方括号记法，正如在 HW0 和项目 0 里看到的，例如用 `A[i]` 取 A 的第 `i` 个元素。

数组由以下部分组成：

* 一个固定的整数长度 N。
* 一串 N 个内存盒子（N = 长度），所有盒子类型相同，编号从 0 到 N - 1。

和类不同，数组没有方法。

### 朴素的 AList

在这一节里，我们会构建一个叫 `AList` 的新类，它和 `DLList` 类似，可以用来存放任意长的数据列表。和 `DLList` 不同的是，`AList` 用数组而不是链表来存放数据。

### 链表性能谜题的答案

原来，如果用的是第 2.3 节描述的双向链表结构，不管你多聪明，`get` 方法通常都会比 `getBack` 慢。

这是因为我们只有指向列表第一项和最后一项的引用，所以总要从前端或后端沿列表走，才能到达想取的那一项。例如，要在长度为 10,000 的列表里取第 417 项，就得沿着向前的链接走 417 步才能到达想要的那一项。

在最坏的情况下，那一项正好在最中间，我们要走过的项数和列表长度成正比（具体地说，是项数的一半）。换句话说，`get` 在最坏情况下的执行时间和整个列表的大小成线性关系。这和 `getBack` 的运行时间形成对比，后者不论列表多大都是常数。在课程后面，我们会用大 O 记号和大 Θ 记号正式地定义运行时间。目前先用一种非正式的理解。

### 第一次尝试：朴素的基于数组的列表

在现代计算机上，访问数组的第 `i` 个元素花的时间是常数。这表明基于数组的列表的 `get` 性能可以比基于链表的方案好得多，因为它直接用方括号记法就能取到想要的项。

如果想知道数组**为什么**能常数时间访问，可以看 [这篇 Quora 帖子](https://www.quora.com/Why-does-accessing-an-array-element-take-constant-time)。

### removeLast

我们还需要支持的最后一个操作是 `removeLast`。开始之前，先指出一个关键的观察：对列表的任何改动，都必须体现为我们实现中一个或多个内存盒子的改动。

这看起来可能显而易见，但其中有一些深刻的道理。列表是一个抽象的概念，而 `size`、`items` 和 `items[i]` 这些内存盒子是这个概念的具体表示。用户通过我们提供的抽象（`addLast`、`removeLast`）对列表做出的任何改动，都必须以符合用户预期的方式，体现为这些内存盒子的某些变化。我们的不变式为这些变化应该是什么样子提供了指引。

### 数组与类

数组和类都可以用来组织一批内存盒子。在两种情况下，内存盒子的数量都是固定的，即数组的长度不能改变，正如类的字段不能增加或删除。

数组和类的内存盒子的关键区别是：

* 数组的盒子是编号的，用 `[]` 记法访问；类的盒子是有名字的，用点号记法访问。
* 数组的盒子必须全部是同一种类型。类的盒子可以是不同类型。

这些区别带来的一个特别值得注意的影响是，`[]` 记法让我们可以在运行时指定想要哪个下标。例如，看下面的代码：

```java
int indexOfInterest = askUserForInteger();
int[] x = {100, 101, 102, 103};
int k = x[indexOfInterest];
System.out.println(k);
```

运行这段代码，可能得到这样的结果：

```
$ javac arrayDemo
$ java arrayDemo
What index do you want? 2
102
```

相比之下，指定类里的字段不是我们能在运行时做的事。例如，看下面的代码：

```java
String fieldOfInterest = "mass";
Planet p = new Planet(6e24, "earth");
double mass = p[fieldOfInterest];
```

如果试着编译它，会得到一个语法错误。

```
$ javac classDemo
FieldDemo.java:5: error: array required, but Planet found
        double mass = earth[fieldOfInterest];        
                               ^
```

如果试着用点号记法，也会出现同样的问题：

```java
String fieldOfInterest = "mass";
Planet p = new Planet(6e24, "earth");
double mass = p.fieldOfInterest;
```

编译时，得到：

```
$ javac classDemo
FieldDemo.java:5: error: cannot find symbol
        double mass = earth.fieldOfInterest;        
                           ^
  symbol:   variable fieldOfInterest
  location: variable earth of type Planet
```

你不会经常碰到这个限制，但为了严谨起见，还是值得指出来。顺便一提，确实有一种在运行时指定想要的字段的方法，叫作*反射*（reflection），但对一般的程序来说，它被认为是非常糟糕的编码风格。可以在 [这里](https://docs.oracle.com/javase/tutorial/reflect/member/fieldValues.html) 读到更多关于反射的内容。**你绝不应该在任何 61B 程序里使用反射**，我们的课也不会讨论它。

一般来说，编程语言的设计部分是为了限制程序员的选择，让代码更容易推理。把这类特性限制在专门的反射 API 里，能让一般的 Java 程序更容易阅读和理解。
