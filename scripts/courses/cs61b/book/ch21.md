## 21.1 引言

### 最短路径

#### 回顾

到目前为止，我们有方法做以下事情：

* 找出从给定顶点 `s` 到图中每个可达顶点的一条路径。
* 找出从给定顶点 `s` 到图中每个可达顶点的一条**最短**路径。（……真的吗？）

在回答下面提出的这个神秘问题之前，我们再回顾一下能用来做上面两件事的两种搜索：BFS 和 DFS。

两者都总是正确的吗？是的。有没有一个给出更好的结果？BFS 能找到**最短**路径，DFS 不能。从运行时间看，有没有一个更高效？没有。从空间看，有没有一个更高效？

* 对细长的图，DFS 更差。设想一个有 10000 个节点、全是细长一条的图。我们最终要做 10000 次递归调用，这对空间不利。
* 对「茂密」的图，BFS 更差，因为队列会被大量使用。

#### 回答那个神秘的问题

我们写出了能找到从给定顶点到其他每个可达顶点的**最短**路径的算法吗？嗯，算是吧。我们写出的算法在边没有标签的图上效果很好。我们做的是：写出一个算法，找出从给定源顶点出发的最短路径（**这里的最短是指边数最少**）。

但这并不总是「最短」的正确定义。有时，图的边可能带有「权重」，如果 A-B 这条边的权重是 5，而 A-C 这条边的权重只是 3，就认为 A-B 比 A-C 远。

这就是为什么当图中的边有权重时，我们需要另一种找最短路径的算法。

### 几点观察

注意，（对于边有权重的图）最短路径可能包含很多很多条边。我们关心的是让所选路径上各条边的权重之和最小。

其次，注意从源点 `s` 出发的最短路径树可以这样构造：

* 对图中每个（不是 `s` 的）顶点 `v`，找出从 `s` 到 `v` 的最短路径。
* 把上面找到的所有边「合并」起来。大功告成！

第三，注意「最短路径树」**总是一棵树**。为什么？嗯，想想我们原来的解法，在那里我们维护了一个 edgeTo 数组。对每个节点，edgeTo 数组里恰好有一个「父节点」。（为什么这意味着「最短路径树」是一棵树？提示：一棵树有 `V-1` 条边，`V` 是树中的节点数。）

### 迪杰斯特拉算法 [/ˈdaɪkstrə/]

迪杰斯特拉算法（Dijkstra's algorithm）接收一个输入顶点 $s$，输出从 $s$ 出发的最短路径树。它是怎样工作的？

1. 创建一个优先队列。
2. 把 `s` 以优先级 0 加入优先队列。把其他所有顶点以优先级 ∞ 加入优先队列。
3. 只要优先队列不空：从优先队列中弹出一个顶点，**松弛**从这个顶点出发的所有边。

### 「松弛」是什么意思？

假设刚从优先队列中弹出的顶点是 `v`。我们会看 `v` 的所有边。比如说，我们在看边 (`v`,`w`)（从 `v` 到 `w` 的边）。我们要试着松弛（relax）这条边。

意思是：看你目前从源点到 `w` 的最好距离，记为 **curBestDistToW**。再看 **curBestDistToV** + weight(`v`,`w`)（记为 **potentialDistToWUsingV**）。

**potentialDistToWUsingV** 是否**更好，即更小**于 **curBestDistToW**？如果是，就令 **curBestDistToW = potentialDistToWUsingV**，并把 **edgeTo[`w`]** 更新为 `v`。

**重要提示：我们从不松弛指向已访问顶点的边。**

计算可能的距离、检查是否更好、可能更新，这整个过程叫作松弛。

### 伪代码

```
def dijkstras(source):
    PQ.add(source, 0)
    For all other vertices, v, PQ.add(v, infinity)
    while PQ is not empty:
        p = PQ.removeSmallest()
        relax(all edges from p)
```

```
def relax(edge p,q):
   if q is visited (i.e., q is not in PQ):
       return

   if distTo[p] + weight(edge) < distTo[q]:
       distTo[q] = distTo[p] + w
       edgeTo[q] = p
       PQ.changePriority(q, distTo[q])
```

**保证**

只要所有边都非负，迪杰斯特拉算法保证给出最优解。

### 证明与直觉

假设所有边都非负。

* 开始时，distTo[source] = 0。这是最优的。
* 松弛从源点出发的所有边之后，设顶点 $v_1$ 是权重最小的顶点（即离源点最近的那个）。**断言：distTo[$v_1$] 是最优的，即此时 distTo[$v_1$] 的值，就是从 $s$ 到 $v_1$ 的最短距离。** 为什么？
  * 我们来看看为什么**一定**是这样。
  * 假设不是这样。那就意味着存在另一条从 $s$ 到 $v_1$ 的路径，比直接的路径 ($s$, $v_1$) 更短。好，考虑这条假想的、很酷的更短路径……它应该是 ($s$, $v_a$, $v_b$, …, $v_1$) 这样的。但是……($s$, $v_a$) **本身**就已经比 ($s$, $v_1$) 大了。（注意这成立，是因为由上面可知，$v_1$ 是离 $s$ 最近的顶点。）那怎么可能存在这样一条真的更短的路径呢？不可能！
* 现在，下一个被弹出的顶点将是 $v_1$。（为什么？注意它现在在优先队列里优先级最低！）
* 所以现在，我们可以对 $v_1$ 以及它做的所有松弛给出同样的论证。（这叫「数学归纳法证明」，有点像证明里的递归。）就这样，证完了。

当负权边出现时，事情可能会变得很糟。看下图。

假设你在标着 34 的那个顶点。现在你要试着松弛你所有的边。你只有一条出边，从你指向 33，权重是 −67。啊，但是注意：顶点 33 已经访问过了（它被标成了白色）。所以……我们不松弛它。（回想 relax 方法的伪代码。）

于是我们以为到 33 的最短距离是 82（标成粉色），就收工回家了。但实际上，我们应该走**经过** 34 的那条路，因为那会给出 101−67=34 的距离。糟糕。

### 一个值得注意的不变式

注意，一个顶点一旦从优先队列中弹出，就再也不会被重新加入。它的距离再也不会被更新。换句话说，一个顶点一旦从优先队列中弹出，我们就**知道**了从源点到这个顶点真正的最短距离。

这个事实的一个好结果是「提前结束」（short-circuiting）。假设……我不关心最短路径树，只想找出从某个源点到另一个目标的最短路径。假设你想把世界上的城市放在一个图里，找出从伯克利到奥克兰的最短路径。运行 `dijkstra(Berkeley)` 意味着你没法让这个强大的算法停下来……你得让它一直跑……直到它找到到洛杉矶、休斯敦、纽约以及所有可能地点的最短路径！

其实，一旦算法中 `Oakland` 从优先队列中弹出，我们就可以停下来。直接返回那时得到的距离和路径，它就是正确的。所以**有时** `dijkstra` 不仅接收一个源点，还接收一个目标。这就是为了提前结束。

## 21.3 A\* 算法

### A\*

讲迪杰斯特拉算法那一节的最后，我们讨论了一种让迪杰斯特拉算法提前结束、一碰到给定目标就停下的办法。这样够好吗？

要回答这个问题，我们得坐下来想想迪杰斯特拉算法到底是怎样工作的。用图来想，迪杰斯特拉算法从源节点出发（想象源节点是一个圆的圆心）。然后迪杰斯特拉算法围绕这一点画一个个同心圆，半径越来越大，「扫过」这些圆，把点收进来。

所以……迪杰斯特拉算法访问的第一个节点是离源点最近的城市，然后是次近的城市，然后是再次近的城市，依此类推。这听起来是个好主意。迪杰斯特拉算法做的是先访问所有距离为 1 个单位的城市，然后是 2 个单位的，依此类推。一圈一圈的同心圆。

现在设想：在美国地图上，从中部某个地方出发，比如丹佛。我要你用迪杰斯特拉算法找出一条到纽约的路径。你会按「最近的同心圆」的顺序遍历节点。

![](https://joshhug.gitbooks.io/hug61b/content/assets/Screen%20Shot%202019-03-23%20at%208.29.56%20PM.png)

你会先画一个小圆，就在丹佛周围，访问这个圆里的所有城市。最终，圆会越来越大，你会画出一个经过拉斯维加斯的圆（到这时，你已经访问了落在这个圆里的所有其他城市）。然后，圆会大到把洛杉矶和达拉斯都包进来……但你离纽约还远着呢。费了这么多力气，画了这么多圆，可还是……离目标那么远。提前结束有帮助，但只有在真的很快碰到目标节点时才有帮助。

要是有办法利用你事先知道的东西就好了：纽约在东边，所以你可以「提示」算法优先选东边的节点，而不是西边的。

### 隆重介绍：A Star

不，不是太阳。是一个叫 A\* 的算法。

注意下面这一点：迪杰斯特拉算法给出的是从源点**到**一个节点的距离的「真实」（即不是估计的）度量。所以，比如说你访问了伊利诺伊州的一个城市，而源点是丹佛，那么到那时，你已经有了这个城市**到**丹佛的真实距离。我们缺的是：从一个节点**到**目标节点纽约的距离的某种粗糙的估计。有了它，图景就完整了。因为如果把这两样东西加起来（从源点到这个节点的度量 + 从这个节点到目标的估计），就得到（从源点到目标的一个估计）。当然，从节点到目标的原始估计越好，从源点到目标的估计就越好，A\* 算法就跑得越好。

所以，我们稍微修改一下迪杰斯特拉算法。在迪杰斯特拉算法中，我们用 **bestKnownDistToV** 作为优先级。这次，我们用 **bestKnownDistToV + estimateFromVToGoal** 作为启发式（heuristic）的优先级。

这里有一个 [演示](https://docs.google.com/presentation/d/177bRUTdCa60fjExdr9eO04NHm0MRfPtCzvEup1iMccM/edit#slide=id.g771336078_0_180)！

### 先有鸡还是先有蛋

我们有一个问题。怎么知道估计值是多少？我是说，估计值本身就是一个**距离**，而我们正是在用 A\* 来**求**从一个节点到另一个节点的距离。

我们似乎陷入了经典的「先有鸡还是先有蛋」问题。顺便一提，有一位 reddit 用户对这个问题有一个 [想法](https://www.reddit.com/r/dadjokes/comments/97768x/i_ordered_a_chicken_and_an_egg_from_amazon_ill/)。

嗯，它之所以叫估计，正是因为它就是估计。我们用 A\* 得到从源点到目标的**真正**最短路径，而估计值是我们近似出来的东西。有时想出好的估计很难。

不过，就丹佛到纽约这个例子给你举个例子。我们可以查出这些城市的 GPS 坐标，用某种方式算出它们之间的直线距离。当然，这不会是正确的，因为从丹佛到纽约多半没有一条可以走的直线，但这是一个相当不错的估计！

### 糟糕的启发式

假设从丹佛到纽约的最短路径经过某个城市 $C$。假设我的 GPS 坏了，于是我以为这个城市 $C$ 离任何地方都无穷远，把图中每个其他节点到 $C$ 的估计距离都设为 ∞。

会怎样？嗯，A\* 基本上永远不想访问这个城市。（记住我们在优先队列中的优先级是什么；对这个城市，优先级永远是 ∞，即使我访问了这个城市的直接邻居。毕竟这个城市的直接邻居到它的估计距离都被设成了 ∞。）

所以……现在呢？我们输了。A\* 失效了。我们得到了错误的答案。糟糕。

这里要记住的是，启发式需要是好的。「好」需要满足两个定义。

1. 可容许性（Admissibility）：heuristic(v, target) ≤ trueDistance(v, target)。（想想上面的问题。从 $C$ 的邻居到 $C$ 的真实距离不是无穷大，而是小得多。但我们的启发式说它是 ∞，所以违反了这条规则。）
2. 一致性（Consistency）：对 $w$ 的每个邻居 $v$：
   * heuristic(v, target) ≤ dist(v, w) + heuristic(w, target)
   * 其中 dist(v, w) 是从 v 到 w 的边的权重。

## 21.4 小结

**迪杰斯特拉算法与单源最短路径。** 假设我们想记录从某个源点到其他每个顶点的最短路径（这样就能快速找到从 s 到 X、从 s 到 Y 等等的路线）。如果只数边的数量，我们已经知道怎么做了，用 BFS 就行。

但如果边有权重（例如表示道路长度），就得用别的办法。结果是，即使考虑边权，我们也能非常高效地预先算出从源点到每个顶点的最短路线。我们把答案存成一棵「最短路径树」。通常，最短路径树存成一个 edgeTo[] 值的数组（如果想让 distTo() 操作是常数时间，还可以存 distTo[] 值）。

要找出最短路径树（SPT），可以用迪杰斯特拉算法，一旦理解了它就会发现它相当简单。本质上，我们按离源点的距离的顺序访问每个顶点，每次访问就是松弛它的每条边。非正式地说，松弛一条边的意思是：如果用这条边比目前已知的到目标顶点的最好距离更好，就用它，否则就忽略它。用伪代码写：

```
Dijkstra(G, s):
    while not every vertex has been visited:
        visit(unmarked vertex v for which distTo(v) is minimized)
```

其中 visit 由下面的伪代码给出：

```
visit(v):
    mark(v)
    for each edge e of s:
        relax(e)
```

（译注：上面 `for each edge e of s` 中的 `s` 应为 `v`，即松弛被访问顶点 `v` 的每条边。）

最后，relax 由下面的伪代码给出：

```
relax(e):
    v = e.source
    w = e.target        
    currentBestKnownWeight = distTo(w)
    possiblyBetterWeight = distTo(v) + e.weight
    if possiblyBetterWeight < currentBestKnownWeight
        Use e instead of whatever we were using before
```

运行时间是 $O(V \log V + V \log V + E \log V)$，又因为对任何我们会对它运行迪杰斯特拉算法的图，都有 $E > V$，所以可以更简单地写成 O(E log V)。运行时间的说明见幻灯片。

**A\* 单目标最短路径。** 如果只需要到单个目标的路径，迪杰斯特拉算法就很低效，因为它探索了很多很多我们不关心的边（例如从丹佛规划到纽约的路线时，在到达纽约之前，我们会把各个方向上一千多英里以内的一切都探索一遍）。

为了解决这个问题，我们对迪杰斯特拉算法做一个非常小的改动：不再按离源点的距离的顺序访问顶点，而是按离源点的距离 + h(v) 的顺序访问它们，其中 h(v) 是某个启发式函数。

用伪代码写：

```
A*(G, s):
    while not every vertex has been visited:
        visit(unmarked vertex v for which distTo(v) + h(v) is minimized)
```

结果是（但我们没有证明），只要 h(v) 小于 v 到目标的真实距离，A\* 的结果就总是正确的。

（译注：原文写的是「小于从 s 到 v 的真实距离」，按上面关于可容许性的定义，应为从 v 到目标的真实距离。）

注意：在课上的版本中，我们没有用显式的「标记」。而是把所有东西都扔进优先队列，一个顶点从优先队列中删除了，就相当于被标记了。
