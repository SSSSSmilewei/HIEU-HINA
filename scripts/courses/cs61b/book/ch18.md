## 18.1 优先队列

二叉搜索树让我们能高效地在树里查找，只花 $\log(N)$ 的时间。这是因为查找的每一步都能排除树中一半的元素。如果我们更关心快速找到*最小*或*最大*的元素，而不是快速查找呢？

现在我们来到*优先队列*（Priority Queue）这个抽象数据类型。要理解这个 ADT，可以设想一个装东西的袋子。你可以往袋子里加东西，可以从袋子里拿东西，等等。唯一的限制是，你只能和袋子里最小的东西打交道。

```java
/** (Min) Priority Queue: Allowing tracking and removal of 
  * the smallest item in a priority queue. */
public interface MinPQ<Item> {
    /** Adds the item to the priority queue. */
    public void add(Item x);
    /** Returns the smallest item in the priority queue. */
    public Item getSmallest();
    /** Removes the smallest item from the priority queue. */
    public Item removeSmallest();
    /** Returns the size of the priority queue. */
    public int size();
}
```

### 使用优先级

我们在哪里会真正用到或需要这种结构？

* 设想这样的情景：我们在监控公民之间的短信，想记录下不和谐的对话。
* 每天，你用一个 `HarmoniousnessComparator`（和谐度比较器）准备一份报告，列出最不和谐的 $M$ 条消息。

我们采用这种做法：把一天中收到的所有消息收集到一个列表里。对这个列表排序，返回前 $M$ 条消息。

```java
public List<String> unharmoniousTexts(Sniffer sniffer, int M) {
    ArrayList<String>allMessages = new ArrayList<String>();
    for (Timer timer = new Timer(); timer.hours() < 24; ) {
        allMessages.add(sniffer.getNextMessage());
    }

    Comparator<String> cmptr = new HarmoniousnessComparator();
    Collections.sort(allMessages, cmptr, Collections.reverseOrder());

    return allMessages.sublist(0, M);
```

可能的缺点？这种做法会用 $\Theta(N)$ 的空间，而实际上我们只需要用 $\Theta(M)$ 的空间。

### 优先队列的实现

我们用优先队列 ADT 解决了同样的问题，让内存的使用更高效。可以看到代码稍微复杂了一点，但并不总是这样。

记住，ADT 和接口类似，实现还有待定义。我们来考虑用已知的数据结构来实现，分析所需操作的**最坏情况**运行时间：

* 有序数组
  * `add`：$\Theta(N)$
  * `getSmallest`：$\Theta(1)$
  * `removeSmallest`：$\Theta(1)$
* 茂密的 BST
  * `add`：$\Theta(\log N)$
  * `getSmallest`：$\Theta(\log N)$
  * `removeSmallest`：$\Theta(\log N)$
* 哈希表
  * `add`：$\Theta(1)$
  * `getSmallest`：$\Theta(N)$
  * `removeSmallest`：$\Theta(N)$

### 小结

* 优先队列是一个针对处理最小或最大元素做了优化的抽象数据类型。
* 使用这种专门的数据结构在空间（内存）上可能有好处。
* 用我们目前知道的 ADT 实现，优先队列操作的运行时间都不够高效。
  * 在这些结构中，二叉搜索树最高效。

## 18.2 堆

前面我们看到，在已知的数据结构中，对优先队列操作运行时间最好的是*二叉搜索树*。修改它的结构和约束，可以进一步提高这些操作的运行时间和效率。

我们把二叉最小堆定义为**完全**的，并且满足**最小堆**性质：

* 最小堆：每个节点都小于或等于它的两个孩子。
* 完全：缺少的项（如果有的话）只在最底层，所有节点都尽可能靠左。

### 堆的操作

对优先队列 ADT，我们关心的三个方法是 `add`、`getSmallest` 和 `removeSmallest`。我们先从概念上描述，给定堆的这种组织方式，这些方法可以怎样实现。

* `add`：暂时加到堆的末尾。沿层级往上「游」（swim）到合适的位置。
  * 「上游」就是如果孩子 < 父节点，就交换这两个节点。
* `getSmallest`：返回堆的根（由*最小堆*性质，它保证是最小值）。
* `removeSmallest`：把堆中最后一项换到根上。沿层级往下「沉」（sink）到合适的位置。
  * 「下沉」就是如果父节点 > 孩子，就交换节点。要和较小的那个孩子交换，以保持*最小堆*性质。

#### 做法 2

回想并查集 ADT。我们用数组来表示加权快速合并结构。要表示一棵树，可以存放 *keys*（键）数组和 *parents*（父节点）数组。keys 数组表示哪个下标对应哪个键，parents 数组表示哪个键是另一个键的孩子。

```java
public class Tree2<Key> {
  Key[] keys;
  int[] parents;
  ...
}
```

花点时间确认左边的树和右边数组中的表示是对应的。

现在要做一个非常重要的观察！根据树的结构以及数组表示和树的示意图之间的关系，可以看出：

1. 这棵树是**完全**的。这是我们前面定义过的性质。
2. parents 数组有一种冗余的规律，元素只是成倍出现。
3. 按层序读这棵树，顺序和 *keys* 数组中键的顺序完全一致。

#### 上游（swim）

有了这种实现，我们为「堆的操作」一节描述的「上游」定义下面的代码。

```java
public void swim(int k) {
    if (keys[parent(k)] ≻ keys[k]) {
       swap(k, parent(k));
       swim(parent(k));              
    }
}
```

parent 方法做什么？它用做法 3 的表示，返回给定的 k 的父节点。

## 18.3 优先队列的实现

我们会用、本书也采用的实际实现，和上一节末尾讨论的表示非常相似。唯一的区别是我们在数组开头留出一个空位，以简化计算。

* `leftChild(k)` = $k * 2$
* `rightChild(k)` = $k * 2 + 1$
* `parent(k)` = $k / 2$

### 和其他实现的比较

| 方法 | 有序数组 | 茂密的 BST | 哈希表 | 堆 |
| --- | --- | --- | --- | --- |
| `add` | $\Theta(N)$ | $\Theta(\log N)$ | $\Theta(1)$ | $\Theta(\log N)$ |
| `getSmallest` | $\Theta(1)$ | $\Theta(\log N)$ | $\Theta(N)$ | $\Theta(1)$ |
| `removeSmallest` | $\Theta(N)$ | $\Theta(\log N)$ | $\Theta(N)$ | $\Theta(\log N)$ |

太棒了！可以看到我们改进了运行时间，也解决了重复元素的问题。几点说明：

* 堆的操作用的是**均摊**分析，因为数组需要调整大小（问题不大）。
* 如果保存一个指向最小元素的指针，BST 的 `getSmallest` 可以是常数时间。
* 基于数组的堆占用的内存，大约是用做法 1A（直接指向孩子的指针）表示堆的 1/3。

（译注：有序数组的 `removeSmallest` 在 18.1 节写的是 $\Theta(1)$，这里写的是 $\Theta(N)$，原文前后不一致：如果数组按降序存放、最小元素在末尾，删除是 $\Theta(1)$；如果按升序存放、要删掉开头再把后面的元素前移，就是 $\Theta(N)$。）

## 18.4 小结

**优先队列。** 最大优先队列（简称 PQ）是一个至少支持插入和删除最大值操作的 ADT。MinPQ 支持插入和删除最小值。

**堆。** 最大（最小）堆是二叉树的一种数组表示，其中每个节点都比它的所有孩子大（小）。这个定义自然是递归适用的，即一个高度为 5 的堆由两个高度为 4 的堆加上一个父节点组成。

**树的表示。** 要知道表示树有很多种方式，而我们用做法 3b（见讲座幻灯片）来表示堆，因为我们知道堆是完全的。

**各种优先队列实现的运行时间。** 要知道无序数组、有序数组和堆三种实现下，三个主要的优先队列操作的运行时间。
