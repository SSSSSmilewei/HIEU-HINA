## 24.1 哈希入门：以数据为下标的数组

到目前为止，课上我们已经看过很多在数据结构里存放东西的方法，但从运行时间看，它们并不总是最高效的。现在登场的是一种了不起的数据结构，不论里面有多少元素（即使有几百万个），它都能提供插入、删除和查询是否包含的操作——在最好情况下全都是 O(1) 的运行时间！听起来好得令人难以置信？

我们会在本章探索哈希（hashing）的魔力，看看这怎么可能。

### 快速回顾目前见过的数据结构

我们看过几种能高效查找某项是否在数据结构里的数据结构。我们看过二叉搜索树，然后用 2-3 树让它们平衡。

不过，这些结构有一些局限（是的，2-3 树也有！）：

1. 它们要求元素是可比较的。怎样决定新元素放在 BST 的什么地方？你得回答「你比根小还是比根大」这个问题。对某些对象来说，这个问题可能毫无意义。
2. 它们给出的复杂度是 $\Theta(\log N)$。这好吗？当然好。但也许我们能做得更好。

### 把数据当作下标

数组的基本操作运行时间非常好。有没有好办法把数据转换成下标、存进数组？接下来几个小节，我们会一步步走向最终的创造——哈希表。看小节里链接的视频，有助于理解我们是经过怎样的过程发明出哈希表的。哈希表会是本章其余部分的重点。

### 24.1.1 第一次尝试：DataIndexedIntegerSet

我们先考虑下面这种做法。这种做法是在 [哈希视频 1](https://youtu.be/rSqSlu8sEkI) 里介绍的。

目前，我们只设法把复杂度从 $\Theta(\log N)$ 改进到 $\Theta(1)$。我们不去管可比较性。事实上，我们只考虑存放和查找 `int`。

有一个想法：创建一个 `boolean` 类型、大小为 20 亿的数组。默认全部是 false。

* `add(int x)` 方法只是把数组的第 `x` 个位置设为 true。这花 $\Theta(1)$ 的时间。
* `contains(int x)` 方法只是返回数组第 `x` 个位置是 `true` 还是 `false`。这也只花 $\Theta(1)$ 的时间！

```
public class DataIndexedIntegerSet {
    private boolean[] present;

    public DataIndexedIntegerSet() {
        present = new boolean[2000000000];
    }

    public void add(int x) {
        present[i] = true;
    }

    public boolean contains(int x) {
        return present[i];
    }
}
```

（译注：代码中的 `present[i]` 应为 `present[x]`。）

就是这样。大功告成。

嗯，其实并没有。这种做法有哪些潜在的**问题**？

* 极其浪费。如果假设一个 `boolean` 占 1 字节，每次 `new DataIndexedIntegerSet()` 都需要 `2GB` 的空间。而且，用户可能只插入寥寥几个元素……
* 如果有人想插入一个 `String` 怎么办？或者别的数据类型？
  * 我们接下来就看这个。当然，我们可能还想插入别的东西，比如 `Dog`。这很快就会讲到！

### 24.1.2 第二次尝试：DataIndexedWordSet

我们的 `DataIndexedIntegerSet` 只允许整数，但现在我们想往里插入 `String` `"cat"`。我们把能插入字符串的数据结构叫作 `DataIndexedEnglishWordSet`。有一个疯狂的想法：给每个字符串一个编号。也许「cat」可以是 `1`，「dog」可以是 `2`，「turtle」可以是 `3`。

（它的工作方式是——如果有人想往数据结构里加一个「cat」，我们就「算出」「cat」的编号是 1，然后把 `present[1]` 设为 `true`。如果有人问我们「cat」在不在数据结构里，我们就「算出」「cat」是 1，检查 `present[1]` 是不是 true。）

但如果有人试图插入单词「potatocactus」，我们就不知道该怎么办了。我们需要一个通用的策略，给定一个字符串，就能算出它的数字表示。

我们选用的两个主要策略是：

#### 策略一：用第一个字母

一个简单的想法是只用给定字符串的第一个字符，把它转换成数字表示。不过，如果有人试图插入两个首字母相同的单词，就发生了**冲突**（collision），我们用下一个策略来处理。

#### 策略二：避免冲突

英语小写字母表里有 $26$ 个不同的字符。我们给每个字符一个编号：$a=1, b=2, ..., z=26$。现在，可以把任何一个小写字符串写成 **26 进制**。（注意 **26 进制**只是说我们用 **26** 作为乘数，就像前面例子里用 **10** 和 **2** 那样。）

* $\text{"cat"}=3 \times 26^2+1 \times 26^1+20 \times 26^0$

**这种表示给每个由小写字母组成的英语单词一个唯一的整数，就像用 10 进制给每个数一个唯一的表示一样。保证不会有冲突。**

### 24.1.3 第三次尝试：DataIndexedStringSet

有一种字符格式叫 **ASCII**，每个字符对应一个整数。这里可以看到最大的值（即我们需要用的基数或乘数）是 126。那就用它吧。和 `DataIndexedEnglishWordSet` 一样，只是基数用 `126`。

```
public static int asciiToInt(String s) {
    int intRep = 0;
    for (int i = 0; i < s.length(); i += 1) {           
        intRep = intRep * 126;
        intRep = intRep + s.charAt(i);
    }
    return intRep;
}
```

那支持中文呢？最大可能的表示是 40959，所以需要用它作为基数。

所以……要存放一个 3 个字的中文词，需要一个大小超过 **39 万亿**（是万亿！）的数组。这有点失控了……所以我们来探索怎样改进，也就是使用 hashCode。

## 24.2 哈希码

*哈希的核心机制！*

我们面临的问题是，Java 里并不是每个对象都能轻易地转换成数字。不过，哈希背后的关键思想就是把任何对象转换成数字表示。关键是用一个哈希函数把键变换成不同的值，再把这个数转换成下标，用来访问数组。

我们通过自己实现一个返回 `int` 类型的 `hashCode()` 函数来做到这一点。这个 `int` 就是我们的*哈希值*（hash value）。

例如，Java 内置的 String 类可能有这样一段代码：

```java
public class String {
    public int hashCode() {
        //implementation here
    }
}
```

照这个例子，我们可以调用 `key.hashCode()`，为一个名叫 `key` 的 `String` 实例生成一个整数哈希码。

### 哈希码的内存低效问题

前面提到的一个问题是内存低效：对于范围很小的哈希值，可以用一个让每个哈希值各占一格的数组。也就是说，数组的每个下标代表一个唯一的哈希值。如果下标都很小、接近零，这样做效果很好。但记住，Java 的 32 位整数类型能表示 -2,147,483,648 到 2,147,483,647 之间的任何数。当然，大多数时候，我们的数据用到的值远没有这么多。但即使只想支持各种特殊字符，数组也仍然需要 1,112,064 个元素那么长！

我们改为稍微修改一下下标策略。比如说，为了避免分配过多的内存，只想用一个长度为 10 的数组。怎样把一个可能有几百万、几十亿那么大的数，变成 0 到 9（含）之间的一个值？

#### 绕回！

**取模运算符（%）**让我们能做到这一点。

*复习*：取模运算的结果就像除法中的余数。例如，`65 % 10` 返回 `5`，因为 65 除以 10 后余下 5。所以再举几个例子，`3 % 10 = 3`，`20 % 10 = 0`，`19 % 10 = 9`。要直观地理解这一点，想想我们在项目 1（Deque）里怎样用取模运算符，通过「绕回」数组的概念避免 `IndexOutOfBounds` 异常、准确地访问双端队列。

回到原来的问题，我们希望能把任何数转换成 0 到 9（含）之间的值。根据对取模运算符的讨论，可以看出任何数模 10 都会得到 0 到 9 之间的一个整数。这正是访问一个大小为 10 的数组所需要的！

更一般地，可以这样为任何键找到正确的下标：

```java
Math.floorMod(key.hashCode(), array.length)
```

其中 `array` 是表示哈希表的底层数组。

*小提示*：在 Java 里，`Math.floorMod` 函数做取模运算时会正确处理负整数，而 `%` 不会。

## 24.3 「合法」与「好」的哈希码

### 合法的哈希码！

你可能会在讨论课里，也可能在考试里看到这个术语。到底什么让一个哈希码「合法」（valid）？有两条性质：

1. ***确定性***：对于两个彼此相等的对象 A 和 B（`A.equals(B) == true`），`hashCode()` 函数给出相同的哈希码。*这也意味着哈希函数不能依赖对象中那些没有体现在* `.equals()` *方法里的属性。*
2. ***一致性***：对同一个对象实例，每次调用 `hashCode()` 函数都返回同一个整数。这意味着 `hashCode()` 函数必须与时间（秒表）、随机数生成器，或者任何会让同一个对象实例多次调用 `hashCode()` 得到不一致结果的方法无关。

注意，并没有要求不相等的对象必须有不同的哈希值。

可以认为这两条要求其实是同一条要求。我们可以重新表述一致性的要求。设想我们在中午 12:00 让一个名叫 `A` 的指针指向对象 `O`，在下午 1:00 让一个名叫 `B` 的指针指向同一个对象 `O`。由一致性要求，我们知道哈希码对两者应该返回同一个整数。可是，上面说的「同一个对象 `O`」该怎样正式定义？从技术上讲，我们之所以认为 `B` 和 `A` 指向同一个东西，唯一的原因是 `.equals()` 方法！这听起来就很像确定性的要求了。

### 好的哈希码！

你大概也会经常看到这个术语。但什么让一个哈希码「好」？一个好的 `hashCode()` 有几条性质：

1. `hashCode()` 函数必须是合法的。
2. `hashCode()` 函数的值应该尽可能均匀地分布在所有整数上。
3. `hashCode()` 函数应该计算得比较快（理想情况下是 O(1) 常数时间的数学运算）。

现在来更具体地想想哈希函数的影响。一般来说，我们假设大多数哈希函数都「比较快」。为什么做这个假设？因为哈希函数是这种数据结构的内在组成部分，它的运行时间会对数据结构的整体运行时间产生重大影响。这意味着我们希望哈希码「容易」计算（最好是常数时间），这样才能保持让哈希如此特别、如此高效的 O(1) 运行时间特性！

## 24.4 处理冲突：线性探测与外部链接

在哈希中，当多个元素在数组中有相同的下标时，就发生了冲突（collision）。

处理哈希表中的冲突有两种常见方法：

1. **线性探测**（Linear Probing）：把冲突的键存到数组的别处，比如下一个空着的数组位置。在分布式哈希表中可以看到这种方法，你在以后可能选修的计算机科学课程里会接触到。
2. **外部链接**（External Chaining）：一个更简单的办法是把哈希值相同的所有键一起存在它们自己的一个集合里，比如一个 `LinkedList`。这个共享同一个下标的条目集合叫作一个**桶**（bucket）。

## 24.5 调整大小与哈希表的性能

不管 `hashCode()` 方法有多好，如果哈希表的底层数组很小，而我们往里加了很多键，冲突就会越来越多。因此，哈希表在开始变满时应该扩大底层数组（就像 `ArrayList` 满了会扩大一样）。

为了记录哈希表有多满，我们定义**负载因子**（load factor）这个术语，它是插入的元素个数与数组实际总长度之比。

<figure><img src="../.gitbook/assets/image (55).png" alt="负载因子等于元素个数除以数组总容量的公式"><figcaption><p>一个非常重要的公式</p></figcaption></figure>

对我们的哈希表，我们会规定允许的最大负载因子。**如果再加入一个键值对会让负载因子超过规定的最大负载因子，哈希表就应该调整大小。** 通常的做法是把底层数组的长度加倍。Java 默认的最大负载因子是 0.75，它在数组大小合理和减少冲突之间取得了很好的平衡。

注意，如果要加入一个键值对，而这个键已经在哈希映射里了，就应该更新对应的值，但不应该调整大小。

举个例子，设想哈希表的数组长度为 10，目前有 7 个元素。这 7 个元素的哈希值都对 10 取模，因为我们想得到 0 到 9 范围内的下标。当前的负载因子是 7/10，即 0.7，刚好低于阈值。

如果再插入一个元素，哈希表里一共有 8 个元素，负载因子是 0.8。因为这会让负载因子超过最大负载因子，我们必须在插入这个元素之前把底层数组调整成长度 20。记住，因为在哈希表中定位一个条目的步骤是取 `hashCode() % array.length`，而数组的长度从 10 变成了 20，哈希表里的所有元素都需要重新安置。所有元素重新安置好、新元素也加进去之后，负载因子是 8/20，即 0.4，低于最大负载因子。

## 24.6 小结

在本章里，我们学习了哈希，这是一种强大的技术，能把 `String` 这样更复杂的对象变成 `int` 这样可以用数字表示的值。

*哈希表*是把*哈希函数*与「数组可以在常数时间内按下标访问」这一事实结合起来的数据结构。利用哈希表和映射这个抽象数据类型，我们可以构建一个 `HashMap`，只要知道键落在哪个桶里，它就能以均摊常数时间访问任何键值对。

不过，我们很快看到这种朴素的实现有几个缺点：表示各种不同对象的能力、内存效率以及冲突。

我们研究了 `hashCode()` 函数的重要性，理解了它怎样影响哈希表的运行时间。为了让数组的大小更小，我们用取模运算符把哈希值缩小到指定的数字范围。然后我们加入外部链接来解决冲突，让多个条目以 LinkedList 的形式住在同一个桶里，并探讨了基于负载因子的调整大小功能！
