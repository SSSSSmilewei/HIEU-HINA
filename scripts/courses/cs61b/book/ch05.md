# 第 5 章　SLList

> 本页是 UC Berkeley CS61B 2026 春季官方教材（Berkeley-CS61B/sp26-gitbook）第 5 章的中文翻译，原文见页面下方的「教材原文」。代码保持原样，代码中的注释不翻译。原教材的部分插图来自旧版教材网站，现在只能从网页存档里取，加载可能较慢。

在第 3 章里，我们构建了 `IntList` 类，这个列表数据结构在技术上能做列表能做的所有事情。不过，在实践中，`IntList` 的问题是用起来相当别扭，写出来的代码难以阅读和维护。

从根本上说，问题在于 `IntList` 是我所说的**裸递归**（naked recursive）数据结构。要正确使用 `IntList`，程序员即使做简单的列表相关任务，也必须理解并运用递归。这限制了它对新手程序员的用处，而且取决于 `IntList` 类提供了哪些辅助方法，还可能引入一整类程序员会遇到的棘手错误。

受 `IntList` 经验的启发，我们现在要构建一个新类 `SLList`，它和现代语言里程序员使用的列表实现要相像得多。我们会通过一步步加入一系列改进来做到这一点。

### 改进一：改头换面

上次的 `IntList` 类如下（省略了辅助方法）：

```java
public class IntList {
    public int first;
    public IntList rest;

    public IntList(int f, IntList r) {
        first = f;
        rest = r;
    }
...
```

第一步，我们只是把所有东西改个名字，并扔掉辅助方法。这看起来大概不像是进步，但相信我，我是专业的。

```java
public class IntNode {
    public int item;
    public IntNode next;

    public IntNode(int i, IntNode n) {
        item = i;
        next = n;
    }
}
```

### 改进二：设立「中间层」

既然知道 `IntNode` 不好用，我们要另外创建一个叫 `SLList` 的类，让用户和它打交道。基本的类就是：

```java
public class SLList {
    public IntNode first;

    public SLList(int x) {
        first = new IntNode(x, null);
    }
}
```

已经可以隐约看出 `SLList` 为什么更好了。比较一下创建一个只有一项的 `IntList` 和创建一个只有一项的 `SLList`：

```java
IntList L1 = new IntList(5, null);
SLList L2  = new SLList(5);
```

`SLList` 对用户隐藏了「存在一个 null 链接」这一细节。`SLList` 类现在还没什么用，所以我们加上 `addFirst` 和 `getFirst` 两个方法作为简单的热身。继续读下去之前，先试着自己写一写。

### addFirst 和 getFirst

如果理解了第 2.1 节（即第 3 章前半），`addFirst` 相对直接。用 `IntList` 时，我们用 `L = new IntList(5, L)` 这行代码往前面加元素。于是得到：

```java
public class SLList {
    public IntNode first;

    public SLList(int x) {
        first = new IntNode(x, null);
    }

    /** Adds an item to the front of the list. */
    public void addFirst(int x) {
        first = new IntNode(x, first);
    }
}
```

`getFirst` 更简单。只要返回 `first.item`：

```java
/** Retrieves the front item from the list. */
public int getFirst() {
    return first.item;
}
```

这样得到的 `SLList` 类好用得多。比较一下：

```java
SLList L = new SLList(15);
L.addFirst(10);
L.addFirst(5);
int x = L.getFirst();
```

和等价的 `IntList` 写法：

```java
IntList L = new IntList(15, null);
L = new IntList(10, L);
L = new IntList(5, L);
int x = L.first;
```

把两种数据结构画出来比较，得到下图（上面是 `IntList` 版，下面是 `SLList` 版）：

![IntList\_vs\_SLList.png](https://joshhug.gitbooks.io/hug61b/content/chap2/fig22/IntList_vs_SLList.png)

本质上，`SLList` 类在列表的用户和裸递归数据结构之间充当中间人。正如上面 `IntList` 版本所暗示的，`IntList` 的用户可能会有指向 `IntList` 中间的变量，这是我们不希望看到的。正如奥维德所说：[凡人不能直视神而不死](https://en.wikipedia.org/wiki/Semele)，所以也许最好还是让 `SLList` 来当我们的中间人。

**练习 2.2.1**：好奇的读者可能会反对说，只要给 `IntList` 写一个 `addFirst` 方法，它也一样好用。试着给 `IntList` 类写一个 `addFirst` 方法。你会发现写出来的方法既棘手又低效。

### 改进三：public 与 private

遗憾的是，我们的 `SLList` 可以被绕过，用户可以直接动用裸数据结构的原始力量（连同它的一切危险）。程序员很容易不经过那个「孩子试过、妈妈认可」的 `addFirst` 方法，直接修改列表，例如：

```java
SLList L = new SLList(15);
L.addFirst(10);
L.first.next.next = L.first.next;
```

![bad\_SLList.png](https://joshhug.gitbooks.io/hug61b/content/chap2/fig22/bad_SLList.png)

这会得到一个带无限循环的畸形列表。为了处理这个问题，可以修改 `SLList` 类，用 `private` 关键字声明 `first` 变量。

```java
public class SLList {
    private IntNode first;
...
```

私有（private）变量和方法只能被同一个 `.java` 文件里的代码访问，在这里就是 `SLList.java`。这意味着像下面 `SLLTroubleMaker` 这样的类会编译失败，报错 `first has private access in SLList`。

```java
public class SLLTroubleMaker {
    public static void main(String[] args) {
        SLList L = new SLList(15);
        L.addFirst(10);
        L.first.next.next = L.first.next;
    }
}
```

相比之下，`SLList.java` 文件里的任何代码都能访问 `first` 变量。

限制访问看起来可能有点傻。毕竟，`private` 关键字唯一做的事，就是让本来能编译的程序编译不过。然而，在大型软件工程项目里，`private` 关键字是一个极其宝贵的信号，表示某些代码应该被最终用户忽略（因此也不必理解）。同样，`public` 关键字应该被看作一项声明：这个方法是可用的，并且会**永远**像现在这样工作。

打个比方，汽车有一些「公开」（`public`）的功能，例如油门和刹车踏板。在引擎盖下面，有关于它们怎样工作的「私有」（`private`）细节。在燃油车里，油门踏板可能控制着某种燃油喷射系统；在电动车里，它可能调节输送给电机的电量。虽然私有细节因车而异，但我们期望所有油门踏板的行为都一样。改变这一点会让用户极为惊慌，很可能还会造成可怕的事故。

**当你创建一个 `public` 成员（即方法或变量）时要小心，因为这实际上是在承诺永远完全按现在的样子支持这个成员的行为。**

### 改进四：嵌套类

现在我们有两个 `.java` 文件：`IntNode` 和 `SLList`。不过，`IntNode` 其实只是 `SLList` 这个故事里的一个配角。

Java 正好为这种情况提供了把一个类的声明嵌在另一个类里面的能力。语法直接而直观：

```java
public class SLList {
       public class IntNode {
            public int item;
            public IntNode next;
            public IntNode(int i, IntNode n) {
                item = i;
                next = n;
            }
       }

       private IntNode first; 

       public SLList(int x) {
           first = new IntNode(x, null);
       } 
...
```

使用嵌套类对代码性能没有实质影响，它只是一种组织代码的工具。关于嵌套类的更多内容，见 [Oracle 官方文档](https://docs.oracle.com/javase/tutorial/java/javaOO/nested.html)。

如果嵌套类不需要使用 `SLList` 的任何实例方法或实例变量，可以把嵌套类声明为 `static`，如下所示。把嵌套类声明为 `static` 意味着这个静态类里的方法不能访问外围类的任何成员。在这里，这意味着 `IntNode` 里的任何方法都不能访问 `first`、`addFirst` 或 `getFirst`。

```java
public class SLList {
       public static class IntNode {
            public int item;
            public IntNode next;
            public IntNode(int i, IntNode n) {
                item = i;
                next = n;
            }
       }

       private IntNode first;
...
```

这能省一点内存，因为每个 `IntNode` 不再需要记录怎样访问它的外围 `SLList`。

换句话说，看上面的代码会发现，`IntNode` 类从来不使用 `SLList` 的 `first` 变量，也不使用 `SLList` 的任何方法。因此，我们可以用 static 关键字，这表示 `IntNode` 类不会得到一个指向它「上司」的引用，从而为我们省下少量内存。

如果觉得这有点技术性、不好理解，就试试练习 2.2.2。一条简单的经验法则是：*如果不使用外部类的任何实例成员，就把嵌套类声明为 static*。

**练习 2.2.2**：尽可能少地删除 `static` 这个词，让 [这个程序](https://joshhug.gitbooks.io/hug61b/content/chap2/exercises/Government.java) 能够编译（点开链接后刷新页面，确认网址变了）。做练习之前一定要读一读文件顶部的注释。

### addLast() 和 size()

为了引出剩下的几项改进，同时展示数据结构实现中的一些常见模式，我们要加上 `addLast(int x)` 和 `size()` 两个方法。鼓励你先拿 [起始代码](https://github.com/Berkeley-CS61B/lectureCode/blob/master/lists2/DIY/addLastAndSize/SLList.java) 自己试试，再往下读。我特别鼓励你试着写一个递归的 `size` 实现，这会是一个有意思的挑战。

我会用迭代的方式实现 `addLast` 方法，不过也可以用递归。思路相当直接：创建一个指针变量 `p`，让它沿列表一直走到末尾。

```java
/** Adds an item to the end of the list. */
public void addLast(int x) {
    IntNode p = first;

    /* Advance p to the end of the list. */
    while (p.next != null) {
        p = p.next;
    }
    p.next = new IntNode(x, null);
}
```

相比之下，我会用递归实现 `size`。这个方法和我们在 [2.1 节](https://joshhug.gitbooks.io/hug61b/content/chap2/chap21.html)（即第 3 章）为 `IntList` 实现的 `size` 方法有些相似。

`IntList` 里 `size` 的递归调用很直接：`return 1 + this.rest.size()`。对 `SLList` 来说，这种做法讲不通。`SLList` 没有 `rest` 变量。我们改用一种在 `SLList` 这类中间人类里常用的模式——创建一个私有的辅助方法，由它和底层的裸递归数据结构打交道。

这样就得到下面这样的方法：

```java
/** Returns the size of the list starting at IntNode p. */
private static int size(IntNode p) {
    if (p.next == null) {
        return 1;
    }

    return 1 + size(p.next);
}
```

用这个方法，很容易算出整个列表的大小：

```java
public int size() {
    return size(first);
}
```

这里有两个方法都叫 `size`。在 Java 里这是允许的，因为它们的参数不同。我们说名字相同而签名不同的两个方法是**重载**（overloaded）的。关于重载方法的更多内容，见 Java 的 [官方文档](https://docs.oracle.com/javase/tutorial/java/javaOO/methods.html)。

另一种做法是在 `IntNode` 类本身里创建一个非静态的辅助方法。两种做法都可以，不过我个人更喜欢 `IntNode` 类里一个方法也没有。

## 改进五：缓存

考虑上面写的 `size` 方法。假设 `size` 在大小为 1,000 的列表上要花 2 秒。我们预计在大小为 1,000,000 的列表上，`size` 方法要花 2,000 秒，因为计算机要逐个走过多 1,000 倍的元素才能到达末尾。对大列表非常慢的 `size` 方法是不可接受的，因为我们能做得更好。

可以重写 `size`，让它不论列表多大，花的时间都一样。

为此，只要给 `SLList` 类加一个 `size` 变量，记录当前的大小，得到下面的代码。这种保存重要数据以加快读取的做法，有时叫作**缓存**（caching）。

```java
public class SLList {
    ... /* IntNode declaration omitted. */
    private IntNode first;
    private int size;

    public SLList(int x) {
        first = new IntNode(x, null);
        size = 1;
    }

    public void addFirst(int x) {
        first = new IntNode(x, first);
        size += 1;
    }

    public int size() {
        return size;
    }
    ...
}
```

这个修改让 `size` 方法不论列表多大都快得惊人。当然，它也会让 `addFirst` 和 `addLast` 方法变慢，并增加类的内存占用，但只是微不足道的一点。在这里，权衡的结果显然支持为大小建立缓存。

### 改进六：空列表

和第 2.1 节（即第 3 章）里简单的 `IntList` 相比，我们的 `SLList` 有很多优点：

* `SLList` 的用户永远看不到 `IntList` 类。
  * 用起来更简单。
  * `addFirst` 方法更高效（练习 2.2.1）。
  * 避免 `IntList` 用户犯错或乱来。
* `size` 方法比 `IntList` 可能做到的更快。

另一个自然的好处是，我们可以很容易地实现一个创建空列表的构造函数。最自然的办法是在列表为空时把 `first` 设为 `null`。这样得到下面的构造函数：

```java
public SLList() {
    first = null;
    size = 0;
}
```

遗憾的是，这会让我们的 `addLast` 方法在往空列表里插入时崩溃。因为 `first` 是 `null`，下面的 `while (p.next != null)` 试图访问 `p.next`，会引发空指针异常。

```java
public void addLast(int x) {
    size += 1;
    IntNode p = first;
    while (p.next != null) {
        p = p.next;
    }

    p.next = new IntNode(x, null);
}
```

### 改进六（续）：哨兵节点

修好 `addLast` 的一种办法是为空列表写一个特殊情形，如下所示：

```java
public void addLast(int x) {
    size += 1;

    if (first == null) {
        first = new IntNode(x, null);
        return;
    }

    IntNode p = first;
    while (p.next != null) {
        p = p.next;
    }

    p.next = new IntNode(x, null);
}
```

这个办法管用，但只要可能，就应该避免上面那样的特殊情形代码。人的工作记忆有限，所以我们要尽可能把复杂度控制住。对 `SLList` 这样简单的数据结构，特殊情形的数量还不多。树这样更复杂的数据结构可能会变得非常非常难看。

一个更整洁但不那么显而易见的办法，是让所有 `SLList` 都「一样」，即使它们是空的。我们可以创建一个始终存在的特殊节点来做到这一点，称它为**哨兵节点**（sentinel node）。哨兵节点会存一个值，但我们不关心这个值是什么。

例如，`SLList L = new SLList()` 创建的空列表如下图所示：

![empty\_sentinelized\_SLList.png](https://joshhug.gitbooks.io/hug61b/content/chap2/fig22/empty_sentinelized_SLList.png)

而存有 5、10、15 三项的 `SLList` 是这样的：

![three\_item\_sentenlized\_SLList.png](https://joshhug.gitbooks.io/hug61b/content/chap2/fig22/three_item_sentenlized_SLList.png)

在上图中，淡紫色的 ?? 表示我们不关心那里是什么值。因为 Java 不允许用问号填整数，我们就随便挑一个值，比如 -518273 或 63 之类。

因为有哨兵的 `SLList` 没有特殊情形，我们可以直接从 `addLast` 方法里删掉特殊情形，得到：

（译注：原文这里写的是「没有哨兵的」（without a sentinel），按上下文应为「有哨兵的」，译文已更正。）

```java
public void addLast(int x) {
    size += 1;
    IntNode p = sentinel;
    while (p.next != null) {
        p = p.next;
    }

    p.next = new IntNode(x, null);
}
```

可以看到，这段代码整洁得多了！

### 不变式

**不变式**（invariant）是关于一个数据结构的、保证为真的事实（假设你的代码没有 bug）。

带哨兵节点的 `SLList` 至少有以下不变式：

* `sentinel` 引用总是指向一个哨兵节点。
* 最前面的元素（如果存在）总是在 `sentinel.next.item`。
* `size` 变量总是等于已添加元素的总数。

不变式让代码更容易推理，也为你确保代码正确提供了具体的目标。
