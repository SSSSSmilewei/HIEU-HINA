## 17.1 旋转树

*就像摩天轮一样。*

B 树虽然平衡得非常好，但实在很难实现。我们要记录不同的节点，拆分过程也相当复杂。作为欣赏整洁代码、也喜欢接受挑战的计算机科学家，我们来找另一种创建平衡树的办法。

### 树的旋转

旋转的正式定义是：

```
rotateLeft(G): Let x be the right child of G. Make G the new left child of x.
```

```
rotateRight(G): Let x be the left child of G. Make G the new right child of x.
```

即：`rotateLeft(G)`（左旋 G）：设 x 是 G 的右孩子，让 G 成为 x 新的左孩子。`rotateRight(G)`（右旋 G）：设 x 是 G 的左孩子，让 G 成为 x 新的右孩子。

接下来几段，我们会慢慢揭开这个过程的神秘面纱。

下面图示了对节点 G 做一次左旋时发生了什么：

<figure><img src="../.gitbook/assets/Screen Shot 2023-02-27 at 7.38.06 PM.png" alt=""><figcaption><p>rotateLeft(G)</p></figcaption></figure>

上面发生的事用文字描述是：

* G 的右孩子 P 和 G 合并，带着它的孩子们一起。
* 然后 P 把它的左孩子交给 G，G 往左下方移，成为 P 的左孩子。

可以看到，树的结构和高度都变了。也可以在非根节点上旋转。只需暂时把这个节点和它的父节点断开，在这个节点处旋转子树，再把新的根接回去。

#### 实现

下面是 `rotateRight` 和 `rotateLeft` 的实现：

```
private Node rotateRight(Node h) {
    // assert (h != null) && isRed(h.left);
    Node x = h.left;
    h.left = x.right;
    x.right = h;
    return x;
}

// make a right-leaning link lean to the left
private Node rotateLeft(Node h) {
    // assert (h != null) && isRed(h.right);
    Node x = h.right;
    h.right = x.left;
    x.left = h;
    return x;
}
```

你可能会想，旋转之后父节点怎么知道该指向哪个节点？这就是为什么我们返回 x，代码的其他部分会利用这个信息正确地更新父节点的指针。

## 17.2 构造左倾红黑树

*软件工程师？不如叫树木工程师。*

上一节说过，我们非常喜欢 2-3 树，因为它们总是保持平衡，但它们很难实现。另一方面，BST 可能不平衡，但我们喜欢它的简单直观。有没有办法两全其美？为什么不创建一种用 BST 实现、但在结构上和 2-3 树完全相同、因而保持平衡的树呢？

（注意本章专门聚焦于 2-3 树，而不是 2-3-4 树。）

### 走进红黑树

#### 从 2-3 树变成什么？

我们来构造这种树：看着一棵 2-3 树，问问自己可以做什么样的修改，把它变成一棵 BST。

对于只有 2-节点（有 2 个孩子的节点）的 2-3 树，它本来就是 BST，不需要任何修改！

但是遇到 3-节点时会怎样？

我们可以做的一件事是创建一个「胶水」节点，它不存任何信息，只用来表示它的 2 个孩子其实属于同一个节点。

<figure><img src="../.gitbook/assets/Screen Shot 2023-02-27 at 8.28.55 PM.png" alt=""><figcaption><p>朴素的解决办法：假的「胶水」节点</p></figcaption></figure>

不过，这不是一个优雅的办法，因为它占用更多空间，代码也会很难看。所以，我们不用胶水节点，而改用**胶水链接**（glue link）！

#### 变成 LLRB 树

为了把假的胶水节点变成胶水链接，我们任意选择让左边的元素成为右边元素的孩子。这样就得到一棵**左倾**的树。

<figure><img src="../.gitbook/assets/Screen Shot 2023-02-27 at 8.31.57 PM.png" alt=""><figcaption><p>左倾红黑树</p></figcaption></figure>

我们把胶水链接画成红色来表示它。普通的链接是黑色的。因此，我们把这种结构叫作**左倾红黑树**（left-leaning red-black tree，LLRB）。这门课里我们用左倾的树。

#### 一一对应

左倾红黑树和 **2-3 树一一对应**。每棵 2-3 树都有一棵与之对应的**唯一**的 LLRB 红黑树。

至于 2-3-4 树，它们和标准的红黑树一一对应。

### LLRB 的性质

{% embed url="https://www.youtube.com/watch?index=4&list=PL8FaHk7qbOD6aKgTz2W-foDiTeBEaBoS3&v=4nZFgj7t52E" %}

下面汇总了 LLRB 树的性质（不变式）：

* 和 2-3 树一一对应。
* 没有节点有 2 条红链接。
* 没有向右的红链接。
* 从根到叶子的每条路径上，黑链接的数量都相同（因为 2-3 树到每个叶子的链接数都相同）。
* 高度不超过对应 2-3 树高度的 2 倍加 1。
* 红黑树的高度和条目数的对数成正比。

## 17.3 往 LLRB 树里插入

*一些树的养护工作。*

我们总可以这样往 LLRB 树里插入：先插入到 2-3 树里，再像前面那样转换。不过，这有悖于我们创建 LLRB 的初衷，即避免 2-3 树复杂的实现！

我们改为**像往普通 BST 里插入那样往 LLRB 里插入**。不过，这可能破坏它和 2-3 树的一一对应，所以我们用**旋转**把树调整回正确的结构。

### 保持正确的结构

往 LLRB 树里插入时，新节点总是用一条**红链接**连到它的父节点。这是因为在 2-3 树里，我们总是把元素加到一个叶子节点里，所以加上的链接应该总是红色的。

但有时在某些位置插入红链接，可能导致破坏 LLRB 的某条不变式。

下面是三种这样的情形，需要执行特定的操作来保持 LLRB 树的正确结构：

* 情形 1：**插入后得到一个右倾的「3-节点」→ 左倾违规**
  * **操作 1：rotateLeft(node)**
  * 回想一下，我们用的是*左倾*红黑树，这意味着永远不能有向右的红链接。
  * 为了处理这个问题，需要用一次**旋转**来保持 LLRB 不变式：「没有向右的红链接」。
  * 如果左孩子*也*是红链接，我们暂时允许这样，原因在情形 2 里会更清楚。

  <figure><img src="../.gitbook/assets/Screen Shot 2023-02-27 at 8.57.00 PM.png" alt=""><figcaption><p>情形 1：插入一条向右的红链接</p></figcaption></figure>

* 情形 2：**在左边连续插入两次 → 不正确的 4-节点违规**
  * **操作 2：rotateRight(node)**
  * 如果有 2 条连续的左红链接，就有了一个不合法的 4-节点。
  * 为了处理这个问题，我们先**旋转**，得到和上面情形 1 一样的树。然后在两种情况下，都用情形 3 来处理暂时出现的不合法 4-节点。

  <figure><img src="../.gitbook/assets/Screen Shot 2023-02-27 at 8.58.30 PM.png" alt=""><figcaption><p>情形 2：在左边连续插入两次</p></figcaption></figure>

* 情形 3：**节点有两个红孩子 → 临时 4-节点**
  * **操作 3：颜色翻转**
  * 最后，通过**翻转**上图中碰到「S」的所有边的**颜色**，来处理不合法 4-节点的问题。
  * 这相当于在 2-3 树中把中间的节点往上推。

  <figure><img src="../.gitbook/assets/Screen Shot 2023-02-27 at 9.02.17 PM.png" alt=""><figcaption><p>情形 3：两条红链接</p></figcaption></figure>

注意：为了完成转换，你可能需要经过一系列旋转。一个操作可能会导致新的 LLRB 规则违规，可以用相应的操作修正。

过程是：只要 LLRB 树不满足和 2-3 树的一一对应，或者破坏了 LLRB 不变式，就根据树的状况执行操作 1、2 或 3，直到得到一棵合法的 LLRB。

### 养护操作小结

* 插入时：用一条**红链接**。插入方式和往 BST 里插入一样。
* 如果有一个右倾的「3-节点」，就有一个**左倾违规**。
  * 对相应的节点**左旋**来修正。
* 如果有两条连续的左链接，就有一个**不正确的 4-节点违规**。
  * 对相应的节点**右旋**来修正。
* 如果有任何节点有两个红孩子，就有一个**临时 4-节点**。
  * 对这个节点做**颜色翻转**，模拟拆分操作。

## 17.4 运行时间分析

*简短而美好。*

因为左倾红黑树和 2-3 树一一对应，而且高度总在对应 2-3 树高度的 2 倍以内，所以各操作的运行时间是 $\log(N)$。

下面是往 LLRB 里插入的抽象代码：

```
private Node put(Node h, Key key, Value val) {
    if (h == null) { return new Node(key, val, RED); }

    int cmp = key.compareTo(h.key);
    if (cmp < 0)      { h.left  = put(h.left,  key, val); }
    else if (cmp > 0) { h.right = put(h.right, key, val); }
    else              { h.val   = val;                    }

    if (isRed(h.right) && !isRed(h.left))      { h = rotateLeft(h);  }
    if (isRed(h.left)  &&  isRed(h.left.left)) { h = rotateRight(h); }
    if (isRed(h.left)  &&  isRed(h.right))     { flipColors(h);      } 

    return h;
}
```

## 17.5 小结

* 二叉搜索树很简单，但容易失衡，导致糟糕的运行时间。2-3 树（B 树）是平衡的，但实现起来很痛苦。
* LLRB 的插入实现起来很简单（删除实现起来难一些，这门课不讲具体细节）。
  * 用三种基本操作来保持平衡的结构，即 rotateLeft、rotateRight 和颜色翻转。
* LLRB 和 2-3 树对应，标准红黑树和 2-3-4 树对应。
  * Java 的 [TreeMap](https://github.com/AdoptOpenJDK/openjdk-jdk11/blob/999dbd4192d0f819cb5224f26e9e7fa75ca6f289/src/java.base/share/classes/java/util/TreeMap.java) 是一棵对应 2-3-4 树的红黑树。
  * 2-3-4 树允许胶水链接出现在任一边（见 [红黑树](http://en.wikipedia.org/wiki/Red%E2%80%93black_tree)）。
  * 实现更复杂，但更快。
