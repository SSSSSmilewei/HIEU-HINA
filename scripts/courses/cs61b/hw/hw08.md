### 起始代码

你可能在讲座里记得，构建哈希表时，桶可以选用多种不同的数据结构。经典的做法是选 `LinkedList`（链表）。但我们也可以选 `ArrayList`、`TreeSet`，甚至更疯狂的，比如 `PriorityQueue`，甚至是 `HashSet`！

![](https://sp26.datastructur.es/assets/homeworks/hw08/ht-buckets.webp)

我们会给哈希表的桶换用不同的数据结构，用实验看看不同的桶结构在渐近意义上有没有差别。

我们会试用 `LinkedList`、`ArrayList`、`HashSet`、`Stack` 和 `ArrayDeque`（遗憾的是，由于样板代码太多，上面示意图里画的 `TreeSet` 和 `PriorityQueue` 没有包含在内，不过你想试也欢迎）。类真不少！

可以想象，如果实现 `MyHashMap` 时不加注意，想换一种桶的类型，就得靠「查找 + 替换」费好大一番功夫。例如，想把所有的 `ArrayList` 桶换成 `LinkedList` 桶，就得把所有出现的 `ArrayList` 查找出来替换成 `LinkedList`。这并不理想——比如，代码里可能有某个与桶无关的组件用到了 `ArrayList` 的方法，我们总不希望把它改成 `LinkedList` 而毁掉代码吧！

起始代码的目的，就是给 `MyHashMap` 提供一个更方便地试用不同桶类型的方式。它靠我们这学期早些时候学过的*多态*（polymorphism）和*继承*（inheritance）实现这一点。它还用到了**工厂方法和工厂类**（factory methods and classes）——用来创建对象的实用工具代码。这是编写较高级代码时的常见模式，不过细节超出了 61B 的范围。

`MyHashMap` 通过哈希表来实现 `Map61B` 接口。起始代码里给出了实例变量 `private Collection<Node>[] buckets`，它是哈希表的底层数据结构。我们来拆解一下这行代码的含义：

- `buckets` 是 `MyHashMap` 类里的一个 `private` 变量：

```
private Collection<Node>[] buckets;
```

- 它是一个由 `Collection<Node>` 对象组成的数组（或者说表），其中每个 `Node` 的 `Collection` 代表哈希表里的一个桶。
- `Node` 是我们提供的一个私有（嵌套）辅助类，存储单个键值映射。这个类的起始代码应该不难懂，也不需要修改。

```
protected class Node {
    K key;
    V value;

    Node(K k, V v) {
        key = k;
        value = v;
    }
}
```

- [`java.util.Collection`](https://docs.oracle.com/javase/8/docs/api/java/util/Collection.html) 是一个大多数数据结构都继承自它的接口，它表示一组对象。`Collection` 接口支持 `add`、`remove`、`iterator` 等方法。`java.util` 里的许多数据结构都实现了 `Collection`，包括 `ArrayList`、`LinkedList`、`TreeSet`、`HashSet`、`PriorityQueue` 等等。注意，正因为这些数据结构都实现了 `Collection`，我们可以用多态把它们赋给静态类型为 `Collection` 的变量。
- 因此，这个 `Collection<Node>` 对象的数组可以用许多不同的数据结构来实例化，例如 `LinkedList<Node>` 或 `ArrayList<Node>`。**务必保证你的桶能推广到任意 Collection！**具体怎么做，见下面的警告框。
- 在创建新的 `Collection<Node>[]` 存进 `buckets` 变量时，注意 Java [不允许创建参数化类型的数组](https://docs.oracle.com/javase/tutorial/java/generics/restrictions.html#createArrays)。`Collection<Node>` 是参数化类型，因为我们用 `Node` 类参数化了 `Collection` 类。因此，对任何给定的 `size`，Java 都不允许 `new Collection<Node>[size]`。如果你试着这么写，会得到「Generic array creation」（泛型数组创建）错误。

> 绕过这个问题的办法是：改为创建 `new Collection[size]`，其中 `size` 是想要的大小。

- `Collection[]` 的元素可以是任何类型的集合，比如 `Collection<Integer>` 或 `Collection<Node>`。**在我们的用途里，只会往 `Collection[]` 里放 `Collection<Node>` 类型的元素。**

不同哈希表实现配不同桶，靠的是工厂方法 `protected Collection<Node> createBucket()`，它就是返回一个 `Collection`。在 `MyHashMap.java` 里，你可以任选一种数据结构。例如选 `LinkedList` 的话，`createBucket` 的方法体就只是：

```
protected Collection<Node> createBucket() {
	return new LinkedList<>();
}
```

**不要用 `new` 运算符直接创建新的桶数据结构，必须改用 `createBucket` 方法**。乍看似乎没什么用，但它让我们的工厂类可以重写 `createBucket` 方法，从而为各个哈希表配不同的桶数据结构。

在 `MyHashMap` 里，让这个方法返回一个新的 `LinkedList` 或 `ArrayList` 就行。

> 计算装载因子时，确保结果以 `double` 精度而不是 `int` 精度记录。下面的代码*不*能用，因为它先做 `int` 除法，再把结果表示成 double。

```
int elements = 3;
int buckets = 16;
double loadFactor = elements / buckets;
```

*注意：整数除法向下取整：`3 / 16 = 0`。这个值随后才被转换成 double：`0 -> 0.0`。想绕过这一点，请查一下 Java 的「类型转换」（casting）。*

### 实现要求

你应该实现以下构造方法：

```
public MyHashMap();
public MyHashMap(int initialCapacity);
public MyHashMap(int initialCapacity, double loadFactor);
```

`MyHashMap` 还有一些别的要求：

- 你的哈希表最初应有 `initialCapacity` 那么多个桶。当装载因子超过最大 `loadFactor` 阈值时，应当扩大 `MyHashMap` 的规模。回忆一下，当前**装载因子**可以这样计算：`loadFactor = N/M`，其中 `N` 是映射中的元素数，`M` 是桶数。装载因子表示平均每个桶里的元素数量。如果没有给出 `initialCapacity` 和 `loadFactor`，应设默认值 `initialCapacity = 16`、`loadFactor = 0.75`（和 Java [内置的 HashMap](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/util/HashMap.html#%3Cinit%3E()) 一样）。
- 冲突要用*分离链接*（separate chaining，即拉链法）处理。除了桶的类、`Collection`、`Iterator`、`Set` 和 `HashSet` 之外，不允许使用其他任何库。分离链接具体应该怎么实现，见上面的「起始代码」一节。
- 因为桶用的是 `Collection<Node>[]`，实现 `MyHashMap` 时，你只能使用 `Collection` 接口中规定的方法。**在 `Collection` 里查找一个 `Node` 时，要遍历这个 `Collection`，找出 `key` 与目标键 `.equals()` 的那个 `Node`。**
- 如果同一个键被插入多次，每次都应更新其值（即不应添加新的 `Node`）。可以假设永远不会插入 `null` 键。
- 扩容时务必按乘法（几何）扩容，而不是按加法（算术）扩容。**不**要求把表缩回去。
- 假设插入的每个对象的 `hashCode` 都能分散得足够好（**回忆：Java 里的每个 `Object` 都有自己的 `hashCode()` 方法**），`MyHashMap` 的所有操作都应是摊还常数时间。

`hashCode()` 可能返回*负值*！Java 的取模运算符 `%` 对负数输入会返回负值，而我们需要把元素送进范围 $[0, M)$ 内的某个桶。处理办法有很多：

1. （推荐）可以用 `Math.floorMod()` 代替 `%` 做取模运算。它的结果是非负的，类似 Python 的取模。
2. 如果 `%` 运算的结果是负的，可以加上数组的大小。
3. 可以用 `Math.abs()` 函数把负值转成正值。注意，$|x| \, \mathrm{mod} \, m$、$|x \, \mathrm{mod} \, m|$ 和 $x \, \mathrm{mod} \, m$ **一般并不等价**！我们这里用取模只是为了得到一个合法的下标，并不太在意元素究竟落在哪个桶里，因为好的哈希函数本就应该在正数和负数上都分散得很好。
4. 做法同 (3)，但用位掩码（bitmask，不知道这是什么也没关系）。这超出了 61B 的范围，不过有些参考资料会这么写，所以我们把它列在这里。

## 常见问题

### 我遇到了「Generic array creation」（泛型数组创建）错误。

务必用 `new Collection[size]` 或 `(Collection<Node>[]) new Object[size]` 来实例化你的桶数组！

### 我在扩容时遇到问题，看到「expected to be greater than [this value], but was [this value]」。

例如，你可能会看到这样的错误信息：

```
expected to be greater than: 16
but was                    : 16
```

如果你遇到了这个问题，一个常见的原因出在装载因子的计算上。装载因子等于映射中的元素总数除以桶总数——这两个值通常都以整数存储，但记住，装载因子是 double。Java 的整数除法会在这里惹出什么问题呢？
