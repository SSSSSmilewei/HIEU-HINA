
注意：有界类型参数的语法（`<K extends Comparable<K>, V>`）有点绕，我们在下面给了一个例子。这里我们为 `Comparable` 对象创建一个 `BSTSet`。我们出于教学目的放进了有点奇怪的 `compareRoots` 方法（想复习 `compareTo` 的话，看这份[文档](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/lang/Comparable.html#compareTo(T))）：

```
public class BSTSet<K extends Comparable<K>> implements Set61B<K> {
    private class BSTNode {
        K item;
        // ...
    }

    private BSTNode root;

    /* Returns whether this BSTSet's root is greater than, equal to, or less
     * than the other BSTSet's root, following the usual `compareTo`
     * convention. */
    public int compareRoots(BSTSet other) {
        /* We are able to safely invoke `compareTo` on `n1.item` because we
         * know that `K` extends `Comparable<K>`, so `K` is a `Comparable`, and
         *`Comparable`s must implement `compareTo`. */
        return this.root.item.compareTo(other.root.item);
    }

    // ...
}
```

记住：上面的代码片段实现的是一个*集合*（Set）——而你要实现的是一个*映射*（Map）。我们建议你在 `BSTMap` 里使用类似的逻辑，并定义某个嵌套的节点类来辅助实现。你的 `BSTMap` 有两个泛型参数 `K` 和 `V`，分别表示 `BSTMap` 中键和值的类型。

注意：我们**强烈建议**你创建辅助方法来简化实现（特别推荐递归的辅助方法）。另外，记住要避免「一臂长递归」（arms length recursion，指去检查当前节点的左/右孩子是否为 null，而不是检查节点本身是否为 null）。更多信息见第 16 讲的幻灯片。

你可以用 `TestBSTMap.java` 测试你的实现。

遗憾的是，你要实现的大多数方法在测试时都依赖别的方法（比如 `get` 的测试需要 `put`）。这使得在实现 `put` 之前，大多数方法都很难测试。我们建议你按 `Map61B` 中给出的顺序实现这些方法。

除非另有说明，「大 O」边界（例如 $O(N)$）和「大 Θ」边界（例如 $\Theta(N)$）指的是给定方法调用中的**比较次数**。

第 1–6 题判断命题真假；第 7 题给出运行时间边界。**译注**：原文此处写的是「第 1–7 题判断真假，第 8 题给出运行时间边界」，但实际只列出了 7 题，其中第 7 题就是要求给出运行时间边界的那道题，译文按实际情况更正。

1. `B.put(K, V)` $\in O(\log N)$
2. `B.put(K, V)` $\in \Theta(\log N)$
3. `B.put(K, V)` $\in \Theta(N)$
4. `B.put(K, V)` $\in O(N)$
5. `B.put(K, V)` $\in O(N^2)$
6. 对某个不等于 `K` 的固定键 `C`，`B.containsKey(C)` 和 `B.containsKey(K)` 的运行时间都是 $\Omega(\log N)$。
7. （这道题相当难。）设 `b` 是某个 `BSTMap` 中的一个 `Node`，它有两棵子树，分别叫 `left` 和 `right`。**译注**：原文此句字面为「and two subtrees rooted at `root`, called `left` and `right`」（两棵以 root 为根、名为 left 和 right 的子树），语序有误；结合 `mystery` 的代码（其中用到 `b.left`、`b.right`），这里指的应是 `b` 的左右子树，译文按此理解。进一步假设：方法 `numberOfNodes(Node p)` 返回以 `p` 为根的子树的节点数（$M$），运行时间为 $\Theta(M)$。在假设 `1 <= z < numberOfNodes(b.root)` 成立时，`mystery(b.root, z)` 在最坏和最好情况下的运行时间各是多少？

   提示：先弄清 `mystery` 在做什么，再看它是怎么做到的。

```
public Key mystery(Node b, int z) {
    int numLeft = numberOfNodes(b.left);
    if (numLeft == z - 1) {
        return b.key;
    } else if (numLeft > z) {
        return mystery(b.left, z);
    } else {
        return mystery(b.right, z - numLeft - 1);
    }
}
```

5. 对（记住：除非另有说明，大 O 不要求是紧的！）。
6. 错。最好情况下，这些节点就在根附近。注意，如果 `C` 和 `K` 是随机选取的，那么在摊还意义下该命题为真，因为树中节点的平均深度由下面这个和给出：$\sum_{h=1}^{\lg n} \frac{h2^h}{N} \in \Theta(\log N)$。
7. `mystery` 找出 BST 中第 `z` 小的元素（下标从 1 开始）。**译注**：原文此处及其后写的是「第 z 大的元素」（the z-th largest），与代码逻辑不符——`mystery` 在左子树节点数恰为 `z - 1` 时返回根的键，因此找出的是第 z *小*的元素（下文「根恰好是第 z 小的元素」等处原文同样写作 largest，译文一并更正）。它的做法是：先计算左子树中的元素个数，再根据左子树的元素太多还是不够，决定向左子树还是右子树递归。注意，`numLeft` 的耗时与左子树的节点数成正比，所以一次递归子调用的工作量是 $\Theta(\text{number of nodes in left subtree})$（即左子树的节点数）。

   对树没有任何附加条件，所以必须分别考虑树茂密、左偏细长、右偏细长三种情形。最好情况是树的根恰好就是第 `z` 小的元素，此时耗时 $\Theta(\text{number of nodes in left subtree})$（因为不再递归）。

   - 茂密的树：左子树有 $\frac{N}{2} - 1$ 个节点，所以最好情况下（`z == N / 2` 时）运行时间是 $\Theta(N)$。
   - 左偏细长的树：左子树有 $N - 1$ 个节点，所以最好情况下（`z == N` 时）运行时间是 $\Theta(N)$。
   - 右偏细长的树：左子树有 $0$ 个节点，所以最好情况下（`z == 1` 时）运行时间是 $\Theta(1)$。

   因此，最好情况的运行时间是 $\Theta(1)$。最坏情况发生在必须一路走到树的叶子时。

   - 茂密的树：第一次递归调用时左子树约有 $\frac{N}{2}$ 个节点，第二次递归调用的左子树约有 $\frac{N}{4}$ 个节点，依此类推，直到碰到叶子。这意味着最坏情况的运行时间是 $\frac{N}{2} + \frac{N}{4} + \frac{N}{8} + \dots + 1 \in \Theta(N)$（当 `z == 1` 时）。
   - 左偏细长的树：这种情况下，每次递归调用的左子树都比它的父节点那次少一个节点。于是总和为 $N + (N-1) + (N-2) + \dots + 1 \in \Theta(N^2)$（当 `z == 1` 时）。
   - 右偏细长的树：每次递归调用时左子树都有 $0$ 个节点，而树高为 $N$，所以最坏情况的运行时间是 $\Theta(N)$（当 `z == N` 时）。

   综合以上情形，最坏情况的运行时间是 $\Theta(N^2)$。总结：最好情况 $\Theta(1)$，最坏情况 $\Theta(N^2)$。
