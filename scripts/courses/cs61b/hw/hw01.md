## 工具概览：终端

这一节没有要做的事；只需要仔细读一遍。真正的任务从任务 1 开始。

在 CS 61B 里，我们会用*终端*（terminal）运行各种命令。

在终端里工作时，终端总有一个*工作目录*（working directory），也就是终端当前「正在想着」的那个文件夹。

- `ls` 命令列出工作目录里的所有文件。
- `pwd` 命令打印出工作目录。
- `cd` 命令改变工作目录。

很多终端命令的行为取决于你的工作目录，所以运行命令之前确认自己在正确的工作目录里是非常重要的！记住，可以用 `pwd` 检查工作目录。

## 工具概览：Git

这一节没有要做的事；只需要仔细读一遍。真正的任务从任务 1 开始。

几乎所有的计算机科学家、数据科学家、软件工程师等等写代码时都用 *Git*。Git 让你能给代码的不同版本拍快照（想退回到以前的版本时很有用）。

Git 还让你能在不同的计算机之间同步一个*仓库*（repository，一个装着你代码的文件夹）。例如，在后面的项目里，你和搭档会用 Git 一起工作。

同步代码的一个常用地方是 *GitHub*。可以把 GitHub 想成云上一台非常大的计算机，每个人都可以把代码同步到这台计算机上（例如保存一份备份，或者和全世界分享代码）。

Git 非常复杂，但在 CS 61B 里你需要知道几个核心命令。

- 要把一个仓库从 GitHub 复制到你的计算机上（在你的计算机上新建一个文件夹），用这个命令：

```
git clone git@github.com:oski/name-of-oskis-repo.git
```

- 要把代码*从*你计算机上的仓库同步*到* GitHub 上的仓库，用这三个命令：

```
# First, take a snapshot of your code. (The commit message is mandatory!)
git add .
git commit -m "your commit message here"

# Then, send your snapshot from your computer to GitHub.
git push origin main
```

（第一段注释的意思是「先给代码拍一个快照，提交说明必须写」；第二段是「再把快照从你的计算机发送到 GitHub」。）

- 要*从* GitHub 上的仓库获取更新、同步*到*你计算机上的仓库，用这个命令：

```
git pull skeleton main
```

## 任务 1：安装 Git

按你的操作系统看对应的说明。

**macOS**

1. 确认磁盘上至少还有 40 GB 的空闲空间。
2. 打开终端。（按 ⌘+空格，输入「Terminal」，按回车。）

## 任务 4：在 GitHub 上完成身份验证

1. 打开终端（或者继续用前面任务里打开的终端）。
2. 运行这个命令：

   ```
   curl -sS --ssl-no-revoke https://sp26.datastructur.es/assets/homeworks/hw01/get-ssh-key.sh | bash
   ```

   在输出中，你应该看到类似下面某一行的内容（意思分别是「好！你新的 SSH 密钥在……」和「你已经有一个 SSH 密钥在……」）：

   ```
   Great! Your new SSH key is at: ~/.ssh/id_ed25519.pub
   You already have an SSH key at: ~/.ssh/id_ed25519.pub
   ```
3. 运行这个命令。如果你的密钥和上面那几行里的不一样，把 `~/.ssh/id_ed25519.pub` 换成你在输出中看到的那个。

   ```
   cat ~/.ssh/id_ed25519.pub
   ```

   你应该看到类似这样的输出：

   ```
   ssh-ed25519 AAAAC3NzaC1lZDI1N6jpH3Bnbebi7Xz7wMr20LxZCKi3U8UQTE5AAAAIBTc2HwlbOi8T oski@oski
   ```
4. 复制上一步的输出。

   打开 [GitHub 的 SSH 设置页面](https://github.com/settings/ssh/new)，把输出粘贴到 Key（密钥）框里。

   Title（标题）随便写（例如有多台计算机时可以写「Laptop」或「Desktop」）。「Key type」（密钥类型）保持「Authentication Key」（身份验证密钥）。点击「Add SSH key」（添加 SSH 密钥）。

   如果你是重修这门课，可能会看到「Key is already in use」（密钥已被使用）。如果是这样，就进入下一步（并确认在下一步能看到成功的消息）。
5. 回到终端，运行这个命令：

   ```
   ssh -T git@github.com
   ```

   如果系统问「The key is not know by any other names. Are you sure you want to continue connecting (yes/no/[fingerprint])?」（是否确定继续连接），输入「yes」。

   如果看到类似这样的输出，这一步就完成了：

   ```
   Hi USERNAME! You've successfully authenticated, but GitHub does not provide shell access.
   ```

   如果你有多个 GitHub 账号，确认 `USERNAME` 就是你在任务 2 里用的那个 GitHub 账号。

   如果没看到这个输出，把这一节的步骤重做一遍。重做之后还不行，就向助教求助。

## 任务 5：克隆仓库

> 在终端里工作时，终端总有一个*工作目录*，也就是终端当前「正在想着」的那个文件夹。
>
> - `cd` 命令可以用来改变工作目录。
> - `pwd` 命令可以用来打印出工作目录。
>
> 很多终端命令的行为取决于你的工作目录。**在这个任务里，运行命令之前确认自己在正确的工作目录里非常重要。**
>
> 例如，命令 `touch potato.txt` 会在工作目录里新建一个文件 `potato.txt`。如果在错误的目录里运行这个命令，你就会把文件建在错误的文件夹里！

1. 打开文件管理器（例如 macOS 上的「访达」），新建一个名叫 `cs61b` 的空文件夹。你所有的代码都会放在这里。

   `cs61b` 文件夹可以放在任何地方，不过我们建议放在桌面上，免得找不到。
2. 打开终端。用 `cd` 命令进入你的 `cs61b` 文件夹。例如：

   ```
   cd ~/Desktop/cs61b
   ```

   如果不确定怎样用 `cd`，[读一读这份终端指南](https://sp26.datastructur.es/resources/using-terminal)（英文）。
3. 运行这个命令：

   ```
   pwd
   ```

   输出应该以 `cs61b` 结尾（例如 `/home/oski/Desktop/cs61b`）。这说明终端的工作目录是 `cs61b` 文件夹。
4. 在同一个终端里，运行这个命令：

   ```
   git clone git@github.com:Berkeley-CS61B/library-sp26.git
   ```

   如果命令成功，你的 `cs61b` 文件夹里现在应该有一个名叫 `library-sp26` 的子文件夹。可以在终端里运行 `ls`，或者打开文件管理器查看。
5. 在同一个终端里，运行这个命令：

   ```
   ls library-sp26
   ```

   这个命令列出 `library-sp26` 文件夹的内容。输出里应该有这样一些行：

   ```
   algs4.jar
   animated-gif-lib-1.4.jar
   antlr4-runtime-4.11.1.jar
   apiguardian-api-1.1.2.jar
   ```
6. 在同一个终端里，运行这个命令：

   ```
   pwd
   ```

   输出应该以 `cs61b` 结尾（例如 `/home/oski/Desktop/cs61b`）。如果不是，用 `cd` 改变工作目录。
7. 在同一个终端里，运行这个命令，把 12345 换成你的仓库编号（来自任务 2）：

   ```
   git clone git@github.com:Berkeley-CS61B-Student/sp26-s12345.git
   ```

   如果命令成功，你的 `cs61b` 文件夹里现在应该有一个类似 `sp26-s12345` 这样名字的子文件夹。可以在终端里运行 `ls`，或者打开文件管理器查看。

   > 不要多次运行 `git clone` 命令。那会在你的计算机上创建同一个文件夹的多份副本，后面会惹麻烦。
   >
   > 如果你觉得这一步弄乱了，用文件管理器在计算机上搜索名叫 `sp26-s12345` 的文件夹。应该只有一个！

   如果看到类似「warning: You appear to have cloned an empty repository」（警告：你克隆的似乎是一个空仓库）的消息，可以放心忽略。
8. 在同一个终端里（`pwd` 输出的是 `...cs61b`），把工作目录切换到你的文件夹，相应地替换 12345：

   ```
   cd sp26-s12345
   ```
9. 运行这个命令：

   ```
   git remote add skeleton git@github.com:Berkeley-CS61B/skeleton-sp26.git
   ```

   如果看到类似「fatal: not a git repository」（致命错误：不是 Git 仓库）的消息，确认你做了上一步。
10. 运行这个命令：

    ```
    git remote -v
    ```

    确认看到类似这样的 4 行输出：

    ```
    origin      git@github.com:Berkeley-CS61B-Student/sp26-s12345.git (fetch)
    origin      git@github.com:Berkeley-CS61B-Student/sp26-s12345.git (push)
    skeleton    git@github.com:Berkeley-CS61B/skeleton-sp26.git (fetch)
    skeleton    git@github.com:Berkeley-CS61B/skeleton-sp26.git (push)
    ```
11. 运行这个命令：

    ```
    git pull skeleton main
    ```

    如果命令成功，你的 `sp26-s12345` 文件夹里现在应该有一个名叫 `hw01` 的子文件夹。可以在终端里运行 `ls`，或者打开文件管理器查看。

    如果看到「fatal: refusing to merge unrelated histories」（致命错误：拒绝合并不相关的历史），改为运行 `git pull skeleton main --allow-unrelated-histories --no-rebase`。
12. 运行这个命令：

    ```
    git branch -M main
    ```
13. 到这一步，你的 `cs61b` 文件夹应该是下面这样的结构。在终端里用 `ls` 或者用文件管理器，确认你的文件夹结构和它一致。

    ```
    cs61b
    ├── library-sp26
    │   ├── algs4.jar
    │   ├── animated-gif-lib-1.4.jar
    │   ├── antlr4-runtime-4.11.1.jar
    │   ├── apiguardian-api-1.1.2.jar
    │   └── ...
    ├── sp26-s12345
    │   ├── hw01
    │   │   ├── src
    │   │   │   └── Arithmetic.java
    │   │   ├── tests
    │   │   │   └── ArithmeticTest.java
    ```

    我们不希望这两个文件夹互相嵌套！`library-sp26` *不应该*在 `sp26-s12345` 里面，反过来也一样。如果文件夹嵌套了，用文件管理器改过来。

## 任务 9：提交你的作业

1. 打开终端，用 `cd` 进入你的 `sp26-s12345` 文件夹。
2. 运行这个命令：

   ```
   git status
   ```

   输出会告诉你有没有还没同步的改动：

   ![git status](https://sp26.datastructur.es/assets/homeworks/hw01/9-git-status.webp)

   这说明你对 `Arithmetic.java` 的修改在你本地的计算机上，但还不在 GitHub 上。
3. 运行这些命令，把你的改动从本地计算机同步到 GitHub。

   让 Git 跟踪 `Arithmetic.java` 文件：

   ```
   git add hw01/src/Arithmetic.java
   ```

   给你的改动拍一个快照：

   ```
   git commit -m "fixed Arithmetic.java in hw01"
   ```

   把这个快照从你的计算机发送到 GitHub：

   ```
   git push origin main
   ```

   以后的作业里，可以把第一个命令里的 `hw01/src/Arithmetic.java` 换掉，添加别的文件。也可以把第二个命令引号里的说明换掉，描述你做的改动。
4. 现在可以再运行一次 `git status`，它应该显示「Your branch is up to date with 'origin/main.'」（你的分支已经和 origin/main 同步）。这说明你的改动已经同步了。

   你也可以打开 [https://github.com/Berkeley-CS61B-Student/sp26-s12345](https://github.com/Berkeley-CS61B-Student/sp26-s12345)，应该能看到你的改动已经同步到了 GitHub 上！
5. 打开 [https://gradescope.com](https://gradescope.com)，点击 CS 61B，再点击 Homework 1 这份作业。

   选择 GitHub，然后选你的 `sp26-s12345` 仓库和 `main` 分支，提交作业。

   如果看不到这个仓库，可能需要 [把你的 GitHub 账号关联到 Gradescope](https://guides.gradescope.com/hc/en-us/articles/21587275611533-Linking-and-Unlinking-Accounts)（英文）。

## 附录：常见问题

**问：怎样配置第二台计算机或者一台新计算机？**

配置第二台计算机需要在第二台计算机上重做任务 1、3、4、5、6、7。

你需要让两台计算机上的两个仓库保持同步：在计算机 1 上运行 `git push origin main`（把更新从计算机 1 发送到 GitHub），在计算机 2 上运行 `git pull origin main`（从 GitHub 下载更新）。
