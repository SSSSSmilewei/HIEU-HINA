## CBTF 规定

如果还没有看过，请务必浏览 [RTL 的 CBTF 页面](https://rtl.berkeley.edu/services-programs/computer-based-testing-facility-cbtf)了解 CBTF 的政策和流程（下面也提供了简要版），并浏览 [Getting Started for Students（学生入门）页面](https://rtl.berkeley.edu/services-programs/computer-based-testing-facility-cbtf/cbtf-student-information/cbtf-getting-started)了解参加期中考试 1 之前你这边需要完成哪些准备。

- 考试期间不允许使用任何未经授权的设备（智能手机、智能手表等）。
- 监考人员会监控 CBTF，发现任何学术不诚信（Academic Dishonesty）行为都会直接报告课程教工。
- CBTF 的监考人员在考试期间不能回答任何与考试内容有关的问题。
- 请务必提前 10 分钟到达你预约的场次，按时完成签到。另外提醒：考试从场次标明的时间准时开始（不是 BERKELEYTIME）。

**本站补充**：BERKELEYTIME（「伯克利时间」）是伯克利的惯例，校内活动通常比标称时间晚几分钟开始；考试不遵循这个惯例，请按场次时间准时到场。

### Save & Grade（保存并评分）

这会提交你的代码，并用我们的测试套件（即自动评分器，autograder）运行、评分。

你的第一次计分提交不扣分；但之后每一次尝试，都会把你可能拿到的最高分扣掉**你这次所丢分数的 25%**。

> 我们再次强烈建议：用测试文件和你自己写的测试，在本地充分测试你的代码。
>
> 这是为了鼓励你在提交之前先自己测试代码，因为在这门课之外的现实世界里，别人不一定会提供检查你代码的测试。

下面是一段说明评分方式如何运作的摘录。你不需要弄懂它的原理，只看这段说明末尾的「太长不看」总结（TL;DR）即可：

> **公式**
>
> $$m_{k+1} = m_k - [(100 - x_k) * 0.25], \quad m_1 = 100$$
>
> 这里 $k$ 表示提交的次数（例如第一次提交就是提交 1，即 $k = 1$），$x_k$ 表示第 $k$ 次提交的得分，$m_k$ 表示第 $k$ 次提交可能拿到的最高分。这些量都以百分比计。
>
> **译注**：原文这段有两处问题：公式里 `0.25)` 后多了一个右括号（原文为 `[(100 - x_k) * 0.25)]`），译文已改正；对 $x_k$ 的定义原文写的是「前 $k$ 次提交的最高分」，与其后的例子矛盾（例子里 $x_1$、$x_2$ 都是那一次提交本身的得分），译文按例子的含义翻译。
>
> **例 1**：如果你总共提交了两次计分提交，第一次得分 $x_1 = 50\%$，那么第二次提交你能拿到的最高分 $m_2$ 是：
>
> $$m_2 = 100\% - [(100\% - 50\%) * 0.25] = 87.5\%$$
>
> **例 2**：如果第一次提交得分 $x_1 = 95\%$，那么第二次提交你能拿到的最高分 $m_2$ 是：
>
> $$m_2 = 100\% - [(100\% - 95\%) * 0.25] = 98.75\%$$
>
> 进一步，如果第二次提交又得到 $x_2 = 95\%$，那么第三次提交你能拿到的最高分是：
>
> $$m_3 = 98.75\% - [(100\% - 95\%) * 0.25] = 97.5\%$$
>
> 最后，如果第三次提交得到满分 $x_3 = 100\%$，你的最终分数就是 $m_3 = 97.5\%$——这是你第三次提交所能拿到的最高分。
>
> 由于你的可能最高分随每次提交丢掉的分数按比例递减，得分越高的提交，使你的可能最高分下降得越少。
>
> **太长不看版（TL;DR）**
>
> 每次提交都尽量拿高分。

如果还没有打开工作区就提交代码评分，这次提交不会计分，而是会显示下面这样的错误页面。你自己的代码有编译错误、或运行自动评分器测试出错时，也会出现这种情况。如果发生了，修好之后重试即可。

> 我们用来给你评分的测试是**隐藏测试**（hidden test）：你看不到测试的内容。期中考试也会使用隐藏测试。
>
> 同样，这是为了鼓励你写自己的本地测试，也是为了保证你不会针对测试套件硬编码（hardcode）。但要注意：本地测试全部通过，并不能保证你在隐藏测试上也拿到满分。

如果你没有拿到满分，你会看到哪些测试没有通过，以及你的部分得分。有时测试的名字能提示你代码没通过的是哪种情况，但不一定总是这样。

默认情况下，在 VS Code 里单击文件只会*预览*（preview）该文件，而不是完整打开它；也就是说，点击其他文件时会复用同一个标签页。这一点可以从标签页里文件名显示为斜体看出来。双击文件才会打开它。也可以双击正在预览的文件的文件名来打开它。

**调试器**

VS Code 也有自己的调试器，功能和你用过的 IntelliJ 调试器类似。

例如，你可以在编辑器里点击行号旁边的行号槽（gutter）来设置断点。然后右键点击测试旁边的绿色播放按钮，选择 `Debug Test`（调试测试），像在 IntelliJ 里那样调试它们。你会看到一个导航条弹出来，上面的符号对应 `Continue`（继续）、`Step Over`（单步跳过）、`Step Into`（单步进入）、`Step Out`（单步跳出）、`Restart`（重启）和 `Stop`（停止）。
