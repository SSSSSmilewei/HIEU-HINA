## 任务 1：主菜单

在项目 5B 里，用户运行 `Main.java` 的 `main` 方法时，会看到一个世界弹出来。现在我们要把它改成一个漂亮的菜单。

实现一个满足下面各项要求的主菜单。

现在，用户运行 `Main.main` 时，应该看到主菜单文字弹出来，像这样：

![Main menu with title CS 61B: The Game, and options New Game (N), Load Game (L), and Quit (Q).](https://sp26.datastructur.es/assets/projects/proj5c/1-main-menu.webp)

菜单应给用户以下选项：

- 在主菜单上按 `N` 或 `n`，创建一局新游戏。
- 在主菜单上按 `L` 或 `l`，从存档文件加载已保存的游戏。
- 在主菜单上按 `Q` 或 `q`，关闭窗口。关闭窗口用 `System.exit(0)`。

用户应能用键盘上对应的按键选择选项。

注意，按键不区分大小写。用户按 `N` 或 `n`，行为应该相同（都创建新游戏）。

除上述要求外，这个菜单的外观随你定制。

如果用户按 `N` 或 `n`，应出现一个新界面，让用户输入种子，像这样：

![Enter Seed menu, with user typing a numerical seed.](https://sp26.datastructur.es/assets/projects/proj5c/enter-seed.gif)

这个界面应把用户到目前为止输入的值显示出来。换句话说，用户每敲一个数字，这个数字都应立刻出现在屏幕上（跟在已输入的其他数字后面）。

用户输完种子后，应能按 `S` 或 `s` 开始游戏。你应显示一个由用户的种子生成的世界。

同样，除上述要求外，这个界面的外观随你定制。

下面是一些你*不需要*支持的情形（除非你想做）。这些情形下的行为是*未定义的（undefined）*，也就是说，这些情况下你的代码做什么都行（例如崩溃、显示错误或其他任何行为）。

- 用户输入超出范围 [0, 9223372036854775807] 的种子是未定义的。这个范围就是 Java 中 `long` 基本类型能表示的值。
- 用户在种子界面敲不允许的字符（即 `0123456789sS` 之外的任何字符）是未定义的。例如，用户在种子界面按退格、敲逗号、敲 `Q` 或其他字母，都是未定义的。

## 任务 2：交互

接下来，让用户能操纵一个头像（avatar）在世界里移动。

实现一个满足下面各项要求的头像。

用户开始游戏时，你生成的世界里还应额外包含一个*头像*瓦片，代表用户。在下图的例子里，`@` 瓦片就是头像。你的头像可以长得不一样，只要有一个清楚唯一的头像即可。

![World with a single avatar.](https://sp26.datastructur.es/assets/projects/proj5c/2-avatar.webp)

头像可以出生在任何地板方格上。出生方格不必随机选择，例如可以永远是最靠左下的地板方格。但出生方格必须是确定的，例如两次输入同一个种子，头像应出现在同一个方格。更多细节见下面「确定性」一节。

用户应能这样操纵头像在世界里移动：

- `W` 或 `w` 将头像向上移动一格。
- `A` 或 `a` 将头像向左移动一格。
- `S` 或 `s` 将头像向下移动一格。
- `D` 或 `d` 将头像向右移动一格。

如果用户试图走进墙里，头像应留在原地，程序不应崩溃。例如，在上面那个示例世界里，按一次 `W` 或 `w` 头像会向上移动；再按一次 `W` 或 `w`，头像就不应再动。

你不需要支持按住按键不放。按住一个键导致未定义行为也可以接受。

在项目后期，你可以随意添加更多玩法。例如，可以加一个道具，让用户能穿墙或一次移动多格；或者加一个额外的键 `P` 用来推东西。添加别的功能都可以，只要遵循这里交互的基本精神：用户能四处移动，但受墙的限制。

### 总览：给游戏加上动画

要给游戏加上动画，你需要不断重新渲染游戏状态的更新。更新内容取决于你所在的场景。可以把这个过程理解成一个「游戏循环」（game loop）。你的世界移动场景大致可以用下面这个游戏循环来刻画：

1. 初始化游戏窗口和世界状态。
2. 根据玩家的输入更新头像的移动。
3. 把更新后的游戏状态渲染到游戏窗口。
4. 重复第 2、3 步，直到玩家退出。

看看你项目 5 仓库 `demo` 文件夹里的 `GameLoopDemo.java`，那里有一个这样的例子。

一般来说，好的编程习惯是先写出职责明确的小过程，再用这些基本单元组合出更复杂的方法。这会让你的开发有一条清晰的前进路径，也更容易拆分逻辑做单元测试。

### 总览：确定性

你的游戏必须是**确定的（deterministic）**。也就是说，如果两个用户以完全相同的顺序按下完全相同的按键，他们游戏的最终状态必须完全相同。例如，二维瓦片网格必须完全相同，你添加的其他东西（分数、血条等）也必须完全相同。

回忆一下，我们已经用伪随机性让「新游戏」的过程变得确定了：两个用户输入同一个种子，就会得到完全相同的世界。

从现在起，你添加的功能会越来越多，请确保游戏仍然是确定的。你仍然可以用伪随机性来帮助你保证确定性。

**关于实时玩法的说明：**

要得到确定的行为，最简单的办法是让游戏不依赖真实时间。一些非实时行为的例子：

- 用户飞快地或缓慢地按下同一串按键，结果的行为应该完全相同。
- 如果你有倒计时计时器之类的功能，计时应按移动次数计量（例如用户每移动一次就减一），而不是按秒数这样的真实时间计量。
- 如果你有敌人生成之类的功能，可以每移动 5 次生成一个敌人，而不是每 5 秒这样按真实时间来。

如果你确实想实现实时行为，也可以，只要任何人都能轻松地用同样的按键序列复现确定的行为就行。例如，让用户在 10 秒倒计时内按一个键是可以的、可复现的；让用户在 0.1 秒内按 20 个键就难以稳定复现了。

## 任务 3：HUD

添加一个「平视显示器」（Heads-up Display，HUD），向用户提供可能有用的额外信息。

> 实现满足下面各项要求的 HUD 功能。

至少，它应包含一段文字，描述当前鼠标指针指向的瓦片。理想情况下，鼠标移动时 HUD 不应闪烁。HUD 必须随着鼠标光标的移动而更新，也就是说，即使用户只是在移动鼠标、没有按任何键，你也必须更新显示。

> 关于怎么做，我们建议两件事：

1. 修改你的代码，在世界顶部留出一小块空白放 HUD。
2. 研究一下 `StdDraw.textLeft(x, y, text)` 函数，它在给定的 `x`、`y` 位置绘制给定的 `text`。类似地还有 `textRight` 和 `text` 两个函数，输入相同，只是分别让 `text` 的右端和中心对齐到给定的 `x`、`y` 位置。

## 任务 4：保存与加载

假设用户正在玩你的游戏，但要休息一下。（也许是要去上 CS 61B 的课？）我们给用户一种保存进度、之后读回游戏的办法。

实现满足下面各项要求的保存与加载功能。

我们知道还没怎么教过保存和加载，所以我们提供了一个演示文件，展示如何保存 / 加载数据。为了完成项目，你可以按需复制其中的代码。

看看你 `demo` 文件夹里的 `ExampleSaveLoad.java` 文件，确保你能看懂它。

下面是保存和加载过程的视频演示：

视频：<https://www.youtube.com/embed/Q8-FKMLYVwk?si=TYxKvHCL4sCQHaeF>

用户在「世界模式」（看着二维世界，而不是主菜单）时，应能按 `:q` 或 `:Q` 立即保存游戏并退出程序。退出程序用 `System.exit(0)`。注意，单按 `q`、`Q` 或 `:` 都不应结束游戏。

用户退出程序时，所有 Java 变量都会丢失。因此，你需要把用户的进度存进一个文件，比如 `save.txt`。`save.txt` 里放什么由你决定，但其中的信息必须足以在之后完整重建用户的游戏。

关于按键的几点说明：

- 在「世界模式」按 `:Q` 或 `:q` 应立即保存并退出，不需要再按其他键来完成。例如，不要在退出前询问用户是否确定。
- 在「菜单模式」（看着主菜单）时，单按 `Q` 应退出程序，不保存任何东西。

如果用户在主菜单上按 `L` 或 `l`，你应从 `save.txt` 文件加载最近保存的世界。世界从未被保存过时能不能加载，我们不会测试。

加载出来的世界应和用户退出游戏前处于完全相同的状态。例如，下面两种操作序列应得到完全相同的世界：

- 用户输入 `N999SDDDWWW`（新游戏、种子 999、开始、右移 3 次、上移 3 次）。
- 用户输入 `N999SDDD:Q`（新游戏、种子 999、开始、右移 3 次、保存）。然后用户重新启动程序，输入 `LWWW`（加载、上移 3 次）。

加载出来的世界应完全一致，连随机数生成器的状态也要一致！

下面是一些未定义行为的情形。记住，未定义行为意味着你的代码可以崩溃、显示错误或做任何别的事情。我们不会测试这些情形。

- 如果之前没有存档，用户在主菜单上按 `L` 或 `l`，行为未定义。
- 如果用户用其他方式退出程序（例如退出 IntelliJ，或者拔掉计算机的电源），行为未定义。这种情况你不需要保存任何东西。

## 任务 5：寻路

现在，除了用键盘（WASD）移动，我们再加一种移动方式：点击一个瓦片来移动。

按下面列出的要求实现寻路。

- 用户点击一个瓦片时，画出一条通向该点的清晰可辨的路径。注意，这条路径只能经过地板或其他可通行的瓦片，并且必须是**可能的最短路径**。最短路径可能 / 必将不止一条，任何一条最短路径都算合格。

- 用户再点一次该瓦片时，让头像沿这条路径动画移动，直到到达目标。
