# 课程制作标准

> 给往站里写课程内容的人和 AI 看。写一门课之前先读完这份文档，交付前按第八节的验收清单逐项检查。
>
> 依据：
> - 《一门好课的组成：课程包 checklist》（负责人整理，对照 csdiy.wiki 的课程清单和约 19 门课的官网）。
> - 站内已经做好的 CS50x（`content/courses/cs50x/`）。
> - 2026-11 CS61A、CS61B、CS61C 第一版的教训（见附录）。

## 一、什么叫「做完了」

**学生点开任何一个条目，都能在站内学完它，不需要跳到外站才知道要做什么。**

只有目录和外链的课叫「导学」，不叫「站内课」，不能说成「完整的课程」。现在站里 118 门课大多是导学；做站内课，就要做到 CS50x 的水准：

| CS50x 的做法 | 说明 |
|---|---|
| 讲义 | 官方讲义整讲翻译进站，每讲约 3 万字节 |
| 习题集 | 官方题目说明整篇翻译进站，每道题一页 |
| 练手题 | 一共 176 道，其中 54 道从官方习题改编 |
| 视频 | 每讲都有官方视频和哔哩哔哩中文字幕视频 |
| 许可 | `license` 写清原作者、许可协议和译者 |

## 二、一门好课由什么组成

一套好课 = 固定的每周节奏 + 每个知识点都有带反馈的练习 + 一个逐步长大的产物 + 验证机制 + 支撑设施 + 可见的阶段成果。

下表把 checklist 的每一项对应到课程包（`hiana-course@1`）里的位置。

| checklist 里的一项 | 放在课程包的哪里 | 要求 |
|---|---|---|
| 元信息卡：先修、语言、难度、学时、资源汇总 | 基本信息字段、`intro`、`links` | 学时按实际条目估算，和 `periods` 合计对得上 |
| 环境和工具上手、整门课的「生存指南」 | 第一个模块「开始之前」，`reading` 条目 | 写清版本、学习顺序、环境配置、自学者怎样测评、外链打不开时怎么办 |
| 每周节奏（schedule） | `modules` 按周或单元排列，必要时用 `group` 再分一层 | 和官方课表的顺序一致 |
| 每讲内容包：讲义、视频、幻灯片、阅读、示例代码 | `lecture` 条目：`pages` 放讲义正文，`videos` 放视频，`links` 放幻灯片、阅读、示例代码 | 讲义是官方正文的翻译（见第四节），不是自己写的提纲 |
| 小练习：每周的 lab、homework | `lab`、`assignment` 条目：`pages` 放题目说明，`practice` 放练手题，`submit` 放正式提交地址 | 题目说明翻译进站，每道题能单独打开 |
| 讨论课 worksheet（带解答、考试风格） | `section` 条目，题目改编成 `practice`，解答写进 `explain` | 可以标 `optional`，但不能只有一个外链 |
| 大项目，拆成 A、B、C 小段 | 每一段一个 `project` 条目，各有一页说明 | 写清每段的目标、检查点和本地测试方法 |
| 贯穿的产物（教学专用系统、起始代码） | 项目页里写清怎样取得起始代码、怎样在本地跑测试 | 自学者拿不到在线评测时，要给出替代办法 |
| 评测与验证：quiz、期中、期末、往年考试 | `quiz`、`exam` 条目：往年试题链接 + 改编题 | 注明哪些官方只对校内开放 |
| 拔高层：竞赛、附加题、自由选题 | 标 `optional` 的条目 | 不计入必学课时 |
| 阶段成果 | 每个单元结尾安排一个看得见的成果（通常是项目） | 站内进度和热力图会记录；证书目前没有 |

## 三、按课程类型取舍

| 类型 | 必须有 | 可以省 |
|---|---|---|
| 入门类（CS50x、Missing Semester） | 每周内容包、小练习、环境上手、最终项目 | 重型大项目、考试 |
| 程序设计类（CS61A、CS61B） | 每周内容包、实验和作业、拆段的项目、讨论课题目、往年考试 | — |
| 系统类（CS61C、CSAPP、6.S081、CS144、15-445） | 教学系统、拆段大项目、本地测试、常见问题 | 讨论课 worksheet |
| 理论类（CS70） | 讲义、带解答的习题、高频小测、理论到应用的对应 | 代码项目 |
| 机器学习与视觉类（CS231n、10-414） | notebook 和起始代码、评分方法、最终项目 | 自研操作系统类教学系统 |

## 四、内容从哪里来

### 优先顺序

1. **官方正文的翻译**：讲义、教材、题目说明。
2. **从官方题目改编**：练手题、讨论课题目、往年考试题。`origin` 填 `official`。
3. **自己编写**：只在官方没有对应内容时才用，`origin` 填 `review`。自编内容不能冒充官方内容，也不能用来填补「拿不到」的空缺。

### 许可

- 翻译进站之前先查许可，结论写进 `license`，格式照 CS50x：「讲义与习题 © 原作者，许可协议；中文翻译 海纳协会，同协议」。
- 许可不允许搬运的，只放链接，并在学习指南里说明。
- 官方要求不公开答案的（例如部分课程的作业答案），站内不放答案。

### 学期

- 用**最新的、已经结束的**学期。正在进行的学期材料不全，后几周的内容还没发布。
- 官网每学期会覆盖旧内容，链接要指向这一学期的存档地址，并在学习指南里写明是哪个学期。

### 外链能不能打开

- 国内经常打不开 YouTube、GitHub Pages。视频优先配哔哩哔哩的中文字幕版本，官方原版作为第二个链接。
- 正文已经翻译进站的条目，外链只是补充，打不开也不影响学习。

## 五、练手题

- **每个讲座条目、实验条目、作业条目都要有练手题**，题目和这一讲的具体内容对应，不出「这一讲在课程中的定位是什么」这类空洞的题。
- 每道题都写 `explain`，说明为什么。
- 站内能判的题型：选择、填空、代码（Python、SQL、JavaScript）。
  - Python、SQL 的课：把官方的「程序会输出什么」题改编成选择或填空，把官方编程题改编成代码题。
  - Java、C、汇编等站内判不了的语言：从官方教材习题、讨论课题目改编成选择和填空；编程部分写进题目说明，用官方起始代码在本地测试。
- 代码题的预期输出必须用参考答案实际运行得出，不能手写。

## 六、制作流程

1. **调研**：列出这门课的官方材料清单——每一项能不能取到、许可是什么、预计工作量多少。
2. **先告诉负责人**：调研结果和计划先报给负责人。资料拿不到、或者达不到本标准的部分，明说缺什么、打算怎么办，**不要用自编内容悄悄凑数**。
3. **先做样板**：一门新课先做一个单元（或第一门课先做完整一门），给负责人看过再铺开。
4. **生成脚本进仓库**：用脚本批量生成的，脚本放进 `scripts/`，写明数据来源，换学期能重跑。
5. **自查**：按第八节的验收清单检查，并在浏览器里实际打开几个条目看。

## 七、诚实地描述交付结果

- 汇报时给出实际数字：多少条目有站内正文、多少只有外链、多少题是官方改编。
- 哪些内容是猜的、没核对过的、自编的，逐条说清。
- AGENTS.md 里的记录要和实际一致，不写「完整」「全文」这类夸大的词。

## 八、验收清单

**内容**

- [ ] 第一个条目是学习指南，写明学期、学习顺序、环境配置、自学测评方法、外链打不开的替代办法
- [ ] 每个讲座条目都有站内讲义正文（官方正文的翻译），篇幅与官方讲义相当
- [ ] 每个实验、作业、项目条目都有站内题目说明
- [ ] 大项目按官方的阶段拆成多个条目
- [ ] 每讲都有国内能打开的视频
- [ ] 没有「只有一个外链」的必学条目

**练手题**

- [ ] 每个讲座、实验、作业条目都有练手题，且和具体内容对应
- [ ] 官方有题目的，优先从官方改编，`origin` 标注正确
- [ ] 每道题都有 `explain`
- [ ] 代码题的预期输出由参考答案运行得出

**来源与许可**

- [ ] `license` 写清原作者、许可协议和译者
- [ ] 用的是最新的、已经结束的学期，链接指向存档地址
- [ ] 没有把猜测的内容当作官方内容

**技术检查**

- [ ] 课程包通过校验（`parsePackage`）
- [ ] `npm test`、`npx tsc --noEmit -p .`、`npm run build` 通过
- [ ] 在浏览器里打开过课程页、讲义页、练手题，深色模式和手机宽度都看过

## 附录：反例——CS61A、CS61B、CS61C 第一版（2026-11-17）

第一版没有达到本标准，负责人看过后判定「完全不行」。数据如下：

| | CS50x（标准） | CS61A | CS61B | CS61C |
|---|---|---|---|---|
| 每讲正文篇幅（中位数） | 约 3 万字节 | 约 650 字节 | 约 780 字节 | 约 830 字节 |
| 只有外链、没有站内正文的条目 | 0 / 23 | 40 / 83 | 20 / 60 | 36 / 80 |
| 没有视频的讲座 | 0 / 12 | 4 / 38 | 39 / 39 | 40 / 40 |
| 从官方题目改编的练手题 | 54 / 176 | 10 / 81 | 0 / 75 | 0 / 76 |

出错的原因：

1. 把「写进系统」理解成「搭出完整的目录」，开工前没有拿 CS50x 定下「做完」的标准，追求的是条目数量。
2. 官网打不开、资料取不到时，用自己写的提纲、按文件名猜的标题、外链填空，没有先告诉负责人。
3. CS61B、CS61C 用了正在进行的学期，材料不全。
4. 三门课一起铺开，没有先做一门样板确认。
5. 交付前没有在浏览器里检查。
