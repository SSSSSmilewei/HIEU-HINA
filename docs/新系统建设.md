## 一、负责人的想法（2026-11-24，原话整理）

### 1. 站内看视频
- 视频在系统里直接看，接 B 站视频源，或其他视频源都可以。
- 看视频的同时，可以在下面（同屏）看课堂教材。
- 与已有结论一致：视频嵌入外站，不自托管。

### 2. 笔记与语音输入
- 看视频时随时可以记笔记；在教材里记的笔记也一样。
- 笔记可以用语音输入。
- 语音输入、整理这些事情交给 AI：不是本地 AI，是接 API，做成系统里的 AI 模块，通过接各种接口来实现这些功能。

### 3. 作业：不要刷题，要 coding 界面 + 自己的仓库
- 负责人明确否定现有模式：「我并不希望把系统做成学习通那种刷题的感觉，更何况现在所谓的刷题内容也很差。」
- 看完一节视频课 / 做完作业后，进入类似 LeetCode、头歌（Educoder）的 coding 界面学习；界面里还要有 Codédex（https://www.codedex.io，像素风闯关带学代码）那种元素。
- 做题内容直接用课程官方作业，比如 CS61A 的 Python 作业，在这个界面里完成。
- **补充（2026-11-25，负责人确认）**：作业不限于官方。官方有作业的课优先用官方作业；官方没有作业，或者官方作业不适合在系统里完成的，由我们自己编写，同样配测试用例，同样写进学生自己的仓库。
- **界面本质是 IDE，但能看到独属于学生自己的仓库**：做题时只是定位到仓库里的某个文件夹；要让同学有「我在自己的仓库里工作」的概念，因为做完题后，代码最终要化成仓库的一部分。做题过程只是内嵌进了系统。

### 4. 两个附加点
- **VSCode 插件**：把系统做成 VSCode 插件，在本地直接管理这些东西。需要很细化才能做好，先记方向。
- **游戏化界面交互**：做一套像 Codédex 那样的游戏界面，用纯粹的游戏交互完成学习。**不是以课程为模块化，而是以纯粹的游戏界面来模块化**，有点像力扣的闯关模式。

## 二、AI 描述的想象（2026-11-25，负责人已看过，未逐条确认）

### 一个学生的一节课

他打开系统，进入的不是课程目录，而是一张地图——一片还没点亮的区域。今天的位置在 CS61A 的某一关。点进去是一间「学习间」：左边播这一讲的视频（B 站源，站内播放），右边或下方是这一讲的教材。没懂的地方不用切出去找笔记软件，直接按住说话，语音变成文字，AI 整理成通顺的话，钉在教材那一段上——既是笔记，也是以后复习的路标。视频讲到某个例子，教材翻到对应位置。

看完这一讲，点「动手做」，进入作业台。

### 作业台：不是在做题，是在自己的仓库里干活

界面是正经编辑器，像 LeetCode 那样左边题目右边代码，但有本质区别：**能看到自己的文件树**。`hw03.py` 就在那儿，属于他自己的仓库，系统只是把他带到这个文件夹、这个函数面前。写完运行，测试用例（官方作业改编，或者我们自己编写）跑起来，红了改，绿了过。AI 不判对错，只在卡住时给分级提示、写评语。

他清楚知道：这份代码不是交上去就消失的答卷，它留在自己的仓库里。这门课的关卡一关一关过，文件一个一个补齐，Hog 项目十关全部点亮时，手里就是一个完整的、能跑的、属于自己的项目仓库。想更进一步，还可以顺着引导交到课程官方拿证书。

**地图上的每一关，就是仓库里真实存在的一步。** 地图让他看见走了多远，仓库让他看见做出了什么。

### 它不像谁

- 不像学习通：没有刷选择题这回事，每一关都在往真实项目里添代码。
- 不像力扣：题与题不孤立，做完三十关不是三十个散文件，而是一个项目。
- 不像 Codédex：借它的地图、经验值、徽章、一关几分钟的节奏，但底下垫的是 CS50x、CS61A 的真正作业（官方没有作业的课，由我们自己编写），判题靠测试用例，不靠 AI 说了算。

### 再往后的样子

VSCode 插件是给「长出本事」的同学准备的：在本地用自己的编辑器写，push 上去，系统里那一关照样点亮。从系统内写到本地写是一条自然的路，不是两套系统。

AI 在底层是统一模块：今天整理语音笔记，明天写作业评语，以后还可以做更多，但始终守一条线——**测试判对错，AI 管表达。**

### 核心理念

**同学离开时带走的不是积分和完成率，而是一个他自己写出来的仓库。**

## 三、现有基础和已有结论（新 agent 先读这些）

- **Forgejo**：已定为自建 Git 服务（灵感备忘录第五节，2026-11-19 定），维护轻、适合换届。个人作业仓库正好承载「我的仓库」。账号权限按团队分可写 / 只读，关闭自助注册。
- **学校服务器**：多半只在校园网、无公网 IP 和域名、可装 Docker、寒暑假不断电但不能访问外网。外网访问的几种办法见灵感备忘录。服务器申请的资源配置表见灵感备忘录第七节第 8 条。
- **浏览器判题已有**：Python（Pyodide）、SQL（sql.js）、JavaScript，做对记进热力图。可支撑 Python 作业的起步。
- **课程内容已有**：CS50x、Missing Semester 站内全文；CS61A/B/C、MIT 18.01、MIT 线性代数已按 `docs/课程制作标准.md` 重做（讲义中文翻译 + 官方作业改编练手题，未经人工逐页核对）。CS61A Hog 项目官方已分 10 个问题，适合做第一个样板（灵感备忘录第八节）。
- **Codédex 调研结论**（`docs/调研-Codedex.md`）：它的练习互相独立、判题靠正则 + AI 不严格、内容浅、证书自己发、要付费；我们学机制（关卡颗粒度、章的节奏、徽章、支线），不照搬画面和课程内容（有版权），文案保持正式书面语。
- **蓝色钉子 · 标记**：已经是钉在讲义段落上的私有 / 公开笔记，新「笔记」功能要考虑复用还是分开。
- **AI 现状**：只用于蓝色钉子「请 AI 回答」，智谱 GLM-4-Flash，`AI_API_KEY` 还没在 Cloudflare 填。
- **OJ（Hydro）企划**：灵感备忘录第七节有 12 月上线的时间表；但负责人的新想法倾向判题做在课程作业界面里，Hydro 可缓一缓或只用来办比赛——**12 月企划要不要照旧，需要重新确认。**
