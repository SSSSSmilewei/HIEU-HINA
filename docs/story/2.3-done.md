# Story 2.3 — VSCode 插件

## 主要目标
在自己电脑上用 VSCode 写作业，提交到同一个仓库和 OJ。

## 验收标准
- [x] `vscode/` 目录：插件源码；命令：登录、克隆我的课程仓库、运行公开测试、提交到 OJ、查看结果
- [x] 提交 = git commit + push + 调平台提交接口，结果在 VSCode 面板显示
- [x] 打包成 `.vsix`，平台「仓库」页提供下载

## 功能要点
- 登录用平台签发的个人令牌（可在平台撤销）

## 单元测试用例设计
- 令牌存储、接口封装

## 行为测试用例设计
- 本地装 .vsix，克隆仓库，改代码提交，平台提交记录出现这次提交

## 完成记录（2026-11-28）
- 个人令牌：表 `api_tokens`（迁移 v21，只存 SHA-256）；接口 `src/worker/api/tokens.ts`（`GET/POST /api/tokens`、`DELETE /api/tokens/:id`），每人最多同时 10 个。
  - 令牌以 `hnp_` 开头，用 `Authorization: Bearer` 发。只放行 `GET /api/auth/me`、`POST /api/oj/run|submit`、`GET /api/oj/submissions|solved`、`GET /api/git/repos…`；其余接口（改密码、签到、签发令牌、改仓库可见范围、设 Git 密码）一律当作没登录。
  - 签发时记下账号的 `session_version`：改密码、重置密码以后旧令牌和其他设备的登录一起失效。
- 插件 `vscode/`（`src/core.ts` 和 VSCode 无关，可单测；`src/extension.ts` 是命令）：
  - 命令：登录、退出登录、克隆我的课程仓库、运行公开测试、提交到 OJ、查看提交记录、在平台上打开这道题；编辑器右上角有「运行」「提交」按钮，状态栏有操作菜单。
  - 按文件在仓库里的路径和作业的 `repoDir` 找到作业（`/oj/index.json` 加了 `repoDir` 字段，只加不改）；一个文件对应几道题时让人选，并记住上次的选择。预测输出、环境图要逐空作答，提示到网页做。
  - 提交顺序：保存 → 拉取 → `git add` 要交的文件 → 有改动就 commit → push → 调 `/api/oj/submit` → 再拉取一次（平台可能更新了 README）。git 操作用 VSCode 自带 Git 扩展的接口，账号密码由它弹框询问。
  - 结果排在「HIANA OJ」输出面板：总结果、逐个用例；失败的公开用例给输入、期望、实际和报错，隐藏用例只给结果。
- 打包：`scripts/vsix.mjs` 在构建时用 esbuild 打包插件，再用 Node 自带的 zlib 写成 zip（不用 vsce），输出 `dist/client/downloads/hiana-oj.vsix`（约 9 KB）。不提交二进制文件。
- 平台「我的仓库」页加「VSCode 插件」一节：下载、安装步骤、签发（令牌只显示一次）、列表（末四位、签发时间、最近使用）、撤销。
- 新增开发依赖 `@types/vscode@1.85.0`（只用于类型检查）。
- 测试：`tests/tokens.test.ts`（4 个）、`tests/vscode-core.test.ts`（8 个，含插件客户端用令牌调真实 Worker、zip 结构）。
- 实测：
  - `code --install-extension` 装进一个隔离的 VSCode 配置目录，安装成功（`hiana.hiana-oj@0.1.0`）。
  - 用插件的核心代码对本机平台（8788）+ 判题服务 + Forgejo 走了一遍：令牌登录 → 读题 → 运行（AC 4/4）→ 拉取、commit、push → 提交（AC 4/4）→ 再拉取；仓库里出现「在 VSCode 里提交」的提交，平台提交记录多了一条。
  - **没有做的**：没有在 VSCode 图形界面里逐个点命令（需要装 VSCode 测试框架，在图形环境里跑）。命令里调用 VSCode 接口的部分只做了类型检查，第一次正式使用时请留意。
