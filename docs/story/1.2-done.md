# Story 1.2 — 判题服务 judge/

## 主要目标
独立的判题服务：收到代码和题目编号，在沙箱里跑测试，返回 OJ 式结果。

## 验收标准
- [x] `judge/` 目录：bun + TypeScript 服务，`POST /v1/run`（只跑公开示例）、`POST /v1/submit`（跑全部测试）、`GET /v1/health`
- [x] 令牌鉴权：请求头 `Authorization: Bearer <JUDGE_TOKEN>`，错误令牌回 401
- [x] 沙箱用 go-judge（Docker），`judge/docker-compose.yml` 一键起；限时、限内存、禁网、只读文件系统
- [x] 语言：Python 3、C、C++、Java、SQLite、Scheme（CS61A 官方解释器）
- [x] CS61A ok 测试适配：在沙箱里运行 ok 测试文件（doctest 式和加密的解锁用例），逐用例给结果
- [x] 结果：AC / WA / TLE / MLE / RE / CE / SE，用时、内存、每个用例的输入/期望/实际（隐藏用例只给序号）
- [x] 同一时间判题数有上限，超出排队

## 功能要点
- 题目文件由服务启动时从 `content/oj` 构建产物读取（`dist/oj/`），按题目编号查找
- 学员文件只覆盖「可改」文件，只读文件用题目自带的
- 输出截断到 64 KB，防止刷屏
- 日志不记录学员代码内容

## 单元测试用例设计
- 结果比对：忽略行尾空白、按题可选忽略顺序（SQL）
- ok 用例解析：doctest、`>>>` 多行、加密的期望输出（hmac 比对）
- verdict 汇总规则：第一个非 AC 的用例决定整体结果

## 行为测试用例设计
- 本地起 go-judge 和 judge 服务：Python 正确解 → AC；死循环 → TLE；`import os; os.system` 访问网络失败；语法错 → CE/RE
- C 和 Java 的 a+b 各跑一次 AC
- 错误令牌 401
