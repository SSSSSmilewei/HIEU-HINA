# 第 6 讲：函数抽象

> 本页讲义由海纳协会依据官方幻灯片「Functional Abstraction」整理，不是官方讲义的翻译。教材 Composing Programs 没有与这一讲对应的小节，相关内容可以参考 1.3.6 节「函数作为抽象」和 1.4 节「设计函数」。

## 函数是一种抽象

一个函数有输入，也有输出：

- 可以没有输入，例如只负责打印问候语的函数。
- 也可以没有输出。没有返回值的函数一定是做了别的事情，比如在屏幕上打印、让机器人移动。这些「除了返回值以外的影响」叫做**副作用**（side effect）。

描述一个函数「做什么」的约定，叫做函数的**规格说明**（specification，简称 spec）。

## 规格说明里写什么

一份规格说明通常包括：

| 项目 | 说明 | 以 `double` 为例 |
|---|---|---|
| 名称 | 函数叫什么 | `double` |
| 输入 | 有哪些参数，各是什么类型，有什么要求 | `n`，一个数 |
| 输出 | 返回什么；没有返回值就写「无」 | 输入的两倍 |
| 副作用 | 会不会打印、修改数据等 | 无 |
| 调用示例 | 几个具体的调用和结果 | `double(10)` 返回 `20` |

在 Python 里，规格说明通常写在函数的**文档字符串**（docstring）里，调用示例写成文档测试（doctest）的形式：

```py
def double(n):
    """Return twice n.

    >>> double(10)
    20
    """
```

## 规格说明里**不写**什么

规格说明不写「怎么做」。这正是函数抽象的妙处：它只规定函数要完成什么工作，不规定具体的做法。

以 `double(n)` 为例，下面几种实现都符合同一份规格说明：

- `return n * 2`
- `return n + n`
- 当 `n` 是正整数时，从 0 开始加 `n` 次 1

这给了写函数的人很大的自由：只要满足规格说明，可以自己选择算法，以后也可以换成更快的算法，而调用这个函数的代码一行都不用改。反过来，使用函数的人只需要读规格说明，不需要读函数体。

## 课堂示例：从 10 减到 0 的游戏

课上用一个小游戏演示怎样把问题拆成函数：

- 两名玩家轮流行动，每次可以从当前总数里减去 1 或 2。
- 总数从 10 开始，减到 0 时游戏结束。
- 最后行动的玩家获胜（换句话说，轮到你时已经没法行动，你就输了）。

写这个游戏时，可以先为每个部分写出规格说明，再分别实现：

- 一个**策略**（strategy）是一个函数：输入当前的总数，输出这一步要减去 1 还是 2。
- 一个函数负责让两个策略对弈：输入两个策略，轮流调用它们，返回获胜的一方。
- 不同的策略只要遵守同样的规格说明，就可以互相替换、互相比较。

这个游戏有一个简单的必胜策略：每次都让对手面对一个 3 的倍数。10 不是 3 的倍数，所以先手的玩家只要先减去 1，之后每次让剩下的总数保持为 3 的倍数，就一定能赢。

项目 1 Hog 正是用同样的思路组织的：每个策略是一个函数，游戏主循环只依赖策略的规格说明，而不关心策略内部怎么做决定。

## 小结

- 规格说明 = 名称、输入、输出、副作用、调用示例。
- 规格说明只写「做什么」，不写「怎么做」。
- 先写规格说明和调用示例，再写函数体；写完之后用文档测试检查实现是否符合规格说明。
