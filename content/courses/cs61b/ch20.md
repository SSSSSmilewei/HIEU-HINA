## 20.1 BFS 与 DFS

在第 19.4 节里，我们为图写出了 DFS（深度优先搜索）遍历。在 DFS 中，我们在开始看第二个孩子之前，先把第一个孩子的整支血脉访问完——名副其实地*深度优先*地搜索。

这里，我们来讲 BFS（广度优先搜索，也叫层序遍历）。在 BFS 中，我们先访问所有直接的孩子，再继续访问任何一个孙子。换句话说，先访问离源点 1 条边的所有节点，然后访问离源点 2 条边的所有节点，依此类推。

BFS 的伪代码如下：

```
Initialize the fringe, an empty queue 
    add the starting vertex to the fringe
    mark the starting vertex
    while fringe is not empty:
        remove vertex v from the fringe
        for each neighbor n of vertex v:
            if n is not marked:
                add n to fringe
                mark n
                set edgeTo[n] = v
                set distTo[n] = distTo[v] + 1
```

即：初始化边缘集合 fringe（一个空队列）；把起始顶点加入 fringe 并标记它；只要 fringe 不空，就从中取出一个顶点 v，对 v 的每个邻居 n，如果 n 没被标记，就把 n 加入 fringe、标记 n、设 `edgeTo[n] = v`、设 `distTo[n] = distTo[v] + 1`。

*边缘*（fringe）只是一个术语，指我们用来存放遍历发现过程「前沿」上的节点（即接下来等着要看的节点）的数据结构。对 BFS，我们用队列作为 fringe。

`edgeTo[...]` 是一个映射，帮助我们记录是怎样到达节点 `n` 的：我们是沿着从 `v` 到 `n` 的边到达它的。

`distTo[...]` 是一个映射，帮助我们记录 `n` 离起始顶点有多远。假设每条边的距离都是 `1`，那么到 `n` 的距离就比到 `v` 的距离多一。为什么？我们可以用已知的到达 `v` 的方式，再多花一步，经由 `v` 和 `n` 之间必然存在的那条边到达 `n`（这条边一定存在，因为在 `for` 循环头里，`n` 被定义为 `v` 的邻居）。

### DFS 与 BFS 的比较

**答案 18.1**：DFS 遍历。

</details>

不过要注意，DFS 和 BFS 的区别不只在于 fringe 用的数据结构。它们标记节点的时机也不同。对 DFS，只有在访问一个节点时（也就是把它从 fringe 里弹出时）才标记它。因此，如果一个节点已经入栈但还没被访问，栈里同时可能有这个节点的多个实例。而 BFS 在把节点加入 fringe 时就立即标记，所以不会出现这种情况。

递归的 DFS 通过递归的栈帧自然地实现了这一点；迭代的 DFS 则手动实现：

```
Initialize the fringe, an empty stack
    push the starting vertex on the fringe
    while fringe is not empty:
        pop a vertex off the fringe
        if vertex is not marked:
            mark the vertex
            visit vertex
            for each neighbor of vertex:
                if neighbor not marked:
                    push neighbor to fringe
```

即：初始化 fringe（一个空栈）；把起始顶点压入 fringe；只要 fringe 不空，就弹出一个顶点，如果它没被标记，就标记它、访问它，并把它所有没被标记的邻居压入 fringe。

## 20.2 图的表示

*怎样在 Java 里创建一个图？*

我们会讨论 **API** 的选择，以及用来表示图的**底层数据结构**。我们的决策会对*运行时间*、*内存占用*以及*实现各种图算法的难度*产生深远影响。

### 图的 API

API（Application Programming Interface，应用程序编程接口）是我们的类提供给用户使用的方法列表，包括方法签名（每个函数接收哪些参数）以及关于它们行为的说明。你已经见过 Java 开发者为他们提供的类写的 API，例如 [Deque](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/util/Deque.html)。

对于我们的图 API，采用常见的约定：给每个不同的节点分配一个整数编号。这可以通过维护一个映射来实现，它告诉我们每个原始节点标签对应的整数。这样我们定义的 API 就专门处理整数，而不需要引入泛型。

然后可以这样定义我们的 API：

```
public class Graph {
  public Graph(int V):               // Create empty graph with v vertices
  public void addEdge(int v, int w): // add an edge v-w
  Iterable<Integer> adj(int v):      // vertices adjacent to v
  int V():                           // number of vertices
  int E():                           // number of edges
...
```

客户端（想使用我们的图数据结构的人）可以用我们提供的任何函数来实现自己的算法。我们提供的方法会极大地影响客户端实现特定算法的难易程度。

既然知道了怎样在纸上画图，也理解了基本概念和定义，现在可以考虑图在计算机里应该怎样表示。我们希望能快速回答关于图的下列问题：

* 给定的顶点 `u` 和 `v` 相邻吗？
* 顶点 `v` 和某条边 `e` 关联吗？
* 哪些顶点和 `v` 相邻？
* 哪些边和 `v` 关联？

### 邻接表

在邻接表（adjacency list）中，要创建一个大小和图中顶点数相同的数组。数组的每个位置代表图中的一个顶点。每个位置指向一个列表。这些列表叫作邻接表，因为列表中的每个元素代表这个顶点的一个邻居。

另一种可以用来表示图中的边的数据结构叫作*邻接矩阵*。

### 邻接矩阵

在这种数据结构中，我们有一个大小为 N×N（N 是顶点数）的二维数组，里面存布尔值。如果有一条从 *i* 到 *j* 的边，矩阵的第 (*i*, *j*) 项就是 true，没有边就是 false。因此，每个顶点在矩阵中都有一行和一列，表中的值表示那条边是否存在。

### 效率

底层数据结构的选择会影响图的运行时间和内存占用。[幻灯片](https://docs.google.com/presentation/d/11iacyiFt3QUrzo1yAU_xoXAjGTH4UzV7o6CR04HYRrI/edit#slide=id.g54593997ea_0_422) 里的一张表汇总了每种表示在各种操作上的效率。强烈不建议不花时间先理解这些界从何而来、怎样得出，就直接把这张表抄到考试的小抄上。讲座里有对其中几格背后道理的详细讲解。

## 20.3 小结

### 图遍历概览

* 我们在树上用过的那些遍历可以推广到图上。给定一个源顶点，可以按以下顺序访问顶点：
  * DFS 前序：对每个顶点调用 DFS 的顺序。
  * DFS 后序：DFS 从每个顶点返回的顺序。
  * BFS：按离源节点的距离排列的顺序（在树里就是层序）。

### BFS

* 和 DFS 不同，BFS 有一个自然的迭代（而不是递归）解法。BFS 先访问源顶点 `s`，然后访问离 `s` 距离为 `1` 的每个顶点，然后访问离 `s` 距离为 `2` 的每个顶点，依此类推。
* BFS 用一个由接下来要探索的顶点组成的 *fringe*。在 BFS 中，这个 fringe 是一个队列。我们把新顶点加到队尾，从队头取出要访问的顶点。
* 如果我们想让从源点到每个其他顶点的边数最少，可以用 BFS 解决最短路径问题。如果想从 BFS 中还原出最短路径，需要在遍历时记录每个顶点的 `edgeTo`。

### 图的实现

* 图的 API 的选择决定了客户端必须怎样写代码。某些 API 让一些任务更容易、另一些任务更难。API 的选择也会影响运行时间和内存。
* 图的实现可以选择邻接矩阵、边的列表和邻接表。邻接矩阵是一个二维布尔数组，表示任意一对顶点是否相邻。边的列表是图中所有边的集合。
* 表示图最常用的做法是邻接表。在这种表示中，我们维护一个以顶点编号为下标的列表数组；每个下标存放和这个顶点相连的所有顶点。

### 元认知问题

1. 假设用 BFS 找到了某条从 `a` 到 `b` 的最短路径。考虑这条路径上 `a` 和 `b` 之间的一个顶点 `c`。关于从 `c` 到 `b` 的最短路径，我们能说什么？
2. [2015 春季期中考试 2](https://drive.google.com/file/d/1uE1QlF4YguWVp8m8UJ97R2xPC4b1NnQ5/view?usp=sharing) 的第 4c 题。

<details>

<summary>第 1 题</summary>

把原来从 `a` 到 `b` 的最短路径记作 $p_{ab}$，把这条路径上从 `c` 到 `b` 的那一段记作 $p^{*}_{cb}$。如果 `c` 和 `b` 之间存在某条更短的路径 $p'_{cb}$，那么我们可以先走原来 $p_{ab}$ 中从 `a` 到 `c` 的那一段，再走 $p'_{cb}$，得到一条从 `a` 到 `b` 的更短的路径。

然而，前面说过 $p_{ab}$ 是 `a` 和 `b` 之间的最短路径。这就矛盾了。

因此，最短路径上从 `c` 到 `b` 的那一段，本身就是 `c` 和 `b` 之间的一条最短路径。

</details>
