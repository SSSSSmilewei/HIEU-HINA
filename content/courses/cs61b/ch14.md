## 14.1 引言

*🚨 新数据结构警报 🚨：并查集*

像你我这样的人都居住在各自的国家里。可以把每个国家看作一个集合，把住在里面的所有人看作这个集合的元素。同一个人不能同时住在两个不同的国家。我们刚才建立的模型就是**不相交集合**（disjoint set）。

> 如果两个集合没有共同的元素，就称它们为*不相交集合*。不相交集合（也叫「并查集」，Union-Find）数据结构记录固定数量的元素，这些元素被划分成若干个*不相交集合*。这个数据结构有两个操作：

1. `connect(x, y)`：把 `x` 和 `y` 连起来。也叫 `union`（合并）。
2. `isConnected(x, y)`：如果 `x` 和 `y` 是连通的（即属于同一个集合），返回 true。

并查集数据结构有固定数量的元素，每个元素一开始各自在自己的子集里。对某些元素 `x` 和 `y` 调用 `connect(x, y)`，就把子集合并起来。

例如，假设有四个元素，叫作 A、B、C、D。一开始，每个元素都在自己的集合里：

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%2823%29.png" alt="">

*{A} {B} {C} {D}*

调用 `connect(A, B)` 之后：

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%28126%29.png" alt="">

*{A, B} {C} {D}*

注意子集 A 和 B 被合并了。看看几个 `isConnected` 调用的输出：

`isConnected(A, B) -> true`

`isConnected(A, C) -> false`

调用 `connect(A, D)` 之后：

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%28104%29.png" alt="">

*{A, B, D} {C}*

我们找到 A 所在的集合，把它和 D 所在的集合合并，形成一个大的 A、B、D 集合。C 保持不动。

`isConnected(A, D) -> true`

`isConnected(A, C) -> false`

有了这个直观认识，我们来正式定义 DisjointSets 接口是什么样子的。提醒一下，**接口**规定数据结构应该有*什么*行为（而不规定*怎样*实现）。这样，任何实现 `DisjointSets` 接口的类都知道必须包含 `connect(int p, int q)` 和 `isConnected(int p, int q)` 这两个函数，如下所示。目前我们只处理非负整数的集合。这并不是一个限制，因为在实际应用中，我们可以给想表示的任何东西分配整数值。

```java
public interface DisjointSets {
    /** connects two items P and Q */
    void connect(int p, int q);

    /** checks to see if two items are connected */
    boolean isConnected(int p, int q); 
}
```

但我们要怎样为这些不相交集合保存数据，以便查出每个成员属于哪个集合？要用什么数据结构来表示这个了不起的数据结构？除了学习怎样实现一个迷人的数据结构，本章也是一个机会，让你看到一个数据结构的实现是怎样演进的。在满意之前，我们会讨论并查集设计的四个版本：*快速查找*（Quick Find）→ *快速合并*（Quick Union）→ *加权快速合并*（Weighted Quick Union，WQU）→ *带路径压缩的 WQU*。**我们会看到设计决策怎样极大地影响渐近运行时间和代码复杂度。**

## 14.2 快速查找（Quick Find）

*记录集合的成员关系……*

### 集合的列表

直观上，我们可能首先想到把并查集表示成集合的列表，例如 `List<Set<Integer>>`。

例如，如果有 N=6 个元素，还没有任何连接，我们的集合列表就是 `[{0}, {1}, {2}, {3}, {4}, {5}, {6}]`。看起来不错。不过，想想怎样完成像 `connect(5, 6)` 这样的操作。我们得遍历最多 `N` 个集合来找到 5，再遍历最多 `N` 个集合来找到 6。运行时间变成 `O(N)`。而且，如果你试着实现它，代码会相当复杂。

> 要记住的教训是：**最初的设计决策决定了代码复杂度和运行时间。**

### 快速查找

我们来考虑另一种用*单个整数数组*的做法。

* **数组的下标**表示集合中的元素。
* **下标处的值**是它所属集合的编号。

例如，把 `{0, 1, 2, 4}, {3, 5}, {6}` 表示成：

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%2872%29.png" alt="">

*集合 4：{0, 1, 2, 4}｜集合 5：{3, 5}｜集合 6：{6}*

数组下标（0……6）是元素。`id[i]` 处的值是它所属的集合。*具体的集合编号无关紧要，只要同一个集合中的所有元素有相同的 id 就行。*

### connect(x, y)

来看 connect 操作怎样工作。现在 `id[2] = 4`，`id[3] = 5`。调用 `connect(2, 3)` 之后，所有 id 为 4 和 5 的元素应该有相同的 id。我们暂且把它们都赋值为 5：

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%28102%29.png" alt="">

*集合 5：{0, 1, 2, 3, 4, 5}｜集合 6：{6}*

**isConnected(x, y)**

要检查 `isConnected(x, y)`，只需检查 `id[x] == id[y]`。注意这是常数时间的操作！

我们把这种实现叫作「快速查找」，因为查明元素是否连通只需常数时间。

### 代码与运行时间

```java
public class QuickFindDS implements DisjointSets {

    private int[] id;

    /* Θ(N) */
    public QuickFindDS(int N){
        id = new int[N];
        for (int i = 0; i < N; i++){
            id[i] = i;
        }
    }

    /* need to iterate through the array => Θ(N) */
    public void connect(int p, int q){
        int pid = id[p];
        int qid = id[q];
        for (int i = 0; i < id.length; i++){
            if (id[i] == pid){
                id[i] = qid;
            }
        }
    }

    /* Θ(1) */
    public boolean isConnected(int p, int q){
        return (id[p] == id[q]);
    }
}
```

N = 并查集数据结构中的元素个数

| 实现 | 构造函数 | `connect` | `isConnected` |
| --- | --- | --- | --- |
| ListOfSets | Θ(N)¹ | O(N) | O(N) |
| QuickFind | Θ(N) | Θ(N) | Θ(1) |

**注**

1. 我们没有讨论这一点，不过可以推出：一开始要创建 N 个不同的集合，花的时间是 Θ(N)。

## 14.3 快速合并（Quick Union）

假设我们优先让 `connect` 操作变快。我们仍然用一个数组表示集合。不过不再存 id，而是给每一项分配它父节点的下标。如果一项没有父节点，它就是一个「根」，我们给它赋一个负值。

这种做法让我们可以把每个集合想象成一棵树。例如，把 `{0, 1, 2, 4}, {3, 5}, {6}` 表示成：

注意我们**只用一个数组**来表示这些集合。树只是我们自己想象出来的样子。

<img src="https://web.archive.org/web/2020id_/https://joshhug.gitbooks.io/hug61b/content/chap9/9.3.1.png" alt="">

对 QuickUnion，我们定义一个辅助函数 `find(int item)`，返回 `item` 所在树的根。例如，对上面的集合，`find(4) == 0`，`find(1) == 0`，`find(5) == 3`，等等。每个元素都有唯一的根。

**connect(x, y)**

要连接两项，先找出每一项所属的集合（它们各自所在树的根），再让其中一个成为另一个的孩子。例子：

`connect(5, 2)`：

1. `find(5)` -> 3
2. `find(2)` -> 0
3. 把 `find(5)` 的值设为 `find(2)`，即 `parent[3] = 0`

注意元素 3 现在指向元素 0，把两棵树（两个集合）合成了一个。

<img src="https://web.archive.org/web/2020id_/https://joshhug.gitbooks.io/hug61b/content/chap9/9.3.2.png" alt="">

在最好情况下，如果 `x` 和 `y` 都是各自树的根，`connect(x, y)` 只需让 `x` 指向 `y`，这是 Θ(1) 的操作！（所以叫 QuickUnion，快速合并。）

**isConnected(x, y)**

如果两个元素属于同一个集合，它们就在同一棵树里，因此有相同的根。所以 `isConnected(x, y)` 只需检查 `find(x) == find(y)`。

### 性能

QuickUnion 有一个潜在的性能问题：树可能变得非常长。这时，找一项的根（`find(item)`）就变得非常昂贵。看下面这棵树：

![](https://web.archive.org/web/2020id_/https://joshhug.gitbooks.io/hug61b/content/chap9/9.3.3.png)

在最坏情况下，我们要走过所有项才能到达根，运行时间是 Θ(N)。因为 `connect` 和 `isConnected` 都要调用 `find`，两者的运行时间上界都是 O(N)。

### 小结与代码

N = 并查集数据结构中的元素个数

| 实现 | 构造函数 | `connect` | `isConnected` |
| --- | --- | --- | --- |
| QuickFind | Θ(N) | Θ(N) | Θ(1) |
| QuickUnion | Θ(N) | O(N) | O(N) |

从运行时间表看，QuickUnion 似乎比 QuickFind 还差！不过要注意 O(N) 是一个**上界**。当树是平衡的时，`connect` 和 `isConnected` 的表现都相当好。下一节我们会看到怎样*保证*它们表现良好。

```java
public class QuickUnionDS implements DisjointSets {
    private int[] parent;

    public QuickUnionDS(int num) {
        parent = new int[num];
        for (int i = 0; i < num; i++) {
            parent[i] = -1;
        }
    }

    private int find(int p) {
        while (parent[p] >= 0) {
            p = parent[p];
        }
        return p;
    }

    @Override
    public void connect(int p, int q) {
        int i = find(p);
        int j= find(q);
        parent[i] = j;
    }

    @Override
    public boolean isConnected(int p, int q) {
        return find(p) == find(q);
    }
}
```

## 14.4 加权快速合并（WQU）

改进 Quick Union 依赖于一个关键的洞察：每次调用 `find`，都得爬到树的根。因此，树越矮，花的时间越少！

**新规则**：每次调用 `connect`，总是把较小那棵树的根连到较大的树上。

遵循这条规则，树的最大高度是 $\log N$，其中 N 是并查集中的元素个数。这对 `connect` 和 `isConnected` 的运行时间有什么影响？

我们用一个例子说明这样做的好处。考虑连接下面的两个集合 T1 和 T2：

![](https://web.archive.org/web/2020id_/https://joshhug.gitbooks.io/hug61b/content/chap9/9.4.1.png)

有两种连接方式：

第一种是把 T1 连到 T2 上。第二种是把 T2 连到 T1 上。

<img src="https://web.archive.org/web/2020id_/https://joshhug.gitbooks.io/hug61b/content/chap9/9.4.2.png" alt="">

**第二种更好**，因为它的高度只有 2，而不是 3。按我们的新规则，也会选第二种，因为 T2 比 T1 小（大小是 3 对 6）。

我们按树中的项数来判断大小。因此，连接两棵树时，需要知道它们的大小（或者说权重）。可以把这个信息存在树的根里，把 `-1` 换成 `-(树的大小)`。

**最大高度：log N**

遵循上面的规则，能保证任何树的*最大*高度是 Θ(log N)。N 是并查集中的元素个数。**由此可知，`connect` 和 `isConnected` 的运行时间上界是 O(log N)。**

为什么是 $\log N$？讲座视频给出了更形象的解释。下面是一个可选读的数学解释，说明为什么最大高度是 $\log_{2}N$。设想树 $T1$ 中的任意一个元素 $x$。只有当 $T1$ 被放到另一棵树 $T2$ 下面时，$x$ 的深度才增加 1。这时，因为 $size(T2)\geq size(T1)$，合并后的树的大小至少是 $T1$ 的两倍。含 $x$ 的树最多翻倍 $\log_{2}N$ 次，就达到 N 项的总数了（$2^{\log_{2}N} = N$）。所以最多翻倍 $\log_{2}N$ 次，每次树增加一层 → 最多 $\log_{2}N$ 层。

你可能会想，为什么不按高度而按权重来连接树。结果是按高度实现起来更复杂，给出的高度上限同样是 Θ(log N)。

### 小结

| 实现 | 构造函数 | `connect` | `isConnected` |
| --- | --- | --- | --- |
| QuickFind | Θ(N) | Θ(N) | Θ(1) |
| QuickUnion | Θ(N) | O(N) | O(N) |
| 加权快速合并 | Θ(N) | O(log N) | O(log N) |

N = 并查集数据结构中的元素个数

## 14.5 带路径压缩的加权快速合并

*加权快速合并已经相当好了，但我们还能做得更好！*

巧妙的洞察在于意识到：每次调用 `find(x)`，都得走过从 `x` 到根的路径。所以，在走的过程中，我们可以顺便把访问到的所有项都直接连到根上，而不增加渐近成本。

把沿途所有项都连到根上，会让树在每次调用 `find` 之后变得更矮。

回想 **`connect(x, y)` 和 `isConnected(x, y)` 总会调用 `find(x)` 和 `find(y)`**。因此，在调用足够多次 `connect` 或 `isConnected` 之后，基本上所有元素都会直接指向它们的根。

由此可知，长期来看，`connect` 和 `isConnected` 的平均运行时间变得**几乎是常数**！这叫作*均摊运行时间*（amortized runtime）。

更具体地说，对 N 个元素做 M 次操作，带路径压缩的 WQU 是 $O(N + M (\lg^* N))$。lg\* 是 [迭代对数](https://en.wikipedia.org/wiki/Iterated_logarithm)，对任何现实中的输入都小于 5。

### 小结

N：并查集中的元素个数

| 实现 | `isConnected` | `connect` |
| --- | --- | --- |
| 快速查找 | Θ(1) | Θ(N) |
| 快速合并 | O(N) | O(N) |
| 加权快速合并（WQU） | O(log N) | O(log N) |
| 带路径压缩的 WQU | O(α(N))\* | O(α(N))\* |

\*长期来看表现为常数。

<details>

<summary>第 4 题</summary>

```java
public int find(int p) {
    int root = p;
    while (root != parent[root]) {
        root = parent[root];
    }
    
    while (p != root) {
        int newp = parent[p];
        parent[p] = root;
        p = newp;
    }
    
    return root;
}
```

（这份参考代码假设根节点的父节点是它自己，和本章用负数表示根的约定不同；如果用负数约定，第一个循环的条件应改为 `parent[root] >= 0`。）

</details>
