### 集合

集合是一组互不相同的元素——每个元素只能有一份。和列表不同，集合也没有顺序的概念：不能按下标访问集合，也不能控制每个元素插入到集合的哪个位置。

#### Java 的集合

Java 有 `Set` 接口和它的实现，例如 `HashSet`。如果不想写全名，记得导入它们！

```java
import java.util.Set;
import java.util.HashSet;
```

使用示例：

```java
Set<String> s = new HashSet<>();
s.add("Tokyo");
s.add("Lagos");
System.out.println(s.contains("Tokyo")); // true
```

#### Python 里的对应写法

在 Python 里，直接调用 `set()`。检查是否包含时，不用方法而用关键字 `in`。例如：

```python
s = set()
s.add("Tokyo")
s.add("Lagos")
print("Tokyo" in s) // True
```

## 10.2 异常

在这一节里，我们会学习怎样抛出异常，有效地处理代码中可能出现的错误。

视频（英文）：<https://youtu.be/r5hp67RfWaY>

上一节的 `ArraySet` 实现有一个小错误。往 ArraySet 里加 `null` 时，会得到 NullPointerException（空指针异常）。

问题出在 `contains` 方法里，我们检查的是 `items[i].equals(x)`。如果 `items[i]` 处的值是 null，就是在调用 `null.equals(x)` -> NullPointerException。

异常会让正常的控制流停下来。事实上，我们可以选择抛出自己的异常。在 Python 里，你可能见过用 `raise` 关键字这样做。在 Java 里，异常是对象，我们用下面的格式抛出异常：

`throw new ExceptionObject(parameter1, ...)`

当用户试图往 `ArraySet` 里加 null 时，我们来抛一个异常。我们抛出 `IllegalArgumentException`，它接收一个参数（一条 `String` 信息）。

修改后的 `add` 方法：

```java
/* Associates the specified value with the specified key in this map.
   Throws an IllegalArgumentException if the key is null. */
public void add(T x) {
    if (x == null) {
        throw new IllegalArgumentException("can't add null");
    }
    if (contains(x)) {
        return;
    }
    items[size] = x;
    size += 1;
}
```

反正都会得到一个异常——为什么这样更好？

1. 我们掌控着自己的代码：我们有意识地决定程序的流程在哪里停下。
2. 对使用我们代码的人来说，异常类型更有用，错误信息更有帮助。

不过，如果程序根本不崩溃会更好。在这种情况下，我们可以有不同的做法。下面列出几种：

**做法一**：如果传给 `add` 的是 `null`，就不把它加进数组。

**做法二**：修改 `contains` 方法，处理 `items[i] == null` 的情形。

不论你怎样决定，重要的是让用户知道会发生什么。这就是为什么文档（比如对方法的注释）非常重要。

## 10.3 迭代

视频（英文）：<https://www.youtube.com/watch?v=Gv6LjusNBU0>

对 Java 的 `HashSet`，可以用简洁的增强 for 循环：

```java
Set<String> s = new HashSet<>();
s.add("Tokyo");
s.add("Lagos");
for (String city : s) {
    System.out.println(city);
}
```

然而，如果对我们的 `ArraySet` 这样做，会得到一个错误。怎样才能支持这个功能？

### 增强 for 循环

先来理解使用增强 for 循环时发生了什么。可以把增强 for 循环「翻译」成一种难看的、手动的写法。

```java
Set<String> s = new HashSet<>();
...
for (String city : s) {
    ...
}
```

上面的代码相当于：

```java
Set<String> s = new HashSet<>();
...
Iterator<String> seer = s.iterator();
while (seer.hasNext()) {
    String city = seer.next();
    ...
}
```

我们来揭开其中的魔法，这样就能构建支持这种写法的自己的类。

关键在于一个叫*迭代器*（iterator）的对象。

在我们的例子里，可以在 List.java 里定义一个返回迭代器对象的 `iterator()` 方法。

```java
public Iterator<E> iterator();
```

现在可以用这个对象遍历列表中的所有项：

```java
List<Integer> friends = new ArrayList<Integer>();
...
Iterator<Integer> seer = friends.iterator();

while (seer.hasNext()) {
System.out.println(seer.next());
}
```

这段代码的行为和上面 foreach 循环的版本完全相同。

迭代器的做法里有三个关键方法：

首先，用 `Iterator<Integer> seer = friends.iterator();` 得到一个新的迭代器对象。

接着，用 while 循环遍历列表。用 `seer.hasNext()` 检查是否还有剩下的项，如果还有没看过的项就返回 true，如果所有项都处理完了就返回 false。

最后，`seer.next()` 同时做两件事。它返回列表的下一个元素，这里我们把它打印出来。它还让迭代器前进一项。这样，迭代器只会检查每一项一次。

### 实现迭代器

在这一节里，我们要讲怎样构建一个支持迭代的类。

先想想，要成功编译下面这个迭代器例子，编译器需要知道什么：

```java
List<Integer> friends = new ArrayList<Integer>();
Iterator<Integer> seer = friends.iterator();

while(seer.hasNext()) {
    System.out.println(seer.next());
}
```

可以看调用相关方法的各个对象的静态类型。`friends` 是一个 List，在它上面调用了 `iterator()`，所以必须问：

* List 接口有 iterator() 方法吗？

`seer` 是一个 Iterator，在它上面调用了 `hasNext()` 和 `next()`，所以必须问：

* Iterator 接口有 next 和 hasNext() 方法吗？

那么怎样满足这些要求？

List 接口继承了（extends）Iterable 接口，继承了其中的抽象方法 iterator()。（其实 List 继承的是 Collection，Collection 再继承 Iterable，不过一开始这样想更容易。）

```java
public interface Iterable<T> {
    Iterator<T> iterator();
}
```

```java
public interface List<T> extends Iterable<T>{
    ...
}
```

接着，编译器检查 Iterator 是否有 `hasNext()` 和 `next()`。Iterator 接口明确规定了这些抽象方法：

```java
public interface Iterator<T> {
    boolean hasNext();
    T next();
}
```

**如果有人在 `hasNext` 返回 false 时调用 `next` 会怎样？**

这种行为是未定义的。不过，一个常见的约定是抛出 `NoSuchElementException`。例子见 [讨论课 5](https://sp19.datastructur.es/materials/discussion/disc05sol.pdf)。

**`hasNext` 总会在 `next` 之前被调用吗？**

不一定。有时使用迭代器的人确切知道序列里有多少个元素，就会这样做。因此，我们不能依赖用户在调用 `next` 之前先调用 `hasNext`。不过，你总可以在自己的 `next` 函数里调用 `hasNext`。

具体的类会为这些接口方法实现自己的迭代行为。来看一个例子。（注意：如果想从头写起，就跟着视频里的现场编码做。）

我们要给 `ArraySet` 类加上遍历键的功能。首先，写一个新类 ArraySetIterator，嵌套在 ArraySet 里面：

```java
private class ArraySetIterator implements Iterator<T> {
    private int wizPos;

    public ArraySetIterator() {
        wizPos = 0;
    }

    public boolean hasNext() {
        return wizPos < size;
    }

    public T next() {
        T returnItem = items[wizPos];
        wizPos += 1;
        return returnItem;
    }
}
```

这个 ArraySetIterator 实现了 `Iterator<T>`，也就是说它实现了 `hasNext()` 方法和 `next()` 方法，用位置 `wizPos` 作为下标来记录它在数组中的位置。对于别的数据结构，我们可能会用不同的方式实现这两个方法。

**思考题**：对链表，你会怎样设计 `hasNext()` 和 `next()`？

有了这些方法，就可以用 ArraySetIterator 遍历一个 `ArraySet`：

```java
ArraySet<Integer> aset = new ArraySet<>();
aset.add(5);
aset.add(23);
aset.add(42);

Iterator<Integer> iter = aset.iterator();

while(iter.hasNext()) {
    System.out.println(iter.next());
}
```

不过，我们还是希望能支持增强 for 循环，让调用更简洁。为此，需要让 `ArraySet` 实现 Iterable 接口。Iterable 接口的核心方法是 `iterator()`，它为这个类返回一个 Iterator 对象。我们只需要返回一个刚写的 `ArraySetIterator` 的实例！

```java
public Iterator<T> iterator() {
    return new ArraySetIterator();
}
```

现在可以对 `ArrraySet` 使用增强 for 循环了！

```java
ArraySet<Integer> aset = new ArraySet<>();
...
for (int i : aset) {
    System.out.println(i);
}
```

这里我们看到了 **Iterable**，即让一个类可以被迭代的接口，它要求有 `iterator()` 方法，返回一个 Iterator 对象。我们也看到了 **Iterator**，即定义真正执行迭代的那些方法的对象的接口。可以把 Iterator 想成一台装在可迭代对象上、帮助完成迭代的机器。可迭代对象就是迭代器在其上工作的那个对象。

有了这两个组件，就可以为你的类写出漂亮的 for 循环了！

支持迭代的 `ArraySet` 代码如下：

```java
import java.util.Iterator;

public class ArraySet<T> implements Iterable<T> {
    private T[] items;
    private int size; // the next item to be added will be at position size

    public ArraySet() {
        items = (T[]) new Object[100];
        size = 0;
    }

    /* Returns true if this map contains a mapping for the specified key.
     */
    public boolean contains(T x) {
        for (int i = 0; i < size; i += 1) {
            if (items[i].equals(x)) {
                return true;
            }
        }
        return false;
    }

    /* Associates the specified value with the specified key in this map.
       Throws an IllegalArgumentException if the key is null. */
    public void add(T x) {
        if (x == null) {
            throw new IllegalArgumentException("can't add null");
        }
        if (contains(x)) {
            return;
        }
        items[size] = x;
        size += 1;
    }

    /* Returns the number of key-value mappings in this map. */
    public int size() {
        return size;
    }

    /** returns an iterator (a.k.a. seer) into ME */
    public Iterator<T> iterator() {
        return new ArraySetIterator();
    }

    private class ArraySetIterator implements Iterator<T> {
        private int wizPos;

        public ArraySetIterator() {
            wizPos = 0;
        }

        public boolean hasNext() {
            return wizPos < size;
        }

        public T next() {
            T returnItem = items[wizPos];
            wizPos += 1;
            return returnItem;
        }
    }

    public static void main(String[] args) {
        ArraySet<Integer> aset = new ArraySet<>();
        aset.add(5);
        aset.add(23);
        aset.add(42);

        //iteration
        for (int i : aset) {
            System.out.println(i);
        }
    }

}
```

## 10.4 Object 的方法

所有类都继承自总的 Object 类。继承来的方法如下：

* `String toString()`
* `boolean equals(Object obj)`
* `Class <?> getClass()`
* `int hashCode()`
* `protected Objectclone()`
* `protected void finalize()`
* `void notify()`
* `void notifyAll()`
* `void wait()`
* `void wait(long timeout)`
* `void wait(long timeout, int nanos)`

本章重点讲前两个。我们会利用继承，在自己的类里重写这两个方法，让它们按我们希望的方式工作。

### toString()

视频（英文）：<https://www.youtube.com/watch?v=AKnMv0ootkg>

`toString()` 方法给出对象的字符串表示。`System.out.println()` 函数会对传给它的任何对象隐式调用这个方法，并打印返回的字符串。运行 `System.out.println(dog)` 时，它实际做的是：

```java
String s = dog.toString()
System.out.println(s)
```

默认的 `Object` 类的 `toString()` 方法打印对象在内存中的位置。这是一个十六进制字符串。Arraylist 这样的类和 Java 数组都有自己重写过的 `toString()` 方法。这就是为什么你使用 Arraylist、为它写测试时，错误信息总会以 (1, 2, 3, 4) 这样漂亮的格式显示列表，而不是返回内存位置。

对于我们自己写的类，比如 `ArrayDeque`、`LinkedListDeque` 等，如果想以可读的格式打印对象，就需要提供自己的 `toString()` 方法。

我们试着为 `ArraySet` 类写这个方法。读一读下面的 `ArraySet` 类，确保你理解各个方法做什么。可以把代码贴进 Java 可视化工具，加深理解！

**练习 6.4.1**：写 toString() 方法，让我们打印 ArraySet 时，它把元素用逗号隔开、放在花括号里打印，即 {1, 2, 3, 4}。记住，toString() 方法应该返回一个字符串。

**解答**

```java
public String toString() {
    String returnString = "{";
    for (int i = 0; i < size; i += 1) {
        returnString += keys[i];
        returnString += ", ";
    }
    returnString += "}";
    return returnString;
}
```

这个解答看起来简单优雅，其实非常幼稚。这是因为在 Java 里这样用字符串连接，即 `returnString += keys[i];` 时，你其实不只是往 `returnString` 后面追加，而是在创建一个全新的字符串。这极其低效，因为创建一个新的字符串对象也要花时间！具体来说，花的时间和字符串的长度成线性关系（后面的章节会讨论为什么！）。

**附加题**：假设往字符串上连接一个字符要花 1 秒。如果有一个大小为 5 的 ArraySet：`{1, 2, 3, 4, 5}`，运行 `toString()` 方法要多长时间？

**答案**：把 `returnString` 设为左括号要花 1 秒，因为这涉及把 `{` 加到空字符串 `""` 上。加第一个元素要创建一个全新的字符串，加上 } 和 1，要花 2 秒。加第二个元素要花 3 秒，因为要加上 `{`、`1`、`2`。这个过程一直继续，所以对整个集合，总时间是 `1 + 2 + 3 + 4 + 5 + 6 + 7`。

为了补救，Java 有一个特殊的类叫 `StringBuilder`。它创建一个可变的字符串对象，这样就可以一直往同一个字符串对象上追加，而不必每次都创建新的。

**练习 6.4.2**：用 StringBuilder 重写 toString() 方法。

**解答**

```java
public String toString() {
        StringBuilder returnSB = new StringBuilder("{");
        for (int i = 0; i < size - 1; i += 1) {
            returnSB.append(items[i].toString());
            returnSB.append(", ");
        }
        returnSB.append(items[size - 1]);
        returnSB.append("}");
        return returnSB.toString();
    }
```

现在你成功地重写了 `toString()` 方法！试着打印 ArraySet，看看你的劳动成果。

### equals()

视频（英文）：<https://www.youtube.com/watch?v=qHuS1o97nfQ>

在 Java 里，`equals()` 和 `==` 的行为不同。`==` 检查两个对象在内存中是否真的是同一个对象。记住，按值传递！`==` 检查两个盒子里装的是否是同样的东西。对基本类型来说，这意味着检查值是否相等。对对象来说，这意味着检查地址（指针）是否相等。

假设有这个 `Doge` 类：

* `False`
* `True`

`fido` 和 `fidoTwin` 不被认为是 `==` 的，因为它们指向不同的对象。不过，既然它们所有的属性都相同，这就相当傻了。可以看出 `==` 会给 Java 测试带来一些问题。我们为 ArrayList 写测试、想检查期望值和函数返回的是否相同时，会把期望值创建成一个新的 arraylist。如果在测试里用 `==`，结果总会是 false。这正是 `equals(Object o)` 的用处。

### equals(Object o)

`equals(Object o)` 是 Object 类里的一个方法，默认情况下它的行为和 == 一样，检查 this 的内存地址是否和 o 相同。不过，我们可以重写它，按我们希望的任何方式定义相等！例如，两个 Arraylist 要被认为相等，只需要它们以相同的顺序含有相同的元素。

**练习 6.4.4**：我们来为 ArraySet 类写一个 equals 方法。记住，集合是无序的、元素互不相同的一组东西。所以，两个集合要被认为相等，只需要检查它们是否含有相同的元素。

**解答**

```java
public boolean equals(Object other) {
        if (this == other) {
            return true;
        }
        if (other == null) {
            return false;
        }
        if (other.getClass() != this.getClass()) {
            return false;
        }
        ArraySet<T> o = (ArraySet<T>) other;
        if (o.size() != this.size()) {
            return false;
        }
        for (T item : this) {
            if (!o.contains(item)) {
                return false;
            }
        }
        return true;
    }
```

我们在方法开头加了几项检查，确保 `.equals()` 能处理 null 和不同类的对象。我们还做了一个优化：如果 == 返回 true，就立即返回 true。这样就省去了遍历集合的额外工作。

**Java 中 equals 的规则**：重写 `.equals()` 方法有时比看起来要棘手。实现 `.equals()` 方法时要遵守的几条规则如下：

1. `equals` 必须是一个等价关系：
   * **自反性**：`x.equals(x)` 为真
   * **对称性**：`x.equals(y)` 当且仅当 `y.equals(x)`
   * **传递性**：`x.equals(y)` 且 `y.equals(z)` 蕴含 `x.equals(z)`
2. 它必须接收一个 Object 参数，才能重写原来的 `.equals()` 方法。
3. 它必须是一致的：如果 `x.equals(y)`，那么只要 `x` 和 `y` 不变，`x` 就必须一直等于 `y`。
4. 对 null 永远不为真：`x.equals(null)` 必须是 false。


### 迭代

#### 迭代器与可迭代对象的区别

这两个词关系非常密切，但含义不同，常常容易混淆。首先要知道，它们都是 Java 接口，需要实现的方法不同。下面是 Iterator 的简化接口：

```
public interface Iterator<T> {
  boolean hasNext();
  T next();
}
```

下面是 Iterable 的简化接口：

```
public interface Iterable<T> {
    Iterator<T> iterator();
}
```

注意，一个对象（例如 ArrayList 或 LinkedList）要成为*可迭代对象*（iterable），就必须包含一个返回*迭代器*（iterator）的方法。迭代器是主动逐个走过可迭代对象的那个对象。使用这两个接口时，要记住它们之间的这种关系和区别。

### Object 的方法

#### toString

`toString()` 方法返回对象的字符串表示。例如，`System.out.println(someObject)` 调用 `someObject` 的 `toString()` 方法，把它返回的字符串打印到控制台。

这在调试时最有用，因为它让我们更容易了解对象的当前状态。

#### == 与 .equals

Java 里有两种相等的概念——「==」和「.equals()」方法。关键区别在于：用 == 时，我们检查的是两个对象在内存中的地址是否相同（它们是否指向同一个实例或对象）。而 .equals() 是一个可以被类重写的方法，可以用来定义某种自定义的判断相等的方式。这让类能利用它对自身的额外了解，更准确地回答相等的问题。

例如，假设想检查两块石头是否相等：

```
public class Stone{
  int weight;
  public Stone(int weight){
    this.weight = weight;
  }
}
Stone s = new Stone(100);
Stone r = new Stone(100);
```

如果想因为 s 和 r 重量相同而认为它们相等，用 == 检查相等时，这两块 Stone 不会被认为相等，因为它们的内存地址不同。

另一方面，如果像下面这样重写 Stone 的 equals 方法：

```
public boolean equals(Object o){
  return this.weight == ((Stone) o).weight
}
```

石头就会因为重量相同而被认为相等。
