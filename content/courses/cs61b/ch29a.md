## 29.1 排序问题

### 排序

在这本教材余下的部分，我们会讨论排序问题，它可以非正式地定义为：把给定的一组元素按某种特定的顺序排列。

这本身就是一项有用的任务，也可以是更大的算法问题中的子问题。排序可以用于查找重复项（排序后，相等的元素相邻）、二分查找、平衡数据结构等问题。

我们介绍排序的另一个原因是，各种排序方法提供了关于怎样着手解决计算问题的一般思路。排序问题的解法常常会用到这门课前面讲过的数据结构。

### 排序：定义

对键 a、b、c 的一个**序关系**（ordering relation）$<$ 具有以下性质：

* *三分律*（Law of Trichotomy）：a $<$ b、a = b、b $<$ a 三者中恰好有一个成立。
* *传递律*（Law of Transitivity）：如果 a $<$ b，且 b $<$ c，那么 a $<$ c。

具有上述性质的序关系也叫**全序**（total order）。

一次**排序**（sort）是对一个元素序列的一种重新排列，使得键相对于给定的序关系按非递减顺序排列，即 x1 ≤ x2 ≤ x3 ≤ ... ≤ xN。

#### 例子：字符串长度

序关系的一个例子是字符串的长度。看看这两条定律怎样适用：

* *三分律*：对两个字符串 `a` 和 `b`，下面三者中只有一个能成立——`len(a)` < `len(b)`、`len(a)` = `len(b)` 或 `len(a)` > `len(b)`。
* *传递律*：如果 `len(a)` < `len(b)` 且 `len(b)` < `len(c)`，那么显然 `len(a)` < `len(c)`。

假设用上面的序关系给 `["cows", "get", "going", "the"]` 排序。那么两种合法的排序结果是 `["the", "get", "cows", "going"]` 和 `["get", "the", "cows", "going"]`。注意在这种排序里，`the` 和 `get` 是等价的，因为它们的长度相等。

### Java 中的序关系

在 Java 里，序关系通常由 `compareTo` 或 `compare` 方法给出。例如：

```java
import java.util.Comparator;
 
public class LengthComparator implements Comparator<String> {
    public int compare(String x, String b) {
        return x.length() - b.length();
    }
}
```

注意，按上面的关系，`the` 和 `get` 在顺序上相等，但按 `.equals()` 方法*并不*相等。

### 逆序对

看待排序的另一种方式，是把它看作修正元素序列中的逆序对。**逆序对**（inversion）是相对于所定义的序关系顺序颠倒的一对元素。

例如，在下面这个由 11 个元素组成的序列里，最多可能有 55 个逆序对（11 选 2），而这个序列本身有 6 个逆序对。

### 排序：性能

前面我们见过对算法运行效率的刻画，也叫算法的**时间复杂度**（time complexity）。例如，可以说迪杰斯特拉算法的时间复杂度是 O(E log V)。

对算法「额外」内存用量的刻画，有时叫作算法的**空间复杂度**（space complexity）。例如，迪杰斯特拉算法存放队列以及 `distTo`、`edgeTo` 数组的空间复杂度是 Θ(V)。注意图本身占用 Θ(V+E) 的空间，但我们不把它算进迪杰斯特拉算法的空间复杂度，因为图是迪杰斯特拉算法的输入。换句话说，我们只关心算法使用的*额外*空间。

## 29.2 选择排序与堆排序

### 选择排序

选择排序（selection sort）使用下面的算法：

1. 找出最小的元素。
2. 把这个元素交换到最前面。
3. 重复，直到所有元素都就位（没有逆序对）。

这个排序算法的演示见 [这里](https://joshh.ug/61b/sorts/selection_sort/index.html)。

用数组或类似的数据结构，选择排序的运行时间是 $\Theta(N^2)$。

你可能注意到选择排序似乎很低效，你说得对——我们每次都要把剩下的整个数组看一遍来找最小值，一遍又一遍地检查同样的元素。

### 堆排序

#### 朴素的堆排序

为了避免上面提到的选择排序的低效，可以利用一个大顶堆（max-oriented heap），而不是线性地扫描数组。

*注意：由于堆是用数组表示的，用大顶堆的实现更简单，我们可以在数组里维持「已排序」和「未排序」两部分。下一节会进一步解释。*

于是，要对 N 个元素做堆排序（heapsort），可以把所有元素插入一个大顶堆，再创建一个输出数组。然后反复从大顶堆里删除最大的元素，把它放到输出数组的后部。

##### 朴素堆排序的分析

这个算法的总运行时间是 $\Theta(N \log N)$。这个运行时间主要由三部分构成：

* 把 N 个元素插入堆：$O(N \log N)$。
* 选出最大的元素：$\Theta(1)$。
* 删除最大的元素：$O(\log N)$。

这比选择排序的 $\Theta(N^2)$ 运行时间有了很大的改进。

在内存用量上，输出数组要多占 $\Theta(N)$ 的空间。这比不用额外空间的选择排序差，但运行时间上的改进远远超过了这个缺点。

更进一步，我们可以对堆排序用一个技巧，去掉额外的输出数组。

#### 原地堆排序

另一种做法是用输入数组本身来构成堆和输出数组。

我们不是把元素插入一个表示堆的新数组，而是用一种叫作*自底向上堆化*（bottom-up heapification）的过程，把输入数组转换成堆。自底向上堆化是按层序的逆序沿着堆往上走，边往上走边把节点下沉到合适的位置。

用这种做法，就不需要数据的额外副本。堆化之后，我们用朴素堆排序的办法，弹出最大值并把它放到数组末尾。这样，我们维持数组前面「未排序」的部分（表示堆）和后面「已排序」的部分（表示目前已排好序的元素）。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%28120%29.png" alt="">

*自底向上堆化*

这个算法的演示见 [这里](https://joshh.ug/61b/sorts/heap_sort/index.html)。

##### 原地堆排序的运行时间

整个过程仍然是 $O(N \log N)$，因为自底向上堆化最多需要 $N$ 次下沉操作，每次最多花 $\log N$ 的时间。

*注意：可以证明自底向上堆化的时间上界是* $\Theta(N)$。*不过，这个证明超出了这门课的范围。*

##### 原地堆排序的内存

用原地堆排序，我们把堆排序的内存用量降到了 $\Theta(1)$。因为重复利用了输入数组，没有使用额外的空间（记住，评估空间复杂度时我们不计算输入）。

## 29.3 归并排序

我们以前讲过归并排序（mergesort），不过提醒一下，算法如下：

1. 把元素分成两半。
2. 对每一半做归并排序。
3. 把两个排好序的一半归并起来，得到最终结果。

这个算法的演示见 [这里](https://joshh.ug/61b/sorts/merge_sort/index.html)。

归并排序的运行时间是 $\Theta(N \log N)$——这里不再重新分析这个算法，如果想复习，可以参考这个 [链接](https://docs.google.com/presentation/u/1/d/1_LhI5V5JlcRHYU55_SF7ZHxPemBr9OVlNzj7ScYdg64/edit#slide=id.g84271d11b_2_77)。

归并步骤中用到的辅助数组需要 $\Theta(N)$ 的额外空间。注意，原地归并排序是可能的；不过它非常复杂，运行时间也会差上一个相当大的常数因子，所以这里不讲。
