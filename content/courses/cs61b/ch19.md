## 19.1 树的回顾

### 树与遍历

#### 什么是树？

回想一下，树由以下部分组成：

* 一组相连的节点（也叫顶点）。这两个词我们混着用。
* 一组连接这些节点的边。边不能构成环。
  * **约束**：任意两个节点之间恰好有一条路径。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/Screen%20Shot%202023-02-26%20at%206.04.39%20AM.png" alt="">

*图的例子（有些是树，有些不是……）*

图 1 是一棵树。它有一个节点，没有边。这*没问题*！

第二个和第三个结构是树。注意第三个是一个链表（LinkedList）。链表仍然是一棵树，因为它是一个连通的无环图。

第四个不是树。为什么？从最上面的节点到最下面的节点有两条路径，所以它不满足我们的约束。

**练习 17.1.1**：找出第五个结构不是树的原因。并修改上面不合法的树，让它们变成合法的树。

#### 什么是有根树？

回想一下，有根树（rooted tree）是指定了一个根（通常画成最上面的节点）的树。

这给了我们另外两个定义：

* 父节点（parent）。除了根，每个节点恰好有一个父节点。
  * 如果一个节点有 2 个父节点会怎样？它还是树吗？（提示：不是。）
* 孩子（child）。一个节点可以有 0 个或多个孩子。
  * 如果一个节点有 0 个孩子呢？它叫作叶子。

#### 树有什么用？

到目前为止，我们看过搜索树、字典树、堆、并查集等等。在我们创造高效算法的旅程中，它们极其有用：加快查找元素、支持前缀操作、检查连通性等等。

但事实上，树比我们意识到的还要无处不在。想想组织结构图。在这里，总裁是「根」。各位「副总裁」是根的孩子，依此类推。

## 19.2 树的遍历

### 树的~~迭代~~遍历

还记得我们怎样学习遍历列表吗？有一种遍历列表的方式感觉很自然。从开头开始……一直往下走。

我们也可能做过一些有点奇怪的事，比如倒着遍历列表。回想一下，我们还在 [讨论课](https://sp19.datastructur.es/materials/discussion/disc05.pdf) 里写过迭代器，跳过答疑排队系统里没写问题描述的学生。

那么怎样遍历一棵树？正确的「顺序」是什么？

回答这个问题之前，我们不能用「迭代」这个词。我们改称它为「遍历一棵树」或「树的遍历」（tree traversal）。为什么？没有什么**真正的**理由，只是大家都把在树上的迭代叫作「遍历」。也许是因为英语里人们喜欢头韵（tree traversal）。

那么有哪些遍历树的自然方式？结果是有好几种——不像列表基本上只有一种自然的遍历方式：

1. 层序遍历。广度优先搜索（BFS）。
2. 深度优先遍历——有三种：前序、中序和后序。（DFS）

我们在下面这棵树上试一试上面提到的这些遍历。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/Screen%20Shot%202023-02-26%20at%206.29.34%20AM.png" alt="">

*同一棵树上的不同遍历……*

#### 层序遍历

我们按层、从左到右遍历。第 0 层？D。第 1 层？B，然后是 F。第 2 层？A、C、E 和 G。

这样得到 `D B F A C E G`。

设想每一层是一本英文书里的一句话，我们一行一行地把它读出来。

**练习 17.2.1**：写出执行层序遍历的代码（警告：这比写其他几种遍历更难）。*提示*：你会需要记录当前在第几层。

#### 前序遍历

前序遍历的思路是这样的。从根开始。**访问根**（也就是执行你想做的**动作**）。这里的动作是「打印」。

所以我们打印根。D。好了。

现在往左走，递归。然后往右走，递归。

现在我们往左走了。我们在 B 节点。打印它。B。打印之后往左走。（记住，处理完 B 的左分支之后，我们会回来访问 B 的右边。）

一直按这个逻辑走下去，得到 `D B A C F E G`。

```java
preOrder(BSTNode x) {
    if (x == null) return;
    print(x.key)
    preOrder(x.left)
    preOrder(x.right)
}
```

#### 中序遍历

稍有不同，但大思路一样。这里我们不是先**访问**（即**打印**），而是先访问左分支。然后打印。然后访问右分支。

我们从 D 开始。不打印。往左走。

我们从 B 开始。不打印。往左走。

我们从 A 开始。不打印。往左走。什么也没找到。回到上面，打印 A。

然后去 A 的右边。什么也没找到。回到上面。现在我们在 B。记住，我们在访问左边之后、访问右边之前打印，所以现在打印 B，然后访问右边。

一直这样走下去，得到 `A B C D E F G`。

**另一种**思考方式如下：

首先，我们在 D。我们知道会先打印左边的项，然后是 D，然后是右边的项。

\[左边的项] D \[右边的项]

现在 \[左边的项] 等于什么？我们从 B 开始，打印左边，然后打印 B，然后打印 B 右边的东西。

\[左边的项] = \[B 左边的项] B \[B 右边的项] = A B C。

A B C D \[右边的东西] = A B C D E F G。

```java
inOrder(BSTNode x) {
    if (x == null) return;    
    inOrder(x.left)
    print(x.key)
    inOrder(x.right)
}
```

#### 后序遍历

同样，大思路一样，不过现在我们先打印左分支，然后是右分支，最后是自己。

用前面想出的方法，结果是这样的：

\[左边的项] \[右边的项] D

\[左边的项] 是什么？是 B 子树的输出。

如果我们在 B，会得到 \[B 左边的项] \[B 右边的项] B，即 A C B。

一直这样推下去，得到：`A C B E G F D`。

```java
postOrder(BSTNode x) {
    if (x == null) return;    
    postOrder(x.left)
    postOrder(x.right)
    print(x.key)   
}
```

## 19.3 图

树很棒，不是吗？但正如我们看到的，用节点和边可以画出一些不是树的东西。具体来说，「任意两个节点之间只能有一条路径」这个限制并不适用于所有情况。我们来看看去掉这个限制会怎样。

### 什么是图？

图（graph）由以下部分组成：

* 一组节点（或顶点）。
* 一组零条或多条边，每条边连接两个节点。

就这些！没有别的限制。

下面所有绿色的结构？每一个都是合法的图！第二个同时也是树，但其他的都不是。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/Screen%20Shot%202023-02-26%20at%202.02.16%20PM.png" alt="">

*图*

总的来说，注意**所有的树都是图，但不是所有的图都是树。**

### 只考虑简单图

图可以分成两类：*简单图*和*多重图*（或者说复杂图，这是我发明的说法，因为我喜欢这样理解它们）。幸运的是，这门课（以及几乎所有的应用和研究）只关注简单图。所以在这门课里我们说「图」时，你应该总是把它想成「简单图」（除非另有说明）。

好了，该说说那个显而易见的问题了。什么是简单图？

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/Screen%20Shot%202023-02-26%20at%202.03.21%20PM.png" alt="">

*简单图与多重图*

看红色的图。中间那个图在底部的两个节点之间有 2 条不同的边。换句话说，两个节点之间有多条边。这**不是**简单图，除非另有说明，我们不考虑它们。这样的图叫作多重图。

看第三个图。它有一个自环！一条从一个节点指向它自己的边！这也是不允许的。这样的图有时也被归为多重图，有时甚至连多重图也明确禁止自环。

### 更多分类

在下文和这门课里，除非另有说明，图都是简单图。不过还有更多的分类方式。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/Screen%20Shot%202023-02-26%20at%202.04.26%20PM.png" alt="">

有无向图（undirected graph），其中一条边 `(u, v)` 既可以表示这条边从节点 u 到 v，也可以表示从 v 到 u。有有向图（directed graph），其中边 `(u, v)` 表示这条边从 u 出发，到达 v（反之则不成立，除非边 `(v, u)` 也存在）。有向图中的边带箭头。

还有无环图（acyclic graph）。这是没有任何环的图。然后是有环图，即存在一种走法：从某个节点出发，沿着一些**互不相同**的边走，回到出发时的那个节点。

在上图中，可以清楚地看到有向边和无向边画法的区别。

看有环的那些图。如果从 `a` 出发，只走不同的边就能绕回到 `a`。因此这个图是有环的。

看左上角的图。是否存在某个节点 `n`，使得从 `n` 出发，沿一些不同的边走，能回到 `n`？没有！（记住对有向边，必须沿着方向走。可以从 `a` 走到 `b`，但不能从 `b` 走到 `a`。）

## 19.4 图的问题

关于一个图，我们可以问很多问题。

例如：

* **s-t 路径**：顶点 s 和 t 之间有路径吗？
* **连通性**：这个图是连通的吗，即所有顶点之间都有路径吗？
* **双连通性**：是否存在某个顶点，删掉它就会让图不连通？
* **最短 s-t 路径**：顶点 s 和 t 之间的最短路径是什么？
* **环检测**：这个图里有环吗？
* **欧拉回路**：是否存在一个恰好经过每条边一次的环？
* **哈密顿回路**：是否存在一个恰好经过每个顶点一次的环？
* **平面性**：能否在纸上把这个图画出来，让边互不交叉？
* **同构**：两个图是否同构（是换了装扮的同一个图）？

图的问题既酷又奇怪的一点是，很难*看出*哪些问题非常难、哪些问题其实没那么难。

例如，考虑欧拉回路和哈密顿回路问题。前者……是一个已经解决了的问题，早在 1873 年就解决了。解法的运行时间是 O(E)，其中 E 是图中的边数。

后者？如果你今天能高效地解决它，你会拿遍所有的数学奖，成为最著名的计算机科学家之一，赢得一百万美元，等等。还没有人能**高效地**解决它。已知最好的算法以指数时间运行。人们为此已经努力了几十年！

### 一步一步来！

好吧，在解决那个百万美元的问题之前，我们先解决列表上的第一个问题。给定源顶点 s 和目标顶点 t，s 和 t 之间有路径吗？

换句话说，写一个函数 `connected(s, t)`，接收两个顶点，返回它们之间是否存在路径。

开始时，假设我们有下面的代码：

```java
if (s == t):
    return true;

for child in neighbors(s):
    if isconnected(child, t):
        return true;

return false;
```

**练习 17.4.1**：继续之前，请读一读上面的代码，花点时间想一想。它能工作吗？它高效吗？在几个场景里过一遍。

好了，我们来试一试。

从 `connected(0, 7)` 开始？它递归地调用 `connected(1, 7)`，后者又递归地调用 `connected(0, 7)`。糟糕。出现了无限循环。

**练习 17.4.2**：怎样修正这个问题？再想一想。问题出在哪里？我们又访问了 `s`……但我们需要这样做吗？

好，我们来试试「记住访问过什么」的做法。

```java
mark s  // i.e., remember that you visited s already
if (s == t):
    return true;

for child in unmarked_neighbors(s): // if a neighbor is marked, ignore!
    if isconnected(child, t):
        return true;

return false;
```

结果是，这样确实可行！跟着 [这些幻灯片](https://docs.google.com/presentation/d/1OHRI7Q_f8hlwjRJc8NPBUc1cMu5KhINH1xGXWDfs_dA/edit#slide=id.g76e0dad85_2_380) 里的例子看看它是怎么工作的。

### 哇，我们刚才搞出了什么？

你可能还没意识到，但我们刚刚为图写出了一种**深度优先遍历**（就像前序、后序、中序那样）。我们做了什么？嗯，我们标记了自己。然后访问了第一个孩子。然后第一个孩子标记了自己，并访问它的孩子。然后第一个孩子的第一个孩子标记了自己，并访问它的孩子。

直观地说，我们在碰到第二个孩子之前，先往深处走（即沿着家族树往下走到第一个孩子、第一个孩子的第一个孩子也就是第一个孙子、第一个孙子的第一个孩子，依此类推……把这一整支血脉都访问一遍）。

接下来，我们会看到相反的思路：先访问所有的孩子，然后是所有的孙子，依此类推。
