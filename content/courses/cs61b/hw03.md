## 起始代码

这份作业使用讲座里介绍过的 `IntList`：

```
public class IntList {
    int first;
    IntList rest;

    public IntList(int first, IntList rest) {
        this.first = first;
        this.rest = rest;
    }

    /** Return the number of ints in this list. */
    public int size() {
        if (this.rest == null) {
            return 1;
        }
        return this.rest.size() + 1;
    }

    /** Returns the int at index i. */
    public int get(int i) {
        if (i == 0) {
            return this.first;
        }
        return rest.get(i - 1);
    }

    /** Returns the int at index i, using an iterative approach. */
    public int getIterative(int i) {
        IntList current = this;
        while (i > 0) {
            current = current.rest;
            i -= 1;
        }
        return current.first;
    }

    /** Return a new list with the same ints, but incremented by 1. */
    public IntList incrementRecursiveNonDestructive() {
        IntList incremented = new IntList(first + 1, null);
        if (rest != null) {
            incremented.rest = rest.incrementRecursiveNonDestructive();
        }
        return incremented;
    }

    public static void main() {
        IntList l1 = new IntList(5, new IntList(10, new IntList(15, null)));

        IntList l2 = new IntList(5, null);
        l2.rest = new IntList(10, null);
        l2.rest.rest = new IntList(15, null);

        IntList l3 = new IntList(15, null);
        l3 = new IntList(10, l3);
        l3 = new IntList(5, l3);
    }
}
```

> **译注**：原文起始代码里的 `main` 方法写作 `public static void main()`，缺少 `String[] args` 参数，此处照原文保留。这个写法不是 Java 标准的程序入口；想直接运行的话，要写成 `public static void main(String[] args)`。

（起始代码里各方法的注释依次是：「返回列表中整数的个数」「返回下标 i 处的整数」「用迭代方式返回下标 i 处的整数」「返回一个包含相同整数、但都加 1 的新列表」。）

## 任务 1：补全一个 IntList 方法

讲座里，我们写过一个实例方法 `incrRecursiveNonDestructive`，用递归（recursion）把列表里的每个值都加 1。这个方法是*非破坏性*（non-destructive）的。

提醒一下，「非破坏性」的意思是：如果我们运行

```
IntList L = new IntList(5, null);
L.rest = new IntList(7, null);
L.rest.rest = new IntList(9, null);

IntList M = incrRecursiveNondestructive(L, 3);
```

那么 `M` 应该是 `8 -> 10 -> 12 -> null`，而 `L` 保持 `5 -> 7 -> 9 -> null` 不变。

在这份作业里，你要写的是一个*破坏性*（destructive）的静态版本。这样安排只是为了让你多练一些 `IntList` 代码，它并不比非静态、非破坏性的版本更好或更差。

为此，请在提供的代码里补全 `incrRecursiveDestructive` 方法：

```
    /**
     * Returns an IntList identical to L, but with
     * each element incremented by x. Modifies the original list.
     * You are not allowed to use "new" in this method.
     */
    public static IntList incrRecursiveDestructive(IntList L, int x) {
        // TODO: Fill in this code
        return null;
    }
```

（注释的意思是：返回一个和 `L` 相同、但每个元素都加了 `x` 的 IntList；会修改原来的列表；这个方法里不允许使用 `new`。）

这个方法应该是**破坏性**的（也叫「mutating」或「in-place」），也就是它会修改原来的列表。也就是说，如果你运行下面的代码：

```
IntList L = new IntList(5, null);
L.rest = new IntList(7, null);
L.rest.rest = new IntList(9, null);

IntList M = incrRecursiveDestructive(L, 3);
```

那么 `L` 和 `M` 都应该是 `8 -> 10 -> 12 -> null`。

有时破坏性的实现比非破坏性的实现更好写，不过就这道题而言，两者难度差不多。

这份作业有一个隐藏测试（hidden test），用来检测你的方法是不是用递归实现的。

如果还想多练一练，我们在 `IntList` 类里还提供了几个可选的方法：`sum()`、`addLast(int x)` 和 `addFirst(int x)`。这些方法在源代码里有说明。

## 认识调试器

**为什么要用调试器？**

在以前的课程里，你可能用过*打印调试*（print debugging）：往程序里加打印语句，观察程序运行时某些变量的值。打印调试非常有用，但它有几个缺点：

- 它要求你修改代码，事后还要清理干净。
- 要决定到底打印什么、把打印语句完整写出来，很繁琐；打印出来的格式也不一定好看。

在作业的第二部分，我们向你介绍一种新技术：交互式调试（interactive debugging），也就是用交互式工具——*调试器*（debugger）——来调试。我们主要使用 IntelliJ 内置的调试器。

**断点**

启动 IntelliJ 调试器之前，你应该先设几个*断点*（breakpoint）。断点用来标记代码里可以暂停程序、查看所有变量值的位置。这样：

- 不需要修改代码、事后清理，因为正常运行时断点会被忽略。
- 不用写打印语句就能看到所有变量。
- IntelliJ 能把所有内容按结构化的方式展示。

设置断点的方法：点击行号右侧紧挨着的区域。

![code breakpoints](https://sp26.datastructur.es/assets/homeworks/hw03/1-code-breakpoints.webp)

**交互式调试**

设好断点之后，就可以开始一次调试会话了！点击你想调试的类或测试旁边的绿色三角形（测试文件里可能有两个绿色三角形）。注意不是点绿色三角形直接运行，而是点 ![debug](https://sp26.datastructur.es/assets/homeworks/hw03/debug.webp)（调试）选项：

![run debugger](https://sp26.datastructur.es/assets/homeworks/hw03/2-run-debugger.webp)

程序会一直运行，直到碰上第一个断点。界面底部原来显示控制台的地方会出现一个调试器窗口。

![debugger session](https://sp26.datastructur.es/assets/homeworks/hw03/3-debugging-session.webp)

在左边，你可以看到当前所有的方法调用；在右边，你可以看到程序运行到这一刻时已创建的变量的值（编辑器里也会以灰色文字显示）。对于类的实例，可以点击展开，查看它的字段。

在调试器里，你有这些选项：

- 从显示的值里寻找线索，找出问题所在，修好你的 bug！点 ![stop](https://sp26.datastructur.es/assets/homeworks/hw03/stop.webp) 结束调试会话。
- 点 ![resume](https://sp26.datastructur.es/assets/homeworks/hw03/resume.webp) 恢复程序运行（直到碰上下一个断点或程序结束）。
- 点 ![step over](https://sp26.datastructur.es/assets/homeworks/hw03/step-over.webp) 让程序前进一行代码。

  - ![step into](https://sp26.datastructur.es/assets/homeworks/hw03/step-into.webp) 的作用类似，但它会进入当前行调用的方法内部；而 ![step over](https://sp26.datastructur.es/assets/homeworks/hw03/step-over.webp) 会跳过该方法。
  - ![step out](https://sp26.datastructur.es/assets/homeworks/hw03/step-out.webp) 会把程序一直运行到当前方法返回之后。

- 如果不小心步进过头、想重新开始这次会话，点 ![rerun](https://sp26.datastructur.es/assets/homeworks/hw03/rerun.webp)（至少目前还没有直接往回退的办法）。

## 任务 3：条件断点

设想一个要循环 5000 次的程序。每次都一步步执行去找错误，效率不会太高。你更希望程序在某一次特定的迭代暂停，比如最后一次。

换句话说，你希望程序只在满足特定条件时暂停。做法是：在你关注的那一行创建断点，然后右键点击断点图标本身，打开「Edit breakpoint」（编辑断点）菜单。在那里填一个布尔条件，程序就只会在条件为真时才在这个断点暂停。它看起来像这样：

![Conditional Breakpoint](https://sp26.datastructur.es/assets/homeworks/hw03/5-conditional-breakpoint.webp)

用一个条件断点找出加进神秘 IntList 的第 500 个数，然后把这个数写进 `middleNumber` 方法里。

提示：加入这个数之前，列表应该恰好有 499 个元素；加入之后恰好有 500 个元素。调试器里有一个「Evaluate Expression」（求值表达式）工具，可以在输入框里输入一行代码并查看结果。例如，你可以输入 `L.iterativeSize()` 来查看当前 IntList 的长度！
