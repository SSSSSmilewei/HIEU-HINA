## 组队结构

对项目 5，我们要求两人一组（47B 学生可选），除非你有特殊情况无法组队。本学期其他作业一律不允许组队。

### 为什么项目 5 要组队？

团队协作的过程和单干很不一样。学习如何与他人高效合作是很好的锻炼，尤其是在涉及 Git 这类麻烦工具的大型复杂项目上。你也许完全可以单干，甚至单干更开心，但大学里能遇到的大型设计项目就那么几个，希望你抓住这个机会，培养这项重要的软技能。

这个项目本身非常开放，多一个人一起做，也有助于找到更有创意的解法，尤其是在世界生成这个问题上。

最后还有一点：去求职面试时，你很可能会被要求讲一段你在压力下和团队合作的故事。这个项目大概率能给你提供这样一个故事。

### 协作规则

在这个项目里，我们明确允许你们分工各自做一部分（divide and conquer）。我们鼓励你们尝试结对编程（pair programming），但不是硬性要求。也不要求你们在同一个房间里工作，不过我们强烈建议这样做，因为那样更有意思。

我们不要求两位搭档贡献完全均等，但两个人都应该至少做出实质性的工作量。

### 协作技巧与合并冲突

我们强烈建议搭档到 Soda 实验室或校园里的其他地方一起**结对编程**完成这份作业：共用一台笔记本电脑，轮流打字，两个人一起思考、一起勾勒解法。结对编程是防止**合并冲突（merge conflict）**发生的最简单的办法。

合并冲突是指：Git 仓库的两个不同用户对同一个文件都提交了修改，随后进行某种合并（例如执行 `git pull`）时产生的冲突。一旦发生合并冲突，你需要逐行决定保留你的修改、你搭档的修改，还是两者都保留（因为 Git 不知道该按什么顺序安排你们俩的修改）。这既烦人又费时间，而且完全可以避免！下面是几种协作方式：

1. 结对编程。就是上面说的那种！
2. 各做各的文件。把项目拆成不同的类 / 组件，分开写。

如果没法当面一起做，用 Zoom 屏幕共享也能达到类似效果！直接把工作对半分通常不是好主意，因为孤立地工作比协作差得多，不过你想这样做也行。IntelliJ（以及 VSCode，如果你用的话）也有支持多人编辑同一个文件的[插件](https://www.jetbrains.com/help/idea/code-with-me.html)（英文），但课程助教不会为它们提供官方支持。

### 解散搭档关系

有时搭档关系会因为种种原因确实处不下去。在极其极端的情况下，我们允许解散搭档关系。过去我们批准过下面这些解散理由：

1. 单方面的搭档关系：尽管多次尝试沟通，你的搭档始终没有为作业做任何事。
2. 各种让学生感到不适的私人原因。
3. 一方退课了。

要提交解散申请，请到 Beacon 的 Groups（小组）标签页并选择一个理由。你的理由不会透露给你的组员。助教审核你的申请后，你和搭档都会收到确认解散的邮件。在等待期间，你可以当作申请已被批准，继续做项目。

请牢记以下关于搭档的政策：

- 你应该已经至少尝试联系过搭档几次。
- 你不应是为了加入另一个小组而解散当前小组。
- 最后，申请解散应是万不得已的手段。

如果我们发现你的解散理由不合理，会按[学术不端](https://sp26.datastructur.es/policies/academic-misconduct)处理。

如果我们发现你根本没有尝试联系搭档并与他合作，你将拿不到组队这一项的分数。

小组解散后，你和原搭档都会失去原小组仓库的写权限。你仍然可以阅读和使用原来的代码，但你需要在一个新建的、属于你个人的小组仓库里继续工作。

项目 5B 截止之后，我们不再接受任何解散搭档关系的申请。

### 重新配对

如果你的小组已解散、你目前是单人小组，或者你是 47B 学生且原本没有配对，你可以申请和处于相同境况的同学重新配对。前提是：你已经解散了小组，现在在单人小组里。47B 学生只会和其他 47B 学生重新配对。

要提交重新配对申请，请到 Beacon 的 Groups（小组）标签页，在 Re-Pair（重新配对）区域下选择对应作业。助教审核你的申请后，你和新搭档都会收到确认被重新配进一个新小组的邮件。

请牢记：

- 会为你们两人新建一个小组仓库。
- 你需要在项目 5B 截止时间之前重新提交一份项目 5A 的设计文档。如果不交，你将拿不到项目 5A 的分数。
- 所有重新配对申请都会在项目 5A 截止时间前处理完，请务必在那之前提交申请。

如果我们发现你的重新配对理由不合理，会按[学术不端](https://sp26.datastructur.es/policies/academic-misconduct)处理。

项目 5A 截止之后，我们不再接受任何重新配对申请。
