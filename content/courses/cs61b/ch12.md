## 12.1 大 Θ

*别和大 O 搞混。*

### 把增长阶形式化

给定某个函数 $Q(N)$，可以用上一章最后两条简化规则得到 $Q(N)$ 的增长阶。

例如，如果 $Q(N)=3N^3+N^2$，增长阶是 $N^3$。

从现在起，我们用 $\Theta$（读作「大 Theta」）来表示增长阶。

### 增长阶的例子

下面这些函数的增长阶分别是：

| 函数 | 增长阶 |
| --- | --- |
| $N^3+3N^4$ | $N^4$ |
| $1/N + N^3$ | $N^3$ |
| $1/N + 5$ | $1$ |
| $Ne^N+N$ | $Ne^N$ |
| $40\sin(N)+4N^2$ | $N^2$ |

我们不说一个函数的*增长阶是*某某，而说这个函数*属于* $\Theta(\text{某某})$。换句话说，它属于具有同样增长阶的那个函数家族。

### 正式定义

对于某个增长阶为 $f(N)$ 的函数 $R(N)$，我们写

$R(N) \in \Theta(f(N))$，意思是存在某些正常数 $k_1$、$k_2$，使得……

对所有大于某个 $N_0$（一个非常大的 $N$）的 $N$ 值，都有 $k_1 \cdot f(N) \leq R(N) \leq k_2\cdot f(N)$。

## 12.2 大 O

*别和大 Θ 搞混。*

O（读作「大 O」）和 $\Theta$ 相似。它不是增长阶上的「相等」，而可以理解为「小于或等于」。

例如，下面这些说法都是对的：

* $N^3  + 3N^4 \in \Theta (N^4)$
* $N^3 + 3N^4 \in \text{O}(N^4)$
* $N^3 + 3N^4 \in \text{O}(N^6)$
* $N^3 + 3N^4 \in \text{O}(N^{N!})$

### 正式定义

$R(N) \in \text{O}(f(N))$ 的意思是存在正常数 $k_2$，使得：对所有大于某个 $N_0$（一个非常大的 $N$）的 $N$ 值，都有 $R(N) \leq k_2 \cdot f(N)$。

注意这是比 $\Theta$ 更宽松的条件，因为 O 不关心下界。

## 12.3 for 循环

*数一数，数一数，再数一数……*

我们已经看过一些运行时间分析了，现在来做几个更难的例子。目标是练习运行时间分析中涉及的规律和方法。这个想法可能不太容易掌握，所以练得越多越好。

### 扫描的例子

视频（英文）：<https://www.youtube.com/watch?v=SlBSvazddmk>

上次我们看到了函数 dup1，它检查列表中是否有任何一项第一次重复出现：

```java
int N = A.length;
for (int i = 0; i < N; i += 1)
   for (int j = i + 1; j < N; j += 1)
      if (A[i] == A[j])
         return true;
return false;
```

做运行时间分析有两种思路：

1. 数操作的次数
2. 几何可视化

### 方法一：数操作的次数

因为主要的重复操作是比较，我们来数必须执行的「**==**」操作的次数。

外层循环第一次时，内层循环运行 $N-1$ 次。第二次时，运行 $N-2$ 次。然后是 $N-3$、$N-4$……一直到 i = $N - 1$ 时内层循环恰好运行 $1$ 次。在最坏情况下，我们要走遍每一项，外层循环运行 $N$ 次。

设 $C$ = 发生的「==」操作的总次数。比较的次数是：

$$
C = 1 + 2 + 3 + ... + (N - 3) + (N - 2) + (N - 1) = N(N-1)/2
$$

其中 $N(N-1)/2$ 属于 $N^2$ 家族。

因为「==」是常数时间的操作，最坏情况下的总运行时间是 $\Theta(N^2)$。

### 方法二：几何可视化

也可以从几何的角度来看。

我们在 $i,j$ 组合的网格里画出什么时候用到 == 操作：

![](https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%28122%29.png)

可以看到，== 操作的次数等于一个直角边长为 $N - 1$ 的直角三角形的*面积*。因为面积属于 $N^2$ 家族，我们再次看到总运行时间是 $\Theta(N^2)$。

### 「打印派对」的例子

```java
public static void printParty(int N) {
   for (int i = 1; i <= N; i = i * 2) {
      for (int j = 0; j < i; j += 1) {
         System.out.println("hello");   
         int ZUG = 1 + 1;
      }
   }
}
```

外层循环每次把 `i` *乘以* 2 来前进。内层循环从 0 运行到 `i` 的当前值。循环里的两个操作都是常数时间的，所以我们这样来思考：**「对给定的 N，它会打印多少次 "hello"？」**

### 方法一：用图找出界

如果画出 0.5N（下面的虚线）、4N（上面的虚线）以及 $C(N)$ 本身（红色的阶梯线）的轨迹，会看到 C(N) 完全被夹在这两条虚线之间。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%2853%29.png" alt="">

因此，（按定义）运行时间也必定是线性的：$\Theta(N)$。

### 方法二：用数学找出界

用数学的力量解上面的等式，也能得到同样的结果：

$$
C(N) = 1 + 2 + 4 + ... + N = 2N - 1
$$

同样假设 N 是 2 的幂。

例如，如果 $N = 8$：

$$
C(N) = 1 + 2 + 4 + 8 = 15 = 2*8 - 1
$$

去掉较小的项和乘法常数，我们知道 $2N - 1$ 属于线性家族，所以运行时间是 $\Theta(N)$。

现在我们得到了下面画出的红色阶梯线的一个更精确的值，即 $2N$。

### 技巧：没有神奇的捷径

视频（英文）：<https://www.youtube.com/watch?themeRefresh=1&v=zWQwIHqlyuc>

如果有某种神奇的办法，看一眼算法就*知道*它的运行时间，那就太好了。如果所有嵌套 for 循环的运行时间都是 $N^2$，那就更好了。

遗憾的是，并非如此。我们之所以知道，是因为上面刚做了两个嵌套 for 循环的例子，它们的运行时间*不同*。

归根结底，运行时间分析**没有捷径**。它需要仔细思考。不过，有几个有用的技巧和要知道的东西：

* **求出精确的和**
* **写出例子**
* **画图**

上面每种技巧我们都用到了。

上面的例子里还用到了两个你会经常见到的重要的和：

* **前若干个自然数之和**：$1+2+3+...+Q=Q(Q+1)/2=\Theta(Q^2)$
* **前若干个 2 的幂之和**：$1+2+4+8+...+Q=2Q-1=\Theta(Q)$

上面你已经见过这两个和了，它们会在运行时间分析中一次又一次地出现。

## 12.5 小结

*结束我们的渐近分析之旅。*

### 要点

* 分析代码的运行时间没有神奇的捷径。
* 在我们的课上，精确计数或直观分析都可以。
* 要知道怎样求 1 + 2 + 3 + ... + N 和 1 + 2 + 4 + ... + N 的和。
* 这门课不写数学证明。
* 这门课里你要做的很多运行时间问题，都和今天这五个问题中的某一个相似。
* 这个主题是全课技能上限最高的主题之一。工具都在这里了，但**练习**是你的朋友！
* 同一个问题（例如排序）的不同解法，运行时间可能不同（差别大到足以让运行时间从不可行变成可行！）。
* $N^2$ 和 $N\log(N)$ 的差别是巨大的。
* 从 $N\log(N)$ 到 $N$ 是不错的进步，但不是根本性的改变。

希望这组例子让你很好地练习了运行时间分析的技巧和规律。下一节还有额外的练习题。记住，没有神奇的捷径，但你有处理这些问题的工具。去分析吧！

### 元认知问题

1. `modified_fib` 的运行时间是多少？假设 values 是一个大小为 n 的数组。int 数组里没有初始化的值会自动设为 0。

```java
public void modified_fib(int n, int[] values) {
   if (n <= 1) {
     values[n] = n;
     return n;
   } else {
     int val = values[n];
     if (val == 0) {
       val = modified_fib(n-1, values) + modified_fib(n-2, values);
       values[n] = val;
     }
     return val;
   }
}  
```

<details>

<summary>第 1 题</summary>

这是动态规划的一个例子，CS170 会更深入地讲这个主题。注意因为 `values` 在各次调用之间保存了下来，每个 `n` 值只会计算一次。计算单个 `n` 值只花常数时间，因为只是把两个已经算好的值相加或做一次数组访问。因此，总运行时间是线性的：$\Theta(n)$。

</details>
