## 15.1 二叉搜索树

链表很好用，但查找一项要花很长时间，即使列表是有序的也一样！如果那一项在列表末尾呢？那要花线性时间！

我们知道，对数组可以用二分查找更快地找到元素，具体地说，用 $\log n$ 的时间。二分查找的简短解释见 [这个链接](https://www.geeksforgeeks.org/binary-search/)。

在二分查找中，我们知道列表是有序的，所以可以利用这个信息缩小查找范围。首先看中间的元素。如果它比要找的元素大，就看它的左边。如果它比要找的元素小，就看它的右边。然后看相应那一半的中间元素，重复这个过程，直到找到要找的元素（或者因为列表里没有它而找不到）。

但怎样在链表上做二分查找？我们得一路走到中间才能检查那里的元素，光这一步就要花线性时间！

我们可以做的一个优化是保存一个指向中间节点的引用。这样，就能在常数时间内到达中间。然后，如果把节点的指针翻转，让我们可以往左右两半走，就能把运行时间减半！

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%2857%29.png" alt="">

*带中间指针的链表*

我们还可以进一步优化，像这样给每个递归的一半都加上指向其中间的指针。现在，如果把这个结构竖着拉开，你会看到一棵树！这种树叫作**二叉树**（binary tree），因为每个分叉处都分成 2 支。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%2811%29.png" alt="">

*带递归中间指针的链表就是一棵二叉树！*

## 15.2 二叉搜索树的定义

树由节点以及连接这些节点的边组成。

**约束**：任意两个节点之间只有一条路径。

在有些树里，我们选定一个**根**（root）节点，它是没有父节点的节点。

树还有**叶子**（leaves），即没有孩子的节点。

在下图中，绿色的结构是合法的树，粉色的结构不是（因为它有环）。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%2858%29.png" alt="">

*合法的树和不合法的树的例子*

联系我们前面得到的那种原始树结构，现在可以在已有约束之上加入新的约束。这就得到更具体的树的类型，其中两个例子是二叉树和二叉搜索树。

* **二叉树**：除了上面的要求，还满足二叉性质的约束，即每个节点有 0、1 或 2 个孩子。
* **二叉搜索树**（Binary Search Tree，BST）：除了上面所有的要求，还满足这样的性质：对树中的每个节点 X，
  * 左子树中的每个键都小于 X 的键。
  * 右子树中的每个键都大于 X 的键。**记住这个性质！！在这个模块和整个 61B 里我们会经常提到它。**

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%28139%29.png" alt="">

*一棵合法的 BST：左子树中的每个键都比父节点小，右子树中的每个键都比父节点大。*

下面是本章其余部分要用的 BST 模块：

```java
private class BST<Key> {
    private Key key;
    private BST left;
    private BST right;

    public BST(Key key, BST left, BST Right) {
        this.key = key;
        this.left = left;
        this.right = right;
    }

    public BST(Key key) {
        this.key = key;
    }
}
```

## 15.3 二叉搜索树的操作

### 查找

要查找某个东西，我们用二分查找，BST 的性质让这件事变得容易。

我们知道 BST 的结构是：一个节点右边的所有元素都更大，左边的所有元素都更小。知道了这一点，就可以从根节点开始，把它和要找的元素 X 比较。如果 X 比根大，就移到根的右孩子。如果更小，就移到根的左孩子。递归地重复这个过程，直到找到那一项，或者到达叶子（这时说明树里没有这一项）。

```java
static BST find(BST T, Key sk) {
   if (T == null)
      return null;
   if (sk.equals(T.key))
      return T;
   else if (sk ≺ T.key)
      return find(T.left, sk);
   else
      return find(T.right, sk);
}
```

如果树比较「茂密」，find 操作会以 $\log n$ 的时间运行，因为树的高度是 $\log n$。

（代码中的 `≺`、`≻` 表示「小于」「大于」，是伪代码写法；真正的 Java 代码要用 `compareTo`。）

### 插入

我们**总是**在叶子处插入！

首先，在树里查找这个节点。如果找到了，就什么也不做。如果没找到，这时我们已经在一个叶子节点处了。这时可以直接把新元素加到这个叶子的左边或右边，保持 BST 的性质。

视频（英文）：<https://www.youtube.com/watch?v=otDvoMb8UqE>

```java
static BST insert(BST T, Key ik) {
  if (T == null)
    return new BST(ik);
  if (ik ≺ T.key)
    T.left = insert(T.left, ik);
  else if (ik ≻ T.key)
    T.right = insert(T.right, ik);
  return T;
}
```

### 删除

从二叉树中删除要复杂一点，因为每次删除时，都要确保重新构造好树，并且仍然保持 BST 的性质。我们把这个问题分成三类：

* 要删除的节点没有孩子
* 有 1 个孩子
* 有 2 个孩子

#### 删除：没有孩子

如果节点没有孩子，它就是一个叶子，我们只需删掉父节点指向它的指针，这个节点最终会被 [垃圾回收器](https://stackoverflow.com/questions/3798424/what-is-the-garbage-collector-in-java) 清理掉。

#### 删除：一个孩子

如果节点只有一个孩子，我们知道这个孩子和这个节点的父节点之间保持着 BST 性质，因为这个性质对左右子树是递归成立的。所以，只需把父节点指向这个节点的指针改为指向这个节点的孩子，这个节点最终会被垃圾回收。

#### 删除：两个孩子

如果节点有两个孩子，过程就复杂一些了，因为我们不能直接让其中一个孩子成为新的根。那样可能破坏 BST 性质。

我们改为选一个新节点来替换被删除的节点。

我们知道新节点必须：

* 比左子树中的所有东西都大。
* 比右子树中的所有东西都小。

在下面的树里，我们标出了在要删除 `dog` 节点时，哪些节点满足这些要求。

<img src="https://raw.githubusercontent.com/Berkeley-CS61B/sp26-gitbook/main/.gitbook/assets/image%20%287%29.png" alt="">

*删除 <code>dog</code> 后可能的替换节点*

要找到这些节点，只需取左子树中最右边的节点，或右子树中最左边的节点。然后用 `cat` 或 `elf` 替换 `dog` 节点，再删掉原来的 `cat` 或 `elf` 节点。

这叫作**希巴德删除**（Hibbard deletion），它在删除中出色地保持了 BST 的性质。

## 15.4 用 BST 实现集合和映射

可以用 BST 实现 `Set`（集合）这个 ADT。如果用 BST，`contains` 的运行时间可以降到 $\log(n)$，因为 BST 性质让我们可以用二分查找！

也可以让每个 BST 节点存放 `(key,value)` 对而不是单个值，把二叉树变成一个映射（map）。我们会比较每个元素的键，来决定把它放在树中的什么位置。

## 15.5 BST 的性能

### 树的高度

BST 一个不幸的特点是，它可以从最好情况下的「茂密」树，一直变到最坏情况下的「细长」树。

在最好情况下，树的高度是 $\Theta(\log N)$，而在最坏情况下，树的高度是 $\Theta(N)$，这时它基本上变成了一个链表。例如，在一棵「细长」的 BST 上执行 `contains` 要花线性时间。

## 15.6 大 O 与最坏情况

*关于渐近分析的一段小插曲。*

考虑下面关于 BST 的说法。哪些是对的？

1. BST 的最坏情况高度是 $\Theta(N)$。
2. BST 的高度是 $O(N)$。
3. BST 的高度是 $O(N^2)$。

答案是三种说法都对。BST 的高度总是线性或更好，而线性高度显然「小于」最后一条里的二次上界。

不过，一个更棘手的问题是：三种说法中哪一种*信息量最大*？

答案是第一种。Θ 总是比大 O 信息量更大。

可以把 Θ 想成类似于 $=$。当我们说某个函数 $F(N) \in \Theta(N)$ 时，意思是它恰好按线性增长。

相比之下，应该把 $O$ 想成 $\leq$。如果说某个函数 $f(N) \in O(N)$，意思是它按线性或更慢的速度增长。

举一个具体的例子，假设我们知道 $f(N)$ 是这两个函数之一：$3N$、$4\log N + 6$。如果我告诉你 $f(N) \in O(N)$，你完全不知道说的是哪个函数。但如果我说 $f(N) \in \Theta(N)$，你马上就知道是哪一个。

打个比方，考虑下面关于酒店房间最坏情况价格的说法：

1. 最贵的房间是每晚 639 美元。
2. 最贵的房间每晚不超过 2000 美元。

这里我们看到，第一种说法给了我们确切的信息，第二种说法没有。按第二种说法，最贵的房间可能是 2000 美元、10 美元，或者介于两者之间的任何价格。

不过，*两种说法说的都是最坏情况*。用到渐近记号上，这意味着我们可以用 $\Theta$、$O$，甚至 $\Omega$ 来描述最坏情况。**大 O 和最坏情况不是一回事！**

### 使用大 O

如果 $\Theta$ 总比 $O$ 信息量大，为什么还要用大 O 记号？有几个原因：

* 我们可以做出更宽泛的陈述。例如，说「二分查找是 $O(\log N)$」是对的，但说「二叉搜索树是 $\Theta(\log N)$」就不对了，因为在某些情况下它可能是常数时间。
* 有时确定确切的运行时间是不可能的或极其困难的。在这种情况下，我们仍然希望给出一个一般的上界。

## 15.7 小结

抽象数据类型（ADT）是用操作来定义的，而不是用实现来定义的。几种有用的 ADT：

* 并查集、映射（Map）、集合（Set）、列表（List）。
* Java 提供了 Map、Set、List 接口，以及它们的几种实现。

我们已经看到了实现集合（或映射）的两种方式：

* ArraySet：最坏情况下操作是 Θ(N)。
* BST：如果树是平衡的，操作是 Θ(log N)。

BST 的实现：

* 查找和插入很直接（不过插入有一点点棘手）。
* 删除更有挑战性。典型的做法是「希巴德删除」。

### 元认知问题

1. 如果按随机顺序把数据插入 BST，很可能得到 $\log N$ 的高度，那为什么不在插入 BST 之前先把数据打乱？
2. 在 BST 中做希巴德删除时，我们总是选后继作为替换。后继保证只有零个或一个孩子——为什么？

<details>

<summary>第 1 题</summary>

在现实应用中，我们常常不是一次拿到全部数据。例如，设想你在收集基于时间的数据，每报告一个新值就插入 BST。当你每次只得到一个或几个数据点时，没有简单的办法把数据打乱。

<details>

<summary>第 2 题</summary>

按定义，后继是（被删节点右子树中的）最小值。为了反证，假设后继有两个孩子。那么它的左孩子比它更小，又在同一棵右子树中，所以它就不是最小值了。这与「后继是右子树中的最小值」矛盾。因此，后继保证最多只有一个孩子（如果有一个孩子，那是它的右孩子）。

（译注：原文这里把后继说成「子树中的最大值」、唯一的孩子是「左孩子」，那描述的是前驱；按题目说的「选后继作为替换」，应为右子树中的最小值，唯一可能的孩子是右孩子，译文已更正。）
